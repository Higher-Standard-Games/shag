// =============================================================================
//  Washoi -- texture browser seed list
// =============================================================================
//  Generated from the real pk3 chain under <EnginePath> (shag/public/data),
//  capped at 10 diffuse/base entries per directory. Norm / gloss / glow /
//  specular / emissive variants are filtered out, since the engine derives
//  those from the compiled shader rather than shipping them as separate
//  entries.
//
//  This list only registers shader NAMES. It carries no image data.
//  NetRadiant does NOT read textures out of the pk3 chain: its texture browser
//  walks the game directory (<enginepath>/<basegame>, i.e. public/data/basewashoi)
//  for files matching texturetypes in washoi.game. So the images must be
//  EXTRACTED from the pk3s to loose files under basewashoi/textures/ (and the
//  .shader definitions to basewashoi/scripts/) or the browser stays empty.
//
//  Names are listed WITHOUT the "textures/" prefix, matching every other
//  gamepack (basewsw lists "common | extra | world"). This matters for the
//  compiler, not just cosmetics: makebsp prepends "textures/" to the shader
//  name unconditionally when resolving the image, so a face written as
//  "textures/blx/blx_dark" is looked up as "textures/textures/blx/blx_dark",
//  the image goes missing, and the face is demoted to non-lightmapped -- the
//  map compiles and loads, but silently receives no lightmap. NetRadiant
//  copies these names verbatim into the .map brush faces, so keeping them
//  unprefixed here is what keeps the compiled map correct.
//
//  Engine-side naming rules (Q3ShaderRegistry.ts), for reference:
//    * "_" falls back to "/" (blx/wall_grey -> blx/wall/grey)
//    * matching is case-insensitive
//    * anything under "common/" is stripped from the compiled texture list
//      (BspLoader.getBspUsedTextures)
// =============================================================================
