# v1.0.0-alpha.3

**Release Date:** unreleased — living changelog

## Changes

- **Washoi owns its npm commands.** Run game commands through
  `npm --prefix src/games/fps run <command>`, or `npm run <command>` from the
  game directory. The launcher selects Washoi and preserves the assembled-root
  paths, arguments and exit status. Install dependencies once at the SHAG root.
  SHAG's package scripts no longer reference the game repository; manuals and
  game CI use the scoped commands.

- **SHAG checks work without the game source.** WebGPU types belong to the
  engine, applications declare their additional prebundled Babylon imports,
  and desktop metadata follows the selected application with a neutral engine
  default. Offline result recovery is available through `ranking:delivery`.
  Engine CI checks out SHAG alone; Washoi owns the assembled server/game gates.

- **Washoi owns its benchmark and MCP launch recipes.** Game fixture, profiling,
  outline, crowd and server benchmark drivers and their tests live with the
  game. Existing npm commands retain their names, arguments and assembled-root
  paths. Historical benchmark receipts remain unchanged.

- **Washoi owns its development probes and water fixture.** Historical research
  probes, the experimental-map verifier and both water-check scripts live with
  the game. Source links and invocations follow the new locations; existing
  stale probes and missing experiment data are documented. Application checks
  retain their prior scope.

- **Washoi owns its game-dependent regression tests.** Playback, reflection,
  FPS input, movement and lobby/match integration coverage live with the game.
  The ranking acceptance command includes the moved lobby tests; assertions
  and timeouts are preserved.

- **Washoi owns its game-specific CLI entry points.** The console runner,
  server checks, demo and benchmark tools, sound audit and SHAGGED application
  launchers live with the game. Existing supported commands keep their names
  and working-directory behavior. Removed the obsolete `debug:compare`,
  `debug:spawn` and unused pickup-gravity diagnostics; assertion-based parity,
  grounding and pickup-placement tests remain.

- **Washoi owns its bot development commands.** Map analysis, route learning,
  neural training and inference benchmarking start from the game repository.
  Existing npm commands, arguments and relative output paths are preserved.

- **Washoi owns its bot application.** Bot clients, brains, navigation, training,
  tests and the bot-server launcher live with the game. Editor analysis and
  tools follow the game-owned modules; control authentication, model/cache
  locations and production bundle names retain their existing behavior.

- **Washoi supplies lobby naming and demo-map policies.** Reusable lobby code
  no longer imports Washoi bot names or renamed-map aliases. Browser validation,
  durable account renaming and legacy demo levelshots retain Washoi's rules
  through explicit application inputs; account keys and storage stay unchanged.

- **Washoi owns lobby startup and the server build recipe.** Development and
  build commands follow the game-owned files while retaining data-directory
  selection, bundle names and atomic server-build publication.

- **Washoi owns its dedicated-server launcher and map-loading composition.**
  Development commands and tools follow the moved source files. Production
  bundle names, launch behavior and reusable SHAG server helpers stay the same.

- **Washoi supplies its dedicated-server entry paths.** The reusable lobby
  spawner no longer chooses a concrete game's source or bundled entry. Existing
  launch paths, runtime inheritance and server behavior are preserved. The
  runtime probe now supplies four players to meet FFA's minimum.

- **Editor reports use game-supplied map analysis.** Washoi supplies its existing
  player and bot reachability checks; SHAG's generic pipeline no longer imports
  the bot application. A missing provider reports analysis unavailable.

- **Washoi owns its browser startup.** Its HTML, lobby/player startup and adapter
  registrations live in the game repository. SHAG provides reusable browser
  renderer/scene helpers and a neutral example; select an application explicitly
  with `SHAG_APP` or an ignored local configuration file.

- **Balanced graphics use bloom off and 4× texture sharpness.** These are also
  the startup/reset defaults; full-resolution textures stay enabled. Zero bloom
  intensity now disables the bloom pass instead of running it at zero weight.
  Saved settings retain their chosen values.

- **Engine separation: Washoi supplies its compiler policy.** SHAGGED's Node
  entry points register Washoi's profile ID, local toolchain path and quality
  recipes. Compiler settings, arguments and reuse fingerprints stay identical;
  the engine handles discovery, profile installation and job execution.

- **Engine separation: Washoi supplies SHAGGED's gameplay entity catalog.**
  Browser and headless editor entry points register the same point and brush
  definitions, preserving palette order, keys and bounds. The engine retains
  its parser and compiler classes without importing Washoi's definitions.

- **Engine separation: Washoi owns shared bot policy.** The lobby, game server
  and bot service use the game's shared bot names and gametype weight profiles.
  Name reservation, profile selection and all behavior weights stay the same.

- **Match loading keeps combat audio quiet.** Sound effects, voices, announcers
  and ambient loops stay muted until the loading screen finishes fading.
  Music continues, saved sound settings stay intact, and delayed shots do not
  play in a burst afterward.
- **Your held weapon is prepared before entering a match.** Loading now warms
  the first-person weapon models, barrels and materials, then reuses that view
  at join. Previously only pickup models were preloaded, while the held weapon
  started a separate load after the loading screen had closed.

- **Engine separation: Washoi owns account-aware naming.** The `name` command
  lives with the game's console commands, preserving account renames, local
  profile names and response text. The FPS headless CLI keeps the same command.
  Engine command discovery no longer imports account services through it.

- **Engine separation: Washoi owns health, armor and powerup rules.** Client,
  server and bots share the game's grant math, Quad timing and mask definitions.
  The engine stores expiry ticks without importing game rules; grant values,
  damage effects and network bit assignments remain unchanged.

- **Engine separation: Washoi owns its shared pickup rules.** Pickup taxonomy,
  map data helpers, item landing and respawn rules now live in the game's
  shared folders, used by client, server and bots. Pickup IDs, positions,
  map fingerprints and timing remain unchanged across all five installed maps.

- **Engine separation: Washoi owns its shared definition catalog.** Weapon,
  projectile, ammo and item definitions now live in the game's shared folder,
  still used by both client and server with identical data and aliases. Engine
  weapon views receive compatibility-ID mapping from the game; generic types,
  defaults and the definition registry stay in SHAG.

- **Engine separation: Washoi owns pickup spawning.** The pickup entity manager
  and `spawn_pickable_entity` command move into the game. The map loader uses a
  registered game adapter at the same definition, spawn and disposal boundaries,
  preserving pickup IDs, placement, visual readiness and cleanup order.

- **Engine separation: Washoi owns its first-person controller.** The concrete
  FPS controller, player-visuals helper and `spectator`/`giveweapon` commands
  move into the game. Their controller ID, command behavior and player logic
  remain the same. Engine debug overlays use the generic position capability.
  Freefly retains ownership of its speed cvar across the module-load change.

- **Engine separation: freefly gets its input mapping from the game.** The
  engine camera no longer imports Washoi's FPS actions. Washoi supplies the
  same movement, jump, crouch and sprint actions, preserving player rebindings
  and input contexts. Game-free scene tools have engine-local freefly controls.

- **Engine separation: joining uses the registered game adapter.** The engine's
  `join` command no longer imports Washoi. Washoi supplies its existing join
  flow through the network adapter, preserving seat admission, team and loadout
  handling and the command's connection, success and failure responses.

- **Engine separation: scene tools use the registered network adapter.** The
  `scene empty` command no longer imports Washoi to check connection state.
  Its freefly controls remain disabled during an active network connection;
  without a registered game adapter, it enables local freefly controls.

- **The Private lobby key says it hosts bot matches.** Its hint read only
  "Invite only", so a player who wanted a match against bots had no reason to
  open it. It now reads "Invite only or bot matches".
- **The play screen drops the mode tags.** Under each mode's tagline sat a row
  of tags ("One on one", "Control pace", "Rail · Rocket · Blade") that repeated
  the tagline and the mode's subtitle. The tagline now leads straight to the
  Find match and Private lobby keys.
- **Chat is a size larger everywhere.** In a match and over the end-of-match
  board, chat lines were 14px and hard to read mid-fight; they are now 16px,
  with a wider, taller box so as many lines fit. The lobby chat goes from 16px
  to 18px and a room's chat from 14px to 16px, sender names and times with them.
- **Add bot works in any room.** Bots were for private rooms only, and players
  in a public room met a greyed-out key without understanding why. Add bot is
  now live everywhere: in a public room it makes the room private, everyone in
  it sees "Lobby changed to private" for two seconds, and the room's link
  becomes an invite link that still brings friends in. Bots still never take a
  seat someone in the queue could have, or play a public ranked match.
- **FFA starts from four players.** It could start with two, which made a
  free-for-all a duel without the duel's rules. A room now waits for four
  ready players; it still holds eight.
- **Quick play.** A pink key at the top of the menu, above Play, for a new
  player who just wants to try the game: it opens a private FFA room, adds four
  bots one by one, votes a random map and readies you up once the last bot is
  in, so the match loads with nothing else to press. If no bot arrives (no bot
  server), it stops and leaves you in the room, not ready.
- **The footer keys press in.** Devlog, Credits and the welcome guide's **?**
  now sink onto their base while held, like every other key in the lobby.
- **FFA opponents wear their own colours.** Every opponent in a free-for-all
  was the same cyan, so in a match against four bots there was no telling
  them apart. Each now takes a colour from the team palette for the match,
  never your own side's colour.
- **FFA players are on "ffa", not "spectator".** A free-for-all never gives
  anyone a side, so the server left every player at its default team,
  "spectator": FFA chat showed each line as **[SPEC]** in the spectator colour,
  and anything reading teams had to remember that "spectator" sometimes meant
  "playing FFA". Players in FFA now carry the team "ffa", and a shared
  same-side rule keeps two FFA players enemies: no spawn protection from each
  other, no teammate view when dead, no bot alliances. Older demos still say
  "spectator" and play as before.
- **Muzzle flashes stay on the barrel while strafing.** A flash was placed
  from the camera before the camera had moved for the frame, so while strafing
  and firing (most visibly the machine gun) it hung a frame's movement behind
  the gun, floating beside it. It is now placed just before the frame is drawn,
  for every weapon.
- **The Voltaic beam leaves the barrel again.** Like the muzzle flash, the
  beam's start was taken from the camera before the camera had moved for the
  frame, and now that the weapon view is prepared during loading this
  happened on every join: the beam trailed the gun while moving. It is now
  placed just before the frame is drawn.
- **`perf shaders [seconds]`** lists the shaders compiled during the
  interval, each with the defines it differs by from the nearest one already
  built, so a mid-match compile stall can be traced to its cause.
- **The blade no longer warns about a missing muzzle** every time it is drawn;
  it is a melee weapon and has none.
- **Less loaded for nothing, and no blade_blast texture warning.** The
  rocket, grenade, plasma and blade blast impacts are the procedural
  explosion, yet each also loaded an impact model that was never shown; they
  are gone. A projectile model whose surfaces carry their own textures (the
  blade blast's ring and glow) no longer looks for a fallback texture and
  warns "No texture found" when there is none.
- **Projectiles are ready before the match starts.** Rockets, grenades,
  plasma and the blade blast were sent from the first snapshot, while the map
  was still loading: before their definitions were registered and before
  their models could load (the loader had no scene yet, and the weapons
  package was not always fetched). Each failed shot tried again, and the
  models and their shaders were finally built mid-fight on each type's first
  shot. Map loading now loads every projectile model and compiles its
  materials beside the weapon views, definitions are registered once when the
  connection starts, and a projectile still loading warns once, not per shot.
- **Fewer frame spikes in fights.** Each explosion made a new fireball and
  shockwave material, and another player switching weapons cloned every
  material of the new weapon; both were new materials for the renderer to
  prepare mid-fight. Explosion layers now share one pool of materials, and
  other players' held weapons share their read-only materials on every WebGL
  browser (previously Firefox only). In a profiled 10-bot FFA timedemo the
  95th/99th percentile frame times fell (for example 41 → 38 ms and
  89 → 72 ms in one gunplay segment); the typical frame is unchanged, since it
  is bound by the CPU cost of drawing the map.
- **Switching to the blade no longer stalls the frame.** The map's frozen
  world materials are re-checked whenever the scene's lights change, and that
  counted lights no wall can receive: the weapon view's own lights (the blade
  light is switched on and off with the blade) and lights scoped to a single
  model. Each re-checked every world material; in a profiled 6-bot plasma FFA
  on washoi_dm5 that was a second of work in two minutes, in 60–120 ms
  spikes. Only lights that can reach the world count now.
- **Timedemo fixtures for any map.** `npm run benchmark:fixture` accepts a
  recipe for any installed map with 2–10 bots; `benchmarks/recipes/wdm5-ffa6.json`
  records a plasma-heavy washoi_dm5 free-for-all.
- **Plasma bolts are textured again, and explosions stop recompiling the
  spark shader.** Loading projectile models early meant a bolt fired while the
  map loaded built the plasma model before the texture loader was set up, so
  it was cached untextured and flew as a plain ball; the projectile loader now
  sets the texture loader up itself. Each explosion's sparks were a particle
  system made and disposed per explosion, and whenever none was alive the
  particle shader was released, so in a plasma fight nearly every explosion
  compiled it again (seven times in thirty seconds of play); finished spark
  systems are now kept and reused.
- **Plasma bolts glow again instead of drawing as grey shapes.** A bolt
  loaded before the map had read the shader scripts was built without its
  script, which draws it additively (black meaning clear), so it fell back to
  an opaque, lit texture and kept it for the session. The projectile loader
  now reads the scripts of the packages it has mounted before building a
  model.
- **The "world meshes were not ready" warning counts the right camera.**
  It said over a hundred map surfaces were not ready when the loading screen
  closed on washoi_dm5. Readiness is kept per camera, and the check ran with
  the engine still on the weapon view's camera, which never draws the map; for
  the camera that does, one surface was still compiling. The check now asks
  in the drawing camera's pass.
- **Fights stop re-decoding model textures.** Every model material copied
  during play (a player's style when they respawn, a drawn weapon, a dropped
  weapon, a barrel) copied its textures too, and a texture made from a model
  file's embedded image has no address to share its upload by, so each copy
  decoded and uploaded the image again. Copies now use the original textures.
  In the profiled 6-bot plasma FFA on washoi_dm5 the gunplay segments drew
  19–28% more frames.
- **Other players' Voltaic beams cost less.** Each shot traced the beam
  against every surface in the scene to find where it hit, and the server's
  exact contact, arriving in the same update, then replaced the answer. The
  trace now runs only when no contact came from the server.
- **Dropped weapons and spinning barrels reuse their materials.** Each drop
  and each barrel copied every material of its model, a new material for the
  renderer to prepare mid-fight. They now share the original's (on WebGL; on
  WebGPU they keep copies, as other players' held weapons do).
- **No "Effect 'walkbob' already registered" warnings on join.** The
  first-person camera now removes its view effects when it is switched away,
  so joining (or rejoining after spectating) registers them once.
- **The unused instagun is gone.** No map, mode or loadout handed it out, but
  its weapon, ammo crate, HUD slot, sounds and splash code were still
  registered and loaded with the game. Weapon slots now run 1–8.
- **No more "No PK3 found for entity model: …ammobox.md3" warning.** Health,
  armour, ammo and quad pickups are procedural, but their definitions still
  named MD3 models, which map loading looked up and the `r_pickupProcedural 0`
  setting fell back to; the game ships none of them. The model paths and the
  setting are removed.
- **Shots no longer stall the frame finding their impact.** Each machinegun
  tracer, riotgun pellet, electrobolt and Voltaic frame tested the shot against
  every triangle of the rendered map, about 2 ms per ray on washoi_dm5, so a
  riotgun blast could cost 35–70 ms. Impacts now come from the map's collision
  brushes, as the server's do, at about 0.015 ms per ray. Shots now visibly stop
  on weapon clip, where the server already stopped them, and leave no mark on
  surfaces marked `nomarks`; shots into the sky leave no impact.
- **Explosions cost a fraction of what they did.** Every rocket, grenade,
  plasma, blade blast and bomb explosion built up to fifteen meshes of its own,
  rewrote its fireball's vertices on the CPU every frame and ran a CPU particle
  system for its sparks. All live explosions now draw as instances of four
  shared meshes, animated on the GPU, with the same look. Plasma impacts draw 4
  to 6 rays instead of 8 to 12. In a stress test of about 60 impacts a second,
  the median frame fell from 20.1 to 11.1 ms.
