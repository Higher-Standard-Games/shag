# v1.0.0-alpha.10

**Release Date:** unreleased — living changelog

## Changes

### Firefox frame drops in fights

Firefox players saw the frame rate collapse during fights, worst when they were
hit. Profiling Firefox 159 on a recorded duel found two causes.

- **The damage flash** redrew a full-screen 2D canvas, gradients and up to 60
  triangles per hit, on every frame while it faded. It is now a red vignette
  and a glow on the screen edge facing the damage, painted once and faded by
  the browser's compositor, so a hit costs almost no frame time. In a Firefox window,
  frames over 33 ms in the 400 ms after a hit fell from 18 to 6, against 5 with
  no flash at all. The flash no longer draws triangles.
- **Shaders compiled again mid-match.** Firefox lacks
  `KHR_parallel_shader_compile`, so each shader program it links stops the
  frame for 150–300 ms. Switching weapons disposed the view model's materials
  and their shaders with them, and switching back compiled them again. Compiled
  shaders now stay cached for the session (`Effect.PersistentMode`), so
  anything rebuilt with the same shaders finds them ready. On the same demo the
  long frames fell from ten to four. The remaining four are a weapon's first
  appearance and the blade's own light switching on and off around a death.
