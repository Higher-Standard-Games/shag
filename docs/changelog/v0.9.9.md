# v0.9.9

**Release Date:** TBD

## Summary

Blade weapon with charged projectile, per-weapon speed modifiers, ragdoll death system, team colors, movement safety fixes (ledge grab ceiling check, walljump fresh press), BSP shader precompilation, hitbox tuning, gib system fixes, cartoon hit effects, weapon pickup/drop reliability improvements, tab-recovery handler, HUD improvements, code quality refactors (WeaponViewManager split, camera controller deduplication), and optimization/dead code cleanup (~3,900 lines removed).

## Changes

### Weapon Pickup Reliability [FIXED]

- **Sticky USE flag** — `FPSMovementSubsystem` now OR-accumulates the USE button across all input queue entries, preventing brief F-presses from being overwritten by a later queue entry without USE set
- **Dropped weapon BSP collision** — replaced fragile custom ballistic simulation (gravity + flat `floorY` check) with Q3-style `stepSlideMove()` for dropped weapons. Weapons now properly collide with walls, floors, and ceilings instead of falling through ledges or flying through walls
- **Collision bounds fix** — `SharedCollisionWorld.stepSlideMove()` was ignoring the `_bounds` AABB parameter, using hardcoded player-sized dimensions (radius=16, height=64) for all objects. Weapons now use their actual 8×8 collision hull via `isSmallObject` gate
- **Duplicate physics body** — removed copy-paste `createDynamicBody()` double-call in `Pickup.ts` that created two Havok bodies per pickup

### Remote Player Crouch Wireframe [FIXED]

- **Wireframe never showed crouched height** — `RemotePlayerRenderer.pushSnapshot()` was reading `isCrouching` from the `velocity` component (which doesn't have it → always `false`). Now correctly reads from `movementState` component where the server serializes it

### Tab Recovery [NEW]

- **Central `onTabReturn()` handler** — `visibilitychange` event triggers coordinated reset when returning from a background tab:
  - **DeltaTime clamp** — caps dt to 16ms for 3 frames, preventing catch-up stutter from massive accumulated deltaTime
  - **Projectile clear** — `ProjectileManager.clear()` nukes stale trails/lights/meshes; server re-sends any alive projectiles
  - **Buffer flush** — `SnapshotBuffer.flush()` discards stale interpolation data, keeps latest snapshot as baseline
  - **Force teleport** — `V2NetworkClient.forceTeleport()` snaps local player to server position
  - **Material revalidation** — `revalidateMaterials()` unfreezes materials, resets texture cache, forces GPU re-upload, recompiles shaders, and re-freezes
- **WebGL context loss detection** — `webglcontextlost` / `webglcontextrestored` canvas event handlers auto-trigger material revalidation on GPU recovery

### Blade Weapon [NEW]

- **Charged energy projectile** — hold fire for 1s to charge, releases `blade_blast` projectile (50 damage, 90 splash radius, 2500 speed)
- **First-person slash animation** — 3-phase melee swing (windup → swing → return) with multiple slash presets cycled per fire
- **Slash trail effect** — red emissive ribbon trail follows blade tip during melee swing, supports multiple concurrent trails with independent fade-out
- **Third-person slash animation** — remote players play `blade_slash` at 2x speed for snappy visual feedback
- **Blade explosion** — 50% scale of rocket explosion with red-themed colors (white-hot core, deep red flames)
- Slash trail suppressed during charged projectile release (only appears on melee swings)

### Per-Weapon Speed Modifiers [NEW]

- **Weapon-specific movement speed bonuses** applied via `speedBonus` field on `WeaponDef`
- **Blade**: +10 speed (410 run) — agile melee
- **Riotgun**: +5 speed (405 run) — light shotgun
- **RL / Electrobolt**: -25 speed (375 run) — heavy weapons
- **All others** (MG, PG, LG, GL, Gunblade, Instagun): 0 (400 run base)
- Server applies speed bonus via `FPSMovementSubsystem.setSpeedBonus()` per entity
- **Client-side prediction sync** — `V2NetworkClient.setSpeedBonus()` mirrors server bonus for correct UPS counter and jitter-free movement

### Keybinds [NEW]

- **Mouse3 (middle click)** added as default bind for crouch/crouchslide (in addition to C and Ctrl)

### Movement Tuning [CHANGED]

- **Sprint speed** increased from 350 → **400** for faster, more cartoonish feel
- **Walljump** retuned: height **280**, bounce **1.2** (more forward push, less upward), boost **1.5**
- **Crouchslide** speed multiplier increased from 1.2 → **1.4** for speed boost while sliding
- **Autosprint fix** — client now correctly transmits inverted sprint bit when `cl_autorun` is enabled

### Walljump — Fresh Press Required [FIXED]

- **No more accidental walljumps during bunny hop** — grounded jump now consumes walljump's `keyReleased` flag, preventing held-space from triggering walljumps when flying past walls
- Player must release and re-press space to walljump (same as Warsow behavior)
- **Prediction parity** — `keyReleased` is preserved during reconciliation reset (not forced to true or false), giving the best approximation of server state and eliminating prediction snaps

### Ledge Grab — Ceiling & Hull Check [FIXED]

- **Upward ceiling trace** — traces from player position to target pull-up height to verify the vertical path is clear; prevents climbing out of map
- **Full player hull traces** — all destination checks (solid, ceiling, standing room) now use the full player bounding box (32×64 AABB) instead of point traces, preventing getting stuck in corners where center is clear but hull clips geometry

### MD3 Normal Map Alignment [FIXED]

- **Weapon normal maps now correctly aligned** — MD3 UVs are V-flipped (`1.0 - v`) during parsing to convert from Quake's bottom-left origin. The normal map texture was authored for the original UV space, so now:
  - Bump texture V sampling is flipped (`vScale = -1, vOffset = 1`)
  - Tangent space axes inverted (`invertNormalMapX/Y`) to correct bump direction
- Eliminates the visible "wrong bumps" on all first-person weapon models

### Shader Precompilation [FIXED]

- **Wall flicker on first projectile fire eliminated** — `EffectPreloader` Phase 2 now force-compiles ALL scene materials (not just BSP) with the PointLight shader variant during map load
- **Render frame settling** — Phase 2 waits a full render frame with the PointLight active before disposing, ensuring the GPU processes compiled shaders. Phase 3 waits another frame for "without light" variant to settle, preventing dirty-flag cascade flicker
- Covers pickup models, weapon models, and all other scene geometry in addition to BSP surfaces

### Background Tab Texture Recovery [FIXED]

- **Prevents "wallhack" exploit** — when the browser tab is backgrounded during map loading, WebGL texture uploads and shader compilations silently fail, leaving walls invisible
- `MapLoader` now tracks tab visibility via `visibilitychange` during `loadBspMap()`
- If tab was backgrounded, triggers full `revalidateMaterials()` on return: marks all materials dirty, force-recompiles shaders with PointLight variant, and waits for GPU readiness
- If tab is still hidden when loading completes, waits for visibility before revalidating

### Optimization & Dead Code Cleanup [NEW]

- **Removed `BspCollision.ts`** (1,151 lines) — legacy trace-based collision, superseded by `SweepCollisionBackend`; migrated `BspCommand` and `headless-bsp.ts` to `CollisionManager`
- **Removed unused v2 server protocol** (~1,200 lines) — `ClientManager`, `InputProtocol`, `SnapshotProtocol`, `BinaryEncoder`, `MessageTypes`; game traffic exclusively uses v1 `MessageCodec`
- **Removed `NetworkManager`** (~550 lines) — unused singleton, `NetworkServices`, `NetworkCommand`; game uses `FPSGameManager` → `NetworkGameHost` directly
- **Removed 4 CLI test tools** — `server-protocol`, `server-integration`, `server-bench`, `server-replay`; cleaned npm scripts
- **BinaryEncoder optimization** — added `reset()` for buffer reuse, fixed `getData()` to return copy (was view), module-level encoder reuse eliminates 16KB alloc per encode call
- **11 roundtrip tests** — snapshot (with/without delta baseline), commands, welcome, ping/pong, ack, encoder reset safety
- **Binary command encoding** — replaced `JSON.stringify` in `encodeCommand`/`decodeCommand` with structured binary layout (direction 3×f32, pitch/yaw f32, buttons u16, tick u32, weaponSlot u8) — ~27 bytes vs ~100+ JSON per tick at 60+ Hz
- **Binary event encoding** — replaced `JSON.stringify` in `encodeEvents`/`decodeEvents` with type-specific binary for all 11 event types (`combat_state`, `weapon_fire`, `damage`, `death`, etc.) — 1-byte type code + fixed fields per event
- **Closure hoisting** — moved 8 inline `serialize`/`deserialize`/`clone` closures from `decodeEntities`/`decodePlayers` to 5 shared module-scope functions (`_noopSerialize`, `_noopDeserialize`, `_shallowClone`, `_transformClone`, `_velocityClone`) — eliminates ~600+ function allocations/sec
- **GameServer split** — extracted 3 modules from `GameServer.ts` (1,310→814 lines): `SnapshotBuilder.ts` (state conversion + hoisted encode closures), `SnapshotBroadcaster.ts` (snapshot history, PVS filtering, delta encode+send), `Client.ts` (shared `ClientInfo`/`GameServerConfig` types)
- **FPSGameManager split** — extracted `GameEvents.ts` (611 lines) from `FPSGameManager.ts` (1,885→1,324 lines): all 12 server event types, weapon state sync, remote weapon fire effects, projectile lifecycle, death/gib/ragdoll logic
- **FPSGameManager → Game** — renamed class and file across ~25 files; cleaner naming without "FPS" prefix or "Manager" suffix
- **`WeaponViewManager.loadWeapon` split** — broke 447-line monolithic method into 6 focused methods: `loadGlbWeapon()`, `loadMd3Weapon()`, `loadMd3Textures()`, `loadMuzzleFlashModel()`, `setupWeapon()`, with `loadWeapon()` as orchestrator
- **Camera controller deduplication** — created `CameraInputHandler` utility (composition pattern) extracting shared pointer lock, mouse look, key prevention, and context menu blocking from `FPSController` and `FreeflyController` (~200 lines removed)

### Crosshair–Projectile Alignment [FIXED]

## Technical Notes

- Weapon speed: `WeaponDef.speedBonus` → `MovementProfile.wishspeed`. Server: `WeaponSystem → FPSMovementSubsystem.setSpeedBonus()`. Client: `V2NetworkClient.setSpeedBonus()` on `weapon_state` sync.
- BSP shader fix: `forceCompilation(mesh, callback)` needs actual mesh for vertex attributes. Temporary PointLight range=999999 forces "has lights" variant.
- Team colors: PBRMaterial `albedoColor` × albedoTexture. HDR >1.0 for vivid looks.
- Scene reference: use `CameraSystem.getInstance().getCamera()?.getScene()` not `EngineStore.LastCreatedScene`.
- **Wire format changed** — commands and events now use structured binary instead of JSON. Both encoder and decoder updated together. Roundtrip tests verify data integrity.
- V2 protocol was planned replacement with better encoding but never wired into game paths. Can be re-implemented when needed.
