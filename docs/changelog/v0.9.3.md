# v0.9.3 - Server-Rendered Projectiles & Network Optimization

**Release Date:** 2026-02-19

## Summary

Server-authoritative projectile rendering with Q3-style SnapshotBuffer interpolation. Per-client delta-compressed snapshots (50-70% bandwidth reduction), 60Hz snapshot rate, tuned interpolation delay, ClockSync, anti-warp input rate limiting, knockback system, and HUD data layer.

## Changes

### Server-Rendered Projectiles

- **Server-authoritative projectiles** — Projectile entities (rockets, grenades, plasma) are now created and simulated entirely on the server, included in network snapshots as `proj_` entities with position and velocity components
- **SnapshotBuffer interpolation** — Projectile positions smoothly interpolated between two server snapshots (Q3/Warsow-style lerp), eliminating all jitter and desync; dedicated `SnapshotBuffer` instance for projectile entities
- **Projectile spawn events** — `projectile_spawn` event type carries `entityId` and `defId` so client knows which weapon model/trail to render
- **Visual effects preserved** — Grenade rotation (velocity-based quaternion orientation) and blue trail effects run locally on interpolated positions
- **Client prediction removed** — No more client-side raycasting or movement for projectiles; server handles all collision and hit detection
- **Player model filter** — `RemotePlayerRenderer.pushSnapshot()` skips `proj_` entities to prevent player models appearing on projectiles

### Snapshot Rate & Interpolation Tuning

- **60Hz snapshot rate** — Default snapshot rate bumped from 30Hz to 60Hz (every 2 ticks at 125Hz tick rate), matching Warsow's competitive timing
- **Interpolation delay tuning** — Default interp delay reduced from 100ms to 50ms; jitter multiplier tightened from 2× to 1× stddev; clamp range narrowed to 16-150ms
- **`--snapshotrate` CLI flag** — Server snapshot rate configurable via command line
- **`cl_interp` / `cl_timenudge` CVars** — Player-side interpolation customization (cl_interp=0 for auto-adjust, cl_timenudge for render time offset)

### Weapon Tuning

- **Projectile speed increase** — Rocket launcher: 1150 → 1800 UPS (+56%), Grenade launcher: 1000 → 1560 UPS (+56%)
- **Gravity tuning** — `FALLING_GRAVITY_MULTIPLIER` reduced from 1.8 to 1.25 for less harsh descents while maintaining jump height

### Delta Compression

- **Per-client snapshot baselines** — Server maintains a 64-entry snapshot history ring buffer; each client's last acknowledged tick selects their baseline for delta encoding
- **Ack-driven baselines** — Ack message updates `ClientInfo.lastAckedTick`; server looks up corresponding `GameState` from history to produce minimal diffs
- **Bandwidth savings** — Delta-compressed snapshots are 50-70% smaller than full snapshots when entities are mostly stationary

### ClockSync

- **NTP-like clock synchronization** — `ClockSync` module calculates server-client time offset using Ping/Pong round-trips with burst sampling, outlier rejection, and periodic resync every 30s
- **Server timestamp interpolation** — `SnapshotBuffer` uses server-authoritative timestamps (converted to local time via ClockSync) for accurate interpolation

### Network Diagnostics

- **Packet loss % in NetGraph** — Tick gap detection over a rolling window of 100 snapshots to estimate loss percentage
- **NetGraph metrics expanded** — Displays 7 metrics: ping, snapshot rate, packet loss %, interp delay, command rate, reconciliation rate, clock offset

### Anti-Cheat

- **MovementValidator** — Server-side anti-warp preventing speed hacking via input flooding (rate cap + time budget layers)
- **Silent drops** — Rejected inputs silently dropped; strike counter tracks violations

### Knockback System

- **Server-side impulse queue** — Knockback applied as velocity impulses before movement simulation; splash damage with distance-based falloff
- **Client-side KB prediction** — Immediate client-side knockback response via SnapshotBuffer interpolation
- **Splash damage** — Radius-based splash damage with configurable `splashRadius`, `splashDamage`, and `knockbackScale` per weapon

### HUD Data Layer

- **`combat_state` event** — Health/armor sent privately to owning player per tick
- **Enriched events** — `damage` and `death` events include `attackerId` and `weaponId` for kill feed
- **HUDState aggregator** — Client-side singleton collecting combat, damage, death, and scoreboard data
- **Debug overlay** — Auto-enabled on connect showing HP, armor, scoreboard, kill feed
- **Real player names** — Captured from join message, displayed in scoreboard
- **Deaths/ping tracking** — Per-player death counter and real ping in PlayerState

### Bug Fixes

- **Double explosion fix** — `isLocalPrediction` flag on client-spawned projectiles; only server events create explosions
- **Diagnostic log cleanup** — Removed flood-causing `[KB-DIAG]`, `[KB-RENDER]`, `[EXPLOSION]` console.log statements
