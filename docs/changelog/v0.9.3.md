# v0.9.3 - Network Diagnostics & Optimization

**Release Date:** 2026-02-18

## Summary

Networking optimizations and server security: per-client delta-compressed snapshots (50-70% bandwidth reduction), packet loss detection in NetGraph, NTP-like ClockSync for server-authoritative interpolation, anti-warp input rate limiting, and a Network Worker feasibility study.

## Changes

### Delta Compression

- **Per-client snapshot baselines** — Server maintains a 64-entry snapshot history ring buffer; each client's last acknowledged tick (`lastAckedTick`) selects their baseline for delta encoding
- **Ack-driven baselines** — Ack message now updates `ClientInfo.lastAckedTick`; server looks up the corresponding `GameState` from history to produce minimal diffs
- **Client baseline clone** — Client stores `lastAckedSnapshot` as a clone of the received snapshot (not predicted `localState`) to ensure decode baseline matches server's encode baseline
- **Bandwidth savings** — Delta-compressed snapshots are 50-70% smaller than full snapshots when entities are mostly stationary

### ClockSync

- **NTP-like clock synchronization** — `ClockSync` module calculates server-client time offset using Ping/Pong round-trips with burst sampling (5 pings on connect), outlier rejection, and periodic resync every 30s
- **Server timestamp interpolation** — `SnapshotBuffer` uses server-authoritative timestamps (converted to local time via ClockSync) instead of local `performance.now()` reception times
- **Ping/Pong protocol** — `Ping` (0x09) and `Pong` (0x0A) message types with `float64` timestamps; server auto-replies
- **Graceful fallback** — If ClockSync hasn't synced yet, interpolation falls back to local reception timestamps

### Network Diagnostics

- **Packet loss % in NetGraph** — Tick gap detection: compares expected vs actual snapshot tick intervals over a rolling window of 100 snapshots to estimate loss percentage
- **NetGraph metrics expanded** — Now displays 7 metrics: ping, snapshot rate, packet loss %, interp delay, command rate, reconciliation rate, clock offset

### Anti-Cheat

- **MovementValidator** — Server-side anti-warp preventing speed hacking via input flooding, using two layers:
  - **Rate cap** — Hard limit of `ceil(clientRate/serverRate) + 2` inputs per server tick
  - **Time budget** — Each input costs `1000/clientRate` ms of real-time credit; budget caps at 200ms to prevent idle-banking
- **Silent drops** — Rejected inputs are silently dropped (no error sent to client); strike counter tracks violations for gametype-level kick decisions
- **Integration** — Validation gate in `GameServer.handleInput()` after dedup, before inputQueue push

### Performance

- **Snapshot encode profiling** — `broadcastSnapshot()` logs per-client encoding cost every 100 ticks (`[Perf]` prefix) to assess Network Worker viability

### Documentation

- **NETWORK_PROTOCOL_FLOW.md updates** — Delta compression baselines, expanded Ack section, Anti-Warp section, NetGraph diagnostics section, bandwidth cheat sheet with delta sizes
- **NETWORK_WORKER_FEASIBILITY.md** — New research doc analyzing worker thread viability (architecture options, state transfer challenges, risk assessment, recommendation to profile first)
