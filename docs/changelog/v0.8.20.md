# v0.8.20 - Map Loading Overlay

**Release Date:** 2026-01-19

## Summary

Adds an in-game loading overlay for map transitions, with a shared animation system and EventBus-based decoupled architecture. Games can fully customize or replace the loading UI.

## Changes

### New Features

- **MapLoadingOverlay**: In-game loading screen for map transitions
  - Shows during `map` command execution
  - Displays animated smoke background (reused from startup screen)
  - Console-style loading messages
  - Engine logo and branding
  - Automatic fade-out when loading completes
  - Minimum display time prevents flash on fast loads

- **LoadingAnimation**: Reusable smoke puff animation component
  - Extracted from startup LoadingScreen for code reuse
  - Configurable colors, puff count, sizes, timing
  - Multiple built-in palettes: SHAG, FIRE, ICE, MONO

- **Weapon Animation System**:
  - **Plasmagun Revamp**: New "Tilt & Pump" reload animation with side inspection and mechanical slide action.
  - **Dynamic Reloads**: Animation duration now respects `weapon.reloadTime` (1.0s).
  - **Stabilization**: Dampened view bobbing during reload to prevent jitter.
  - **Screen-Space Pump**: Improved "Down & Up" pump animation.
  - **Recoil Alignment**: Fixed recoil direction to kick backward (Z-axis) correctly.
  - **Recoil Rotation**: Fixed recoil rotation axis (mapped to Z) for rotated weapon models to prevent sideways rolling.
  - **Recoil Intensity**: Tuned recoil pitch intensity to 20% for more realistic feedback.

- **Physics & Spawning**:
  - **Q3-Style Player Physics**: Complete rewrite of player collision system using proper Quake 3 coordinate conventions.
    - Asymmetric bounding box: -24 (feet) to +32 (head) from origin, total height 56 units
    - Position tracked at "origin" level (24 units above feet) matching Q3's `pm->ps->origin`
    - Clean `stepSlideMove` implementation without hacky offsets
    - Proper viewheight system (26 units from origin = 50 from feet)
    - New `PlayerPhysicsConstants.ts` centralizes all Q3 physics values
    - **Fixes stair stepping bug** where camera got stuck low when walking into stairs
  - **Havok Integration**: Full WASM-based physics implementation for map and pickups.
  - **Spectator Spawn**: Force spectator mode on map load to prevent getting stuck.
  - **Asset Preloading**: Preload items during map load for instant spawning.

- **LoadingEvents**: EventBus-based loading event system
  - `loading:start`, `loading:progress`, `loading:complete` events
  - Fully decoupled - MapLoader emits events, UI listens
  - Games can disable default overlay and use their own
  - Extensible type system: `'map' | 'assets' | 'save' | 'network' | 'generic'`

### Improvements

- **LoadingScreen refactored**: Now uses shared LoadingAnimation component
- **MapLoader**: Emits loading events for progress tracking
- **Customization**: Games can configure colors, logo, branding via `MapLoadingOverlay.configure()`
- **Ledge Grab**: Added slope detection to prevent unwanted ledge grabs on 45° ramps (requires vertical wall).

### Technical Details

New files:
- `src/engine/physics/PlayerPhysicsConstants.ts` - Q3-style player physics constants
- `src/engine/ui/LoadingAnimation.ts` - Shared animation component
- `src/engine/ui/LoadingPalettes.ts` - Color palette definitions
- `src/engine/ui/MapLoadingOverlay.ts` - In-game loading overlay
- `src/engine/core/LoadingEvents.ts` - Event type definitions
- `docs/research/MAP_LOADING_OVERLAY_DESIGN.md` - Design documentation

### Usage

```typescript
// Enabled by default in main.ts after startup

// Games can customize:
MapLoadingOverlay.configure({
  animationColors: FIRE_PALETTE,
  logoUrl: 'games/mygame/logo.png',
  showBranding: false,
});

// Or disable and use custom UI:
MapLoadingOverlay.disable();
EventBus.on('loading:start', (e) => { /* custom handling */ });
```
