# v0.9.18

**Release Date:** 2026-07-12

## Summary

Focus areas this cycle:

1. **In-game chat** - Warsow/Q3-style messagemode is now on main: press **T** to talk, keep pointer lock and mouse look, suppress game binds while typing, Enter sends, Esc cancels. Messages are server-authoritative, sanitized, rate-limited, broadcast as `chat` snapshot events, and captured into demos at their original ticks.
2. **Networking manual refresh** - the engine networking guide now documents fixed-rate authoritative physics, input sanitization, current client message codes, and chat snapshot events.
3. **FPS manual refresh** - the FPS manual now includes in-game chat, demo chat playback, updated player/HUD/movement/pickup/weapon notes, and server command guidance.
4. **Smarter bots** - bots now route through teleporters and jumppads, fire their selected weapon (including charged blade shots), use crouchslide movement, ADS only while attacking, and aim from the weapon fire origin.
5. **HUD and spectator polish** - the FPS HUD gained spread/ADS crosshair feedback, reload/out-of-ammo prompts, pickup notifications with cartoon toasts, print-slab spectator UI, and keycap-styled actionable prompts.
6. **Death and corpse camera pass** - ragdoll/gib deaths now support a smoothed corpse-follow death camera with world clamps, plus cleanup for sticky death-time viewmodel and beam artifacts.
7. **Renderer stability** - dynamic light material caps now guard WebGL uniform-buffer limits, and remote player models are protected against body culling / hidden-body floating-weapon regressions.

The following landed on branch `feature/hud-prompt-polish` *(merged to main)*:

8. **Items and pickups** - medium (25) and small (+5 overheal "bubble") health now spawn, and every Warsow per-weapon ammo box (`ammo_riotgun`, `ammo_lasergun`, …) spawns and grants — previously only plasma ammo did. Ammo boxes now show a per-type simpleitem icon, and the weapon swap prompt was polished (spacing, padding, size). *(Small health was later corrected to cap at 100 — no overheal — so it stays visible at full HP.)*
9. **On-gun ammo counter** - weapons authored with the `tag_ammo` bone + an `ammoCounter` cfg render live ammo digits on the gun (procedural LCD, drawn on the weapon camera layer), live-tunable via `cg_ammocounter_*` cvars.
10. **Player model visuals** - team tint colors, fullbright, and outline colors are cvar-backed with a settings UI.
11. **Fixes** - negative scores no longer underflow to `4294967295` (signed encoding); loose textures resolve from the pk3 search root; the lobby labels teams Soba/Udon to match the in-game teams.

The following is on branch `feature/post-game-screen` (not yet merged):

12. **Post-game screen** - the match end is now an event: input freeze with free-look, authoritative winner banner + enlarged gold scoreboard locked open, 3D winner-model showcase with weapon, duel overtime (no draws — +1 minute until someone leads), endgame music with proper restore.
13. **Single-match servers** - lobby matches now run one match per server process: the post-game is terminal (mouse + chat + RETURN TO LOBBY at ~6s, bots leave at +10s, 120s grace), players regroup in the same lobby (map vote = the rematch), and the emptied server exits — automatic per-match cleanup during alpha. Classic warmup loop stays available (`continuous`).

## Changes

### In-Game Chat [ADDED]

Plan and decisions: `docs/research/ingame-chat.md`.

- **Protocol wire:** added `MessageType.Chat (0x89)` for reliable client-to-server chat text. The server identifies the sender from the connection, then rebroadcasts sanitized messages as self-contained `chat` snapshot events with `senderId`, `senderName`, `team`, and `text`.
- **Server authority:** chat text is sanitized at ingest (control characters to spaces, whitespace collapse, 128-character cap) and rate-limited (600ms minimum interval plus 5 messages per 5-second burst window). Over-limit messages are dropped without simulation impact.
- **Talk mode:** **T** opens chat only during gameplay with pointer lock active and menus/settings closed. `InputSystem` now ignores game binds while a text field has focus, while keyup still clears held keys to prevent sticky movement.
- **HUD history:** one 100-message store backs both closed and talk-mode views. Closed chat shows the last 5 messages with an 8-second fade; talk mode expands into a scrollable Washoi print-slab history panel with team-colored sender stamps and `[SPEC]` spectator labeling.
- **XSS safety:** the chat renderer uses `textContent`; the binary codec remains transparent and does not HTML-escape payloads.
- **Demo playback:** chat events are recorded automatically through the shared snapshot path and replay in `DemoService` through a read-only chat widget.

### Bot Intelligence [ADDED] [CHANGED]

Bots in `src/bot/*` learned the v0.9.17 movement and combat features:

- **Trigger routing** — `BotNavGraph` + `BotVision` now path bots *through* teleporters and jumppads instead of treating them as walls, so bots use the same map shortcuts players do.
- **Weapon usage** — `BotWeaponProfile` + `StateMachineBrain` fire the bot's actually-selected weapon (not a hardcoded default) and hold/release **charged blade shots**.
- **Movement + ADS** — bots use **crouchslide** to close distance and only **ADS while attacking** (Warsow-LG-style — precise on target, mobile otherwise).
- **Aim origin fix** — bots now aim from the weapon **fire origin** (eye/muzzle), matching where their shots actually come from, so their aim lines up with their fire.
- Coverage added in `StateMachineBrain.test.ts` and `BotNavGraph.test.ts`.

### Server [FIXED]

- **Player separation vs. world** — the Q3-style "push overlapping players apart" pass is now clamped against world collision, so shoving two players apart can't nudge one into or through a wall (`fix(server): clamp player separation against world collision`).

### HUD, Spectator, and Pickups [ADDED] [CHANGED]

- **Dynamic crosshair:** crosshair spread now reflects movement, ADS, and weapon state, with clearer reload/out-of-ammo warnings.
- **Action prompts:** swap/reload/respawn text now uses keycap styling on actionable labels, including the restyled weapon swap prompt.
- **Pickup notifications:** server-side pickup events now drive HUD pickup toasts for any item, with badge, burst/tumble, and fight-plate styling.
- **Spectator UI:** the spectator overlay and chase controls were restyled into the Washoi print-slab look, with fixes for chase target cycling and roster display.

### Death Camera and Death FX [ADDED] [FIXED]

- **Corpse-follow camera:** local deaths can now bind the camera to the live ragdoll hips or gib burst centroid instead of falling back to a detached fixed death view.
- **World clamp safeguard:** the death camera clamps against extreme corpse/gib positions so ragdolls falling through geometry do not drag the view behind the map.
- **Death presentation:** added the "YOU GOT FRAGGED" blood-plate slam dialog and tightened death/respawn prompts.
- **Death cleanup:** fixed sticky blade viewmodel visibility after fragging and LG beam remnants after death/respawn.
- **Remote model lifecycle:** removed eager remote player model preloading from the deathcam path, kept local corpse models on-demand, and hid/restored third-person weapon roots with their owning body to prevent floating guns.

### Renderer and Dynamic Lights [FIXED]

- **Dynamic light safety:** added a shared dynamic-light cap helper and applied it to weapon, projectile, explosion, pickup, BSP, model, and preloader material paths to avoid unsafe WebGL2 shader variants.
- **PBR material guard:** PBR/clearcoat materials are capped more conservatively so dynamic lights do not exceed `GL_MAX_VERTEX_UNIFORM_BUFFERS` on constrained GPUs.
- **Remote player body visibility:** cloned player models now force body and child meshes enabled/visible and keep skinned meshes active to avoid stale bounds culling while the bone-attached weapon remains visible.

### Documentation [CHANGED]

- Added `docs/changelog/v0.9.18.md` and linked it from the changelog index.
- Refreshed `docs/manual/guides/networking.md` with the current fixed-rate physics/input sanitizer model and chat protocol entry.
- Updated `docs/research/ingame-chat.md` from plan to implementation/progress log.
- Advanced the FPS manual submodule to the chat/manual refresh commit, including `docs/manual/multiplayer/chat.md`.

### Items and Pickups [ADDED] [FIXED] — *feature/hud-prompt-polish*

- **Health items:** added `item_health_medium` (+25) and the bare Q3 `item_health` alias, and corrected `item_health_small` to the Warsow +5 overheal bubble (was +25). `item_health_medium` (147 across shipped maps) previously never spawned.
- **Ammo boxes:** every shipped map uses per-weapon classnames (`ammo_riotgun`, `ammo_lasergun`, `ammo_electrobolt`, …) but only `ammo_plasmagun` was mapped, so only plasma ammo spawned. Made the Warsow per-weapon names the primary classname on each ammo def (Quake-style names kept as `classnameAliases`) and added them to the shared PickupTable.
- **Alias handlers:** `EntityManager` now registers a spawn handler for each `classnameAlias` (map dispatch is exact-classname), and the pickup-id match keys off the entity's raw BSP classname — so aliased map classnames actually spawn with the correct authoritative id.
- **Swap prompt:** fixed the missing space before the item name (`inline-flex` → `inline-block` so the flex line-box no longer trims trailing whitespace), with more padding and a larger font.
- **Ammo-box icon:** overlays the Warsow `ammobox_icon.md3` quad on the generic box and skins it with the ammo type's simpleitem icon (`gfx/hud/icons/ammo/*`); skips silently (plain box) when the icon isn't available.

### On-Gun Ammo Counter [ADDED] — *feature/hud-prompt-polish*

- Weapons whose model carries a `tag_ammo` anchor and whose `.cfg` declares `ammoCounter` render live ammo digits on the gun. Digits are generated procedurally into a `DynamicTexture` (LCDdigits font isn't shipped) on a quad mounted at the anchor, on the weapon camera's render layer/group so it draws in the view-model overlay.
- Handles mirrored model imports (negative world scale) and exposes `cg_ammocounter_scale/_yaw/_pitch/_roll/_fwd` for live positioning. Currently authored on the plasmagun/rlauncher/glauncher tag sets; other weapons light up once their models gain the anchor + cfg.

### Player Model Visuals [ADDED] [CHANGED] — *feature/hud-prompt-polish*

- `PlayerModelManager` gained a `PlayerModelVisualStyle` (tint color, fullbright enable/intensity, outline color); tint multiplies the texture while fullbright adds a small emissive lift so armor/fabric detail stays visible. Team palette moved to HDR-capable values.
- `PlayerModelVisualSettings` maps team slots (alpha/beta/ffa) to tint + outline colors backed by cvars (`cl_team_*_color`, `cl_team_*_outline_color`); `RemotePlayerRenderer` re-applies when the slot or cvars change; settings UI exposes the controls.

### Networking [FIXED] — *feature/hud-prompt-polish*

- Player `score` was encoded as `uint32` (in both `PlayerState` and the delta player block), so a negative score after a selfkill read back as `4294967295`. Added `writeInt32`/`readInt32` and switched both score sites to signed; wire bytes are unchanged for a given value, so it stays build-compatible and determinism-neutral.
- `PK3TextureLoader`'s loose-file fallback now probes the pk3 search roots (e.g. `data/`) in addition to the `game()` root, so loose model/HUD assets that aren't packed into a loaded pk3 resolve.

### Lobby [CHANGED] — *feature/hud-prompt-polish*

- The match lobby labels its team columns **TEAM SOBA** (alpha/cyan) and **TEAM UDON** (bravo/pink) to match the esc menu and scoreboard. Internal team keys stay `alpha`/`bravo`.

### Post-Game Screen and Match End [ADDED] [FIXED] — *feature/post-game-screen*

Design and codepath map: `docs/research/post_game_screen.md`.

- **The match end is now an event:** server-side input freeze on PostGame (movement/actions zeroed, free-look kept — mirrored client-side so prediction agrees), an authoritative winner in the match snapshot (team or top player, computed on both the time-limit and score-limit paths), a "X WINS!" slam that hands off to an enlarged gold-titled scoreboard locked open for the phase, and a 3D **winner showcase** — the winning player's model with their weapon, team tint/outline resolved per viewer, standing left of the right-shifted board under a directional veil.
- **Duel overtime:** a tie at the time limit never ends a duel — the match extends +60s (stacking) with an "OVERTIME!" slam until someone leads (`overtimeOnDraw`/`overtimeDuration` config; DM/TDM can still draw).
- **Aim lock without pause-menu popups:** `CameraInputHandler.setLookFrozen` ignores mouse-look while keeping pointer lock held.
- **Endgame music** now restores the game playlist when the next phase begins (previously looped forever).
- **Fixes along the way:** post-game board no longer strobes (data-signature-gated refresh) and no longer shows pre-final-frag scores; the gameplay HUD (death screen, timer, prompts) fully hides during the post-game; bots auto-ready on join and re-ready on rollover (lobby-invited bots were never registered); `SHAG_TIMELIMIT` env override reads bare numbers as **minutes** (g_timelimit semantics) with `s`/`m` suffixes; match pacing env overrides (`SHAG_TIMELIMIT`/`SHAG_SCORELIMIT`/`SHAG_WARMUP`) for testing.

### Single-Match Servers + Lobby Return [ADDED] — *feature/post-game-screen*

Design and work orders: `docs/research/single_game_server_lobby.md`.

- **Per-match servers are now the default for lobby matches** (`GameServerConfig.singleMatch`, CLI `--single-match`, spawner defaults it on): the post-game is **terminal** — no warmup loop. At ~6s the screen "opens up" (pointer lock released, chat input opens, **RETURN TO LOBBY** button); bots are released at +10s; any stragglers are closed out after a 120s grace so the process always exits (`shutdownOnEmpty` reaps it). Fresh server per match = automatic cleanup, no drift/leak accumulation during alpha.
- **The lobby is the rematch screen:** on game-server exit the lobby resets to waiting (now also clearing `isStarting`, `serverUrl`, and map votes), same lobby URL, ready-up + map vote for the next match on a new server.
- The classic long-running warmup loop remains available as `continuous` (dev CLI default).
