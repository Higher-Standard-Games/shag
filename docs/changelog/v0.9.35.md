# v0.9.35

**Release Date:** unreleased — living changelog

## Changes

- Fixed the standalone player-crowd benchmark requesting its player package
  relative to the benchmark page instead of `/data/`, which caused ZIP parsing
  failures. Firefox performance and Linux held-button reports are documented
  under `docs/research/`; the gameplay performance issue remains open.

### Netcode: low frame rates and stalled links no longer warp the player

- The server no longer throws away commands from clients running below about
  30 FPS. Its anti-warp rate cap accepted 4 new commands per server tick, but a
  client sends one burst per rendered frame: at 25 FPS a fifth of a player's
  movement was silently dropped, and every dropped command was a correction on
  the player's screen. The cap is now a flood guard of 64 per tick; the
  one-command-per-tick simulation still keeps a fast sender from gaining time.
- A stalled link (a lost TCP segment, Wi-Fi) used to replay on top of the
  player's own prediction: the server repeated the last command for the whole
  stall without advancing the ACK, then trimmed the late backlog, so the
  player was pushed forward and then back. Past the first two starved ticks,
  each server guess now stands in for the client's next command and advances
  the ACK, and that command is dropped when it arrives late. The player sees
  only where a guess differed from what they did.
- The input buffer holds 12 commands instead of 6, and a queue that stays deep
  for a whole second gives one command up, so a stall leaves no lasting latency.
- The client keeps up to 250 ms of frame time when generating commands (was
  100 ms), so an ordinary shader-compile or GC hitch no longer loses commands
  the server then has to guess.

### Input

- Under pointer lock, mouse motion that changes no button (`button` -1) is no
  longer read for button state. A platform reporting an empty button mask on
  locked motion ended firing and aiming at the first flick. That fits the
  Linux report of ADS and Voltaic fire ending as soon as the mouse moves; it
  has not yet been confirmed on a Linux machine.
