# v0.9.24

**Release Date:** unreleased — living changelog

## Summary

v0.9.24 is a bugfix and documentation cycle. The manual is read against the
code one engine part at a time: what the docs claim is confirmed, corrected or
deleted, and whatever the reading turns up in the code is fixed as it is found.
Progress, part by part, is tracked in `docs/research/v0.9.24-QA.md`.

*(living changelog — unreleased)*

## Changes

### Renderer lifecycle fixes and WebGPU audit

Optional screen-space reflections now refresh their environment cubemap after
map loads and scene-environment changes, instead of retaining a missing or old
sky. Disposed cubemaps are detached, and scene shutdown or setup failure releases
the pipeline. The lighting guide now documents the existing shared shadow-map
restriction: enabling the scene shadow toggle does not create a sun shadow map.

WebGPU now enables the shared clustered lighting path on capable devices and
uses the same Standard/PBR light budgets as WebGL2. Weapon materials can receive
both ambient and muzzle-flash lighting again. Paired isolated two-container GPU
tests passed, including frozen/skinned fixtures; gameplay lighting acceptance
remains in progress. Renderer QA adds a two-container pixel test and local
Copy/Download JSON controls.

A third QA case, `rendererqacase=environment`, checks reflections from a cube
environment: each face must show its own colour on Standard and metal PBR, and
a rough surface must sample the dimmer mips. On an RTX 4070 SUPER it passes
with identical pixels on WebGL2 and WebGPU.

A first gameplay pass on both backends, with bots, SSR and a reconnect, found
and fixed several faults:

- WebGPU lost a frame at every map load, because a shader-warmup light was
  destroyed while a draw still used it.
- Screen-space reflections did not start on WebGPU: an engine extension was
  missing, then a Babylon WGSL shader bug, now patched.
- The sky lights were rebuilt on every map load, which cost WebGPU a frame.
- Reconnecting stacked a second spectator overlay, kept updating projectile
  trails and damage numbers the map unload had disposed, and left a spectator
  with an invisible gun.

WebGL2 and WebGPU now play the sequence clean.

The first-person weapon's fill light reached the whole world. From the
moment you joined it brightened the map by about 38%. Spectators never saw
that, and on WebGPU it dropped frames. It now lights only the gun. The same
fill belongs to the map's own lights, so the world looks as it did in play
for players and spectators alike.

KTX2 sidecars now keep their base dimensions and consistent row orientation
through raw and compressed uploads. This fixes the upload defects implicated
in enlarged distant floor patterns and inverted lamp halos on WebGPU; final
in-game visual confirmation is pending. Device restoration retains the sidecar
loader. The worker's ZSTD decoder now fetches its bundled local WASM asset.

Brightness- and alpha-only shader waves now preserve texture UV transforms,
including compressed-texture orientation. Filter decals now use the texture's
UV matrix on both backends, including after frozen-material texture changes.
These are headless-verified compatibility fixes; the newly reported WebGPU
floor-layer and flipped-halo artifacts still need same-view GPU confirmation.

Glow overlays now respect separate base/glow texture transforms while keeping
BSP lightmap UVs intact. `shader surface` captures aimed layers, depth/alpha
settings and texture source/orientation, making backend comparisons reproducible
without changing rendering settings.

Added a source and headless audit with reproducible lifecycle probes and an
ordered WebGPU recovery plan in
[`v0.9.24-renderer-webgpu-QA.md`](../research/v0.9.24-renderer-webgpu-QA.md).
It identifies disconnected Q3 NodeMaterial wiring, incomplete backend recovery,
a stale compressed-KTX1 upload API, and postprocess/resource ownership defects.
The first repair batch binds post-processing to the world camera during scene
service initialization and camera changes, restores independent settings
defaults, and keeps bloom, grading, vignette, chromatic aberration and SSAO off
while their master switch is disabled. Disposal now removes clock/camera
subscriptions. Cel outlines own and release their depth target without altering
other effects' depth renderers; privately owned water depth textures are also
released. Client map unload now waits for resource cleanup to finish.

WebGPU initialization failure now falls back on a fresh canvas, and partial
cleanup cannot hide the original error. A failed WebGL fallback is attempted
only once. Both scene bootstrap paths apply the same backend-specific light
caps. Backend reporting now distinguishes WebGL1 from WebGL2.

Added opt-in `?rendererqa=1&renderer=webgpu` (or `webgl2`) diagnostics: isolated
Standard/PBR fixtures, bounded compilation/render waits, GPU validation scopes,
and a JSON report with backend, capabilities, frame count and first failure.
Compressed KTX1 textures now use Babylon's loader and negotiated format
capabilities on WebGL/WebGPU, preserving source bytes for recovery and applying
the compressed-texture orientation through the public Texture wrapper. Failed
uploads release their internal texture before software/image fallback. Complete
authored mip chains are retained; partial compressed chains use a safe base-level
filter. Legacy raw files with incomplete trailing mips keep their usable base
image. Real-device GPU acceptance remains open.

The first full-game WebGPU console capture exposed two further failures. Cel
outlines now sample depth before applying their per-pixel sky mask, avoiding
invalid derivative-dependent sampling in divergent shader control flow. Lit
WebGPU materials wait for a matching shader after light-layout changes instead
of drawing an older shader with missing light buffers; cap changes also
invalidate frozen material readiness. These repairs still need a fresh GPU
game run to confirm the white-world failure is resolved.

Water's WebGPU path now samples its single-level scene captures explicitly at
mip zero, avoiding derivative-uniformity failures in per-pixel branches. WebGPU
startup also registers Babylon's dynamic-texture extension, which weapon ammo
displays require. Intermittent white frames and an oversized GPU shader layout
remain under investigation.

WebGPU gameplay now automatically captures a bounded JSON error report with
oversized shader layouts, named uniform buffers and matching scene owners.
This makes white-frame failures diagnosable from the console without manually
inspecting Babylon's internal effect cache.
Reports distinguish compile-time light counts from current material settings
and emit each new error separately to keep console captures manageable. The
latest user capture identifies oversized BSP material layouts; their creation
and the remaining white-frame flicker are still under investigation. Full
WebGL/WebGPU feature and visual parity remains the target.

Effect shader warmup now explicitly compiles its off-screen fixtures on both
backends. Previously a rendered frame was counted as success even when those
fixtures were culled. Shader failures now reject warmup/revalidation instead of
being mistaken for successful compilation, and temporary fixtures/lights are
released on failure.

Applying render settings now preserves material freeze state. Previously it
froze even materials deliberately left mutable for dynamic lighting, allowing
old light layouts to persist when the light set changed. Isolated renderer QA
now includes eleven-light/frozen-material cases and an explicit refresh control
for WebGL/WebGPU comparison. The gameplay white-frame failure remains open.

Fixed a reproduced cause of oversized WebGPU world shaders: completing a glTF
model import raised light caps on every scene material, including existing BSP
surfaces, to the scene's light count. The renderer now restores its WebGPU light
budgets at import readiness. This prevents later weapon/player imports from
undoing map setup; repaired gameplay rendering still needs GPU confirmation.

User testing confirms WebGPU gameplay now boots. A follow-up lift audit fixes
inline brush faces sharing the wrong lightmap when one wall texture appears on
multiple pages. Lift/door lightmaps also use the world's established baked-light
conversion. The reported missing lift still needs visual confirmation after
these fixes.

### Bots in Deathmatch fight again

Since July, bots in a free-for-all never attacked anyone — not each other, not
people. The server has no team to name in a free-for-all and sends "spectator" for
every player, which its own rules read as "no team"; the bots read it as a team they
all shared, and counted every other player as an ally. They now read it the way the
server means it.

### Bots and training run on Node 24

Anything that loaded TensorFlow — a trained bot, `bot:train`, self-play — failed
on Node 23 or newer with `util.isNullOrUndefined is not a function`: the native
backend calls a helper Node has since removed. It is put back before the backend
loads.

### Demos record what a person did, and bots can learn from it

A recording used to hold only what the server simulated, so training a bot on
one meant guessing which buttons produced the motion — and the guess is
backwards exactly where it matters, since an air-strafe points the wish
direction and the velocity different ways on purpose. Demos now carry the
command the server applied for every player, every frame, taken on the path
where commands are accepted so nothing a validator threw out is recorded as
something a person did.

Training reads those commands instead of inferring them, and learns from people:
a seat with an account verified by a lobby ticket is a person, and bots are left
out unless you ask for them with `--include-bots`. The labels are what the
player did rather than how well the frame went — the old scheme built every
target from a reward, which on a neutral frame, meaning most of them, said 0.5
whatever the person had done. A directory of recordings is now read as one
corpus, matches already trained on are skipped, and whole matches are held back
to score the result, because frames seconds apart in the same match are nearly
the same frame and splitting between them measures memory instead of play. Every
output the network is asked for is now something a person presses: the three it
used to carry for "which mode am I in" could not be labelled from a recording at
all, two of them were never read, and which mode to be in was always the state
machine's decision anyway. The network sees the last three frames rather than one,
so a movement in progress is visible to it, and its inputs are built by one piece
of code for training and for play, with the map loaded on both sides — there were
three copies, and they had drifted far enough that a bot in a match would have been
fed item distances and a combat target that training had never shown it. What
a set of weights was trained on is written beside it, and weights that expect a
feature vector this build no longer produces are refused rather than quietly
read as noise.

Bots can finally use any of it: a bot added from a room inherits the server's
model directory, where before it always ran the plain state machine however much
had been trained. The first run on a real recording then showed that none of it
had ever worked end to end: the extractor looked each player up by an id the
snapshots do not use and found nobody, so demo training had never extracted a
single frame from a real match; a finished run never exited; and a bot pointed at
trained weights looked in a subdirectory, found nothing, and never looked anywhere
else. All three are fixed, and bots have now loaded trained weights and played a
full match with them. A trained bot acts on an output only as far as it was shown
to work on matches it never trained on, draws its yes-or-no answers instead of
thresholding them, and reads aim as a turn from where it is looking — the aim it
learned had been applied at a third of its size, behind a dead zone wider than most
turns a person makes. A trained bot's decision no longer calls into TensorFlow at
all — the forward pass runs from the weights directly, sixty times faster, so eight
trained bots cost a bot server almost nothing. A run now stops when the held-out
score stops improving and
says, per output, whether it learned anything or merely matched the best fixed
answer — most of these outputs are off most of the time, so a network answering
"no" to every button scores well and has learned nothing. The whole chain has a
manual page, and writing it turned up a training flag that had never been wired to
anything: `--lr` was parsed and stored while both models compiled with a fixed
step size. And two matches finishing inside the same second no longer
overwrite each other's recording — the name is only accurate to a second, and a
lobby starting two rooms at once is ordinary.

### A match under way takes players while it has room

Once a match started, its room was closed. Anyone who had not been in it at
the start could only watch, even with seats free: a watcher in a 7/8
free-for-all pressed Join and nothing happened. It now works as a Quake or
Warsow server does.

- A running room with free seats reads **join** in the lobby's rail and puts
  you straight in, on the smaller side in a team mode.
- A full one reads **watch**. While watching, **J** asks the lobby for a seat,
  and you take it on the connection you are watching from, without reloading
  the map.
- A Duel whose two sides are taken, including a side held for a player who
  dropped, puts you in the challengers queue, and the side is yours when it
  frees.
- Every seat is still ticketed. The lobby gives the running game server the
  new seat over its stdin and hands the ticket out only once the server has
  it. A late player's result counts, and **Rejoin match** covers their seat
  like any other.

Fixed along the way:

- A refused join used to be silent. The game's own messages (a refusal, a
  queue place, a round to wait for) now appear in the chat in gold.
- The lobby client skipped a listener whenever the one before it unsubscribed
  itself on the same message, which every one-shot listener does. That
  swallowed the seat handoff here, and could silently drop any message that
  had a one-shot waiter.
- In-game chat sat on top of the health block. It now sits above the bottom
  bar.
- A spectator in warmup was told to press F4 to ready up.

### Watching someone shows what they see

A spectator who chased a player in a free-for-all saw no weapon at all, and a
HUD reading 100 health and the Blade, which were the spectator's own idle
defaults. Watching now shows the watched player's screen. Their weapon is in
front of you; it switches when they switch, flashes and kicks when they fire,
and sways with their stride, and the camera sways and crouches with them. The
HUD shows their health, armour, weapons, ammo and powerup timer, and their
footsteps, shots, pain and pickups play as first-person sound. The demo viewer
and live spectating now run this from the same code, so the two cannot drift
apart, and the demo viewer gained the muzzle flash it lacked.

Fixed along the way:

- Watching a teammate after dying in a round mode drew every shot they fired
  twice, once from the server and once from your own camera.
- Chase cycling stepped onto dead players, because it looked for death where
  the snapshot does not carry it.
- When the chased player died, the name on the bar moved to someone else while
  the camera stayed frozen where they fell. Now the two agree. The view waits
  where they fell, without their gun, and picks them up again when they
  respawn. If they leave the match, it moves to the next player.
- In a round mode, where the dead stay down until the next round, the camera
  moves on to a living player after a few seconds.
- A spectator flying free no longer sees a health and ammo bar describing
  nobody.
- A spectator chasing someone during warmup was told to press F4 to ready up.

### Watching a match, shots and explosions no longer freeze in the air

A spectator saw every rocket, grenade, plasma bolt and explosion stop where it
was first drawn and hang there for good, until the arena filled with frozen
fireballs and specks of light. They were being moved and cleared by the code
that draws your own gun, which a spectator does not have. They now move, fade
and clear on their own.

### The first screen, in the game's look

The start-up screen was the logo on black above a pulsing dot, which never
said it was waiting for a click. It now wears the match handoff's look: its
rail lists what the game is starting — renderer, packages, engine, lobby — and
the logo sits in a ring that turns while it starts, then pulses gold over the
words **Click to start** (**Tap to start** on a touch screen). Enter starts it
too. The lobby now logs in behind it, so a new player's name question is up
the moment the screen lifts, rather than a second or two after a glimpse of the
lobby.

### Who fragged you, and your frags confirmed

The death screen named your killer by an entity number — "Fragged by
player_12" — and the message confirming a frag you took never appeared at
all: it waited to be told who you were, and nothing ever told it. The death
screen now names who fragged you and how (blown up, railed, gunned down,
telefragged…) on a card that reads over any part of the map, counts the
respawn protection down on a striped bar, and darkens the screen in red toward
the edges, which a layout rule had been confining to the middle. **FRAGGED**
and your victim's name now rise above the crosshair when you take one.
Watching someone else, the bar with their name no longer sits on top of the
match clock: it has moved above the bottom of the HUD, and the key guide for
flying free is large enough to read. A round's result stands on a dark plate
instead of floating over the map.

### The ready room fits a laptop screen

On a laptop the ready room did not fit. The map cards slid under the Ready
key; a Search & Destroy room squashed its status to a strip and hid the maps
behind its buttons; in a browser window the buttons could fall off the bottom
of the page; and a narrow team room left no room for your own name next to its
YOU and NOT READY tags, while its Ready key ran off the side. The room now
tightens on a short screen, and a team room that still has more than fits
scrolls its players and maps between a status and a Ready key that stay in
view. Your name keeps its line, the buttons wrap instead of running off, and
the room chat on the left keeps a few lines instead of one.

### Armor you can see is armor you can take

Maps often put armor and health some way above the floor for the game to drop.
The client drew them on the floor, but the server kept each pickup where the
map put it: on Le Toxiquet the red armor hung 80 units up, out of reach of
anyone standing at it, and only a jump took it — which looked like armor that
had not spawned yet. Every map item now comes to rest on the floor when the map
loads, on the server, the client and for bots alike, unless the map marks it as
hanging where it is.

### Settings over a match, laid out as in the lobby

The in-game Settings was the lobby's page in an older panel frame, with a
second SETTINGS title and a cyan Close, and closing it left you with a free
cursor and no menu. It now opens on the match menu's rail — the logo, the four
page keys, Back — with the page on the lobby's stage, and Back or Esc returns
to the match menu. Both rails open with the lobby's logo, which took the place
of the big MATCH MENU title. Esc closing a Video section no longer closes the
whole screen with it.

### A room's stripes move when it is waiting on someone

The striped bar under a room's status crawled all the time. It now moves only
while the room is waiting on someone else — a player to join, the others to
ready up after you have, the server to start, when it runs faster — and stands
still when it is your move, or when the room's match is already running.

### The menus over a match, in the lobby's look

None of the screens that come up during a match were in the lobby's design, and
each had drifted its own way.

- **The Esc menu is the lobby's gold rail.** It slides in over the match with
  the lobby's raised keys — Resume, Settings, Spectate, and Leave match at the
  foot — and names the mode and the map. It said PAUSED, which a multiplayer
  match never is; it now says the match keeps going. Its Spectate key promised
  "Watch the duel" in every mode. For a spectator the first key is Join, with
  each side's key saying how many players it has.
- **Tab works in the menus.** Tab showed the scoreboard even with a menu up, and
  swallowed the key, so a keyboard could never reach a menu's buttons. With the
  Esc menu, the settings or the join screen up, Tab now moves through the keys.
- **The join screen is the handoff's.** A server reached with `connect` greeted
  you with an orange-bracketed panel and a spinning 3D logo. It is now the match
  handoff's rail and stage with every step done, the mode and the map, and keys
  to join or to watch first; it covers the HUD rather than sitting under it.
- **The scoreboard's plate is gold**, not red, and the post-game's way home is
  the lobby's gold key, **Back to the lobby**. The post-game board no longer
  sets its SCORE heading at the size of the scores.
- **The loadout picker** no longer cuts the L off LOADOUT with its slanted edge,
  and its Enter the round key is the lobby's gold key rather than a green bar.
- **The kill feed stays in the fight.** It sat above everything, so frags wrote
  themselves across the loading screen and the menus. It now sits over the
  scoreboard and under every menu.

### Joining a match already under way no longer hangs on the loading screen

A load's last step waits for the scene to report ready. Every explosion added
two empty particle systems, left over from an effect that was taken out, and an
empty particle system never reports ready; the game loop that removes them only
starts once the load is done. Joining a match where people were already firing
rockets held the loading screen up for good. Explosions no longer make them, and
the wait itself now gives up after 15 seconds, naming in the log what was still
not ready, rather than leaving anyone on a loading screen.

### A deathmatch scoreboard lists its players

In a free-for-all the server calls every player's side "spectator", because
only team modes hand out sides, and the scoreboard believed it: everyone,
fragging or not, was listed under SPECTATORS and the board had no rows. Outside
team modes, anyone in the game is now a player, and only real spectators are
listed apart. The end-of-match standings had the same problem.

### Joining a match reads as one sequence

Joining a match showed the handoff screen — the gold rail, "GAME STARTING" —
and then cut to a different, black loading screen with the engine's logo and a
console log. The map loading screen now wears the handoff's look and takes
over from it in place: step 03 MAP LOAD lights up, the stage names the map as
the lobby names it ("Proving Grounds") over its levelshot, and a bar fills as
the map loads — packages, shaders, textures, lightmaps, models — then says
"Setting up" while the game readies its sounds and collision, and "Ready" as it
fades into the arena. A map loaded with no server behind it shows its own
three steps (map data, world, game). A failed load keeps its error on screen
long enough to read instead of flashing past. On a phone-width screen the
handoff no longer scrolls a few pixels because of its background word.

For developers: `MapLoadingOverlay` still decides when the screen is up (holds,
minimum display, fade) and now takes a `view` for what is on it; the engine's
own screen is the default, and `TransferLoadingView` is the handoff-styled one,
set in `src/main.ts`. Display names come through `rememberMapTitle()`, fed by a
room's map vote, the live match list and the demo list; a map nobody has named
keeps its file name.

### The lobby, finished

- **A room says when it can start.** A Search & Destroy room starts with two
  players, but said "Waiting for players" until all ten seats were full. It now
  says "Ready when you are · 3 / 4 ready · 6 seats stay open until it starts",
  "Ready up" once the room is full, and that each side needs a player when one
  is empty. The Ready key counts who is ready, Add bot counts the open seats,
  and the room's heading reads "Up to 5 vs 5 · starts at 2" or "Free for all · 8
  players".
- **Room chat says who came and went**, and how many are here; a player coming
  back from a match is not announced as leaving and joining. Names are coloured
  as on the Play chat.
- **The lobby chat notes a match starting** in any public room ("Duel on
  Proving Grounds started · Reaper vs Eclipse"), and an empty chat says so
  instead of sitting blank.
- **Keyboard players can reach the menu.** Tab from the top of the page went
  into the closed console, which sits off-screen above the page and takes Tab
  for its autocomplete, so focus never got further. A closed console is out of
  Tab's reach now.
- **Less motion when asked for.** With reduced motion set, the menu panel
  appears and goes at once and its frame no longer drifts.
- **Offline is not "unsupported".** With the lobby server down, the leaderboard
  said the server did not offer rankings; it now says the server is offline. A
  Profile with no key yet no longer shows the key's warning on its own.

### The menu keys stand on their sides again

The Play, Leaderboard and Demos keys, and Profile and Settings at the foot of the
rail, looked flat: a steep slanted band with a thin line under it, where the
design draws a key standing on a darker side with a shadow under it. They are
the menu's page tabs underneath, and the old tab frame still applied to them;
its own cut clipped away the key's side and shadow. The Console key beside them,
which was never a tab, always looked right. Now they all do.

### Profile, on the gold panel

Profile was a page of four cards on the stage. It is now what the design drew:
the Profile key at the foot of the menu widens the rail into the same gold panel
the Welcome screen uses, and it opens on your key — hidden until you ask, with
Copy, Save as file and Save in browser under it, and **Done** to go back.
Changing your name and playing as someone else with another key are screens of
their own on the same panel, and Esc steps back to the key and then closes it.
Your ranked record sits on the stage beside the panel.

### Settings, the way the design drew them

The settings screen was the old four-tab form inside the new menu frame. It is
now the screen the design drew: four pages in the rail — Controls, Gameplay,
Video and Audio — saved as you go.

Controls is a keyboard and a mouse coloured by what each key does, beside the
list of actions and their keys. A key can be changed from either end: click it
and pick what it does, or click an action and press the key, click or wheel
turn you want. A key does one thing, so giving it away says what it used to do.
Gameplay shows your side and enemies on a real map as you pick their colours,
and the crosshair as you change it. Video starts from three presets — Smooth,
Balanced (the game's defaults) and Pretty — and marks what each setting costs
in frames. Resets ask once, on the key itself, instead of in a dialog.

What the old screen got wrong along the way:

- The crosshair colour lists did not contain the game's own defaults, green and
  red on a hit, so neither showed as chosen until you changed it.
- Team colours were raw number triples such as `1.55 0.2 1.35`, with a
  separate outline and free-for-all colour for each. A side is now one colour,
  body and outline together, and enemies are one colour in free-for-all too.
- Keys 4 to 9 showed as free while the game still had them on weapon slots
  (a player carries three weapons), and giving one to another action left the
  slot binding in place, so the key did both.
- Scoreboard, chat, console and join could be rebound, and the new key did
  nothing: the game reads Tab, T and Enter, \` and J directly. They now show as
  fixed.
- A Controller tab that could not be opened and a "Test sensitivity" button
  that did nothing are gone.

### The leaderboard, the way the design drew it

The leaderboard now reads like the design: the mode keys in their own colours,
three boards — the last 30 days, all time, and the whole top 100 with a search
and a key that jumps to your row — and the rule it ranks by, written above it
(most wins first, ties to fewer losses). Your rank in every mode sits in the
rail, and when you are off the board your row is pinned under it with what the
next step takes: "11 wins to reach the top 10", "1 win to pass #12". Rows show
wins, losses, matches and win rate. The design also had a K/D column; the lobby
records who won, not who killed whom, so it is left out rather than invented.

### Demos, the way the design drew them

The demos page follows the design now. Three boards sit at the top: **Featured**,
one large match beside this week's other picks with their map shots; **Latest**,
six recordings to a page with page numbers; and **Yours**. The modes are keys in
their own colours, the maps sit in the rail with how many recordings each has,
and the line under the boards says how Featured chose, including when there
were no top-10 matches this week and it fell back to the latest multiplayer
ones. **⚡ Highlights** asks how long a cut you want (1, 2 or 5 minutes) right on
the page instead of in a dialog.

The archive cards used to clip their own text, cutting player names and the map
name off at the top of every card. The design also drew final scores, team
names and players' ranks; a recording's header carries none of those, so a card
shows who played, the map, the mode, how long, when and the size, and nothing
it would have to guess.

### A duel room has no sides to switch

A Duel or Amphi room offered **Switch** ("to Team Udon") and **Shuffle** ("mix
the teams"). With two seats, which side is whose changes nothing: colours follow
who is on your side, and each side is one player. Both keys now appear only in
rooms with teams to choose between, such as Search & Destroy. An empty seat also
stopped drawing a blank status chip under "Waiting for a player".

### The console tells you when it did not do the thing

Typing `r_bloom abc` used to turn bloom off. A numeric cvar given text read it
as zero, took the zero, and reported success — so a typo silently changed the
renderer, and a headless batch full of typos exited 0. A numeric cvar now
refuses text and keeps the value it had, and the console reports the refusal as
a failed command, which is what batch and headless runners take their exit code
from. A number outside the cvar's range is still clamped, as it was.

A value kept from browser storage, or from an earlier registration, also
skipped the type and bounds of the registration that followed it: a saved `99`
stayed `99` for a variable later registered with a maximum of 3. It is now held
to whatever the registration declares.

`help physics` and `help show_fps` printed usage lines that left out arguments
those commands accept.

### The console fits the menu and makes commands easier to find

The dropdown console used a separate colour scheme and had only an Inspect
button. It now follows the Washiki cyan, magenta and gold palette and has Help,
Size and Clear keys beside Inspect. Size cycles through 50%, 75% and 100% of
the screen. Command names in the help list and autocomplete show their usage on
hover, while the full help list is grouped by purpose. One registered `help`
command now owns that output; previously the auto-discovered command replaced
the richer console version during startup.

The large faint character behind the lobby's gold menu rail was an explicit
decorative watermark. It has been removed so it no longer shows through the
main menu.

### The Android app is this game

The Capacitor project still carried another product's identity —
`com.iwmengine.ganjawars`, "Ganjawars" — in seven places across four files. It
is `net.washoi.game`, "Washiki Washoi!" now, reverse-DNS on a domain the studio
owns, with `MainActivity` moved into the matching package directory. An
application ID is the store's permanent identity for an app and is tied to
signing, so this was worth changing before the first upload rather than after.

### The Android splash screen lets go

The native splash is configured to wait for the app to dismiss it, and nothing
ever did, so it sat there. The app now hides it as soon as its own loading
screen is up — early, so the progress the loading screen reports is not hidden
behind a still image for the whole boot. Unverified on a device.

### bind binds

`bind` has taken a key and a command since the engine had a console, and done
nothing with them but report that binding was planned. It binds now:

```text
bind f screenshot
bind 5 "give all"
unbind f
```

Keys are written the way you say them — `f`, `5`, `f5`, `space`, `esc`, `` ` ``
— or as the browser's key code, and bindings persist per browser. This is not
the action map in Settings → Controls: an action says what a key *means* while
it is held, a binding runs a command once on the press, and a key can be both
— binding `space` to a command does not stop it being Jump. A bound key stays
quiet while you are typing, while the console is open, and whenever Ctrl, Alt
or Meta is held, so it never takes a shortcut that was not meant for it.

### The bug lists say how old they are

`docs/known_bugs.md` held one entry, marked critical and reproducible every
time, filed in March 2025 — before the networking audit that reworked the very
mechanism it blames. It is now recorded as unconfirmed, with what changed
underneath it and what would actually settle it. The research list gained a
header saying it is a record of what was believed at the time, and every
`file.ts:123` citation in it was deleted rather than updated: all were wrong,
and they rot again on the next edit.

### A tutorial import that only worked on Windows

The sidescroller tutorial imported `SidescrollController`; the file is
`SideScrollController.ts`. Windows and macOS shrug at the difference and Linux
does not, so the snippet a reader is most likely to paste would have failed in
CI or a container. The feature-status page also still listed the Electron
packaging blocker this cycle fixed, and had five camera controllers where there
are six.

### The networking guide caught up with two releases

The protocol table still said snapshots were message `0x04`. They are `0x0B`;
`0x04` is the old envelope that never named the state it was deltaed against,
kept only for reading old data. `0x09` was listed as a server ping that does
not exist — it carries server text — and the three message types added for
resuming a dropped session and choosing a kit were missing. The snapshot format
did not mention the baseline header at all, which is the entire point of the
change that introduced it, and lag compensation — the headline of the same
release — had no section in the guide that covers hit registration.

### A typo no longer switches freefly collision off

`freefly_collision` read anything it did not recognise as "not on, therefore
off" — including `freefly_collision info`, which the physics guide told you to
type. It disabled collision and reported that as the state, so the command
appeared to be telling you the truth. It now refuses an option it does not have
and says which ones it takes.

### A file pattern is matched as a pattern

`findByPattern` turned a glob into a regex by swapping `*` and `?` and leaving
everything else alone, so the rest of the pattern kept whatever the regex
engine made of it: `maps/*.bsp` matched `maps/wdm2Xbsp`, and a texture name
carrying an unbalanced bracket or parenthesis — Q3-era names carry both, and
plus signs — threw an invalid-regular-expression error instead of matching
nothing.

### The lobby has a manual page

Accounts, rooms, private invites, match tickets, signed results and the ranking
rule shipped in v0.9.23 with nothing written about them. There is a Lobby
Server guide now, and the player-facing Connecting page no longer opens on a
screen the game has not had for a release — it describes being asked who you
are, the key that opens your account anywhere, a private room whose only way in
is its link, and the return trip to the same room afterwards. Two of its claims
were wrong: an unticketed console connect is admitted as a spectator rather
than refused, and a dropped seat is held for twenty seconds, not three.

### Weapons respawn in thirty seconds

The pickup page said fifteen, which is the ammo interval. Every other number on
the weapon and pickup pages held against the definitions: damage, fire rate,
splash radii, clip sizes and ammo classes for all nine weapons, the armor plate
rules, and the quad's thirty seconds in hand and two minutes away.

### What the bots actually do

The bot page described four difficulty tiers by aim percentage — ~70 to ~99 —
where the presets are 0.25 to 0.92 across eight dials, and a priority-ordered
state list the brain does not have. Bots choose what to do through a goal
layer: sources propose goals, considerations score them, and the arbiter takes
the best reason rather than the highest total. The page also called two shipped
things future work: training from demo recordings, and bots joining lobby
rooms.

### Amphi is in the manual

The mode shipped in v0.9.23 with no page, no sidebar entry and no row in the
gametype table, which still said the game had four gametypes. It has five, and
Amphi's page now describes the kit you pick before you are seated, what decides
a round when nobody is eliminated, the drawn round, and its three maps. The
gametype barrel also listed Duel and Team Deathmatch as future work while both
have been playable all along.

### The chat page described colours the game does not use

In-game chat colours a sender by allegiance — teammate or opponent, whichever
side you are on this half — while the manual described fixed team colours and a
`[SPEC]` tag that does not exist. The HUD page also predated Amphi, and gave
its round clock, round-result banner and loadout picker to Search & Destroy
alone.

### Desktop packaging can run at all

`npm run electron:build` could never have produced anything. The config read a
game manifest from a path that does not exist, and — because this package is
`"type": "module"` — a `.js` config file's `module.exports` assigns into
nothing, so electron-builder was handed an empty object: no app name, no
appId, no file list. The config is now `electron-builder.config.cjs`, it picks
its game the way the web build does, and it takes the app's name from that
game's `displayName`. A test loads it, so neither half can rot again unseen.

The web deployment guide also told you to serve source maps. The build moves
them out of `dist/` on purpose, because `dist/` is what gets served and what
the desktop and Android packages copy wholesale.

### .env.example names every variable again

The file you are told to copy listed three environment variables; the code
reads eighteen. Everything the lobby, the bot server, a spawned game server and
the headless tools actually read is in there now, grouped by which process
reads it and commented with what it does — including the two the lobby sets per
match, which nobody should set by hand.

### The camera says which mode it is in

`camera mode` answered with the controller's class name — `FreeflyController` —
which is not a word the command accepts. It answers `freefly` now, and the list
of modes it offers is built from the table it matches against instead of a
second copy that could drift from it.

### A quoted argument survives a batch

`--exec` splits its commands on semicolons, and split on the ones inside a
quoted argument too. The manual's own example of a deterministic movement
replay — `sim replay "W+CROUCH 60; JUMP 1; W 30"` — was therefore impossible to
run from a batch: the sequence arrived as three unknown commands and the run
exited 1. Splitting now leaves anything inside double quotes alone.

### The manual, read against the code

The console and cvar pages were read line by line against
`src/engine/console/` and `src/engine/core/Cvar.ts`. The API they describe was
accurate throughout; what was wrong was what they left out and what they
implied.

- The command reference was missing about thirty commands the engine actually
  registers, among them `god`, `noclip`, `giveweapon`, `spectator`,
  `timescale`, `spawn`, `weather`, `wind`, `light`, `shadow`, `skybox` and
  `daynight`, along with whole subcommand families of `bsp`, `shader` and
  `freefly_collision`. Developer-gated commands are now marked as such.
- The console guide told you to turn developer mode on before inspecting maps
  and then demonstrated it with a command that is not gated. It now names
  commands that are.
- The render-variables page predated the water release and listed none of its
  fourteen variables.
- The console tutorial quoted an argument with single quotes; the parser
  honours double quotes only.

The headless pages were then read the same way, by running what they
documented: a "useful batch" that fails at its first command because `pk3` is
developer-gated, a network client invoked with two flags it does not have
(`--host` and `--port`; it takes `--connect <url>`), and the replay batch
above. The commands only this runner registers — `sim`, `anim`, `headless`,
`leaktest`, `trace_test` — were not mentioned anywhere, and neither were the
dedicated server's tickrate, snapshot-rate and TLS flags.
