# v0.9.37

**Release Date:** unreleased — living changelog

## Changes

### 1.0.0-alpha release review

- **Account settings survive slow logins and late-loaded systems.** Background
  uploads now wait for the initial account download, and replies from a stopped
  account sync cannot overwrite the next account's sync state. Downloaded cvars
  reach systems that register later; saved values awaiting registration are kept
  when other settings are saved and when settings upload to the account.
- **Release tests clean up their browser fixtures.** The BSP material tests
  restore their temporary window, and profile deletion tests destroy opened
  views. Leaked browser state and Escape handlers interfered with later map,
  chat and texture-browser checks in the shared test process.

### Papercuts

- **Black world surfaces on Macs fixed.** Legacy ETC1 `.ktx` textures with mipmaps
  rendered pure black on Apple GPUs (seen in Brave on a MacBook Air), the
  desktop GPUs that expose ETC. Babylon's WebGL2 uploader fills mip chains
  with `compressedTexSubImage2D`, which ETC1 does not support, so the upload failed
  (`Invalid internal format 0x0000` in the console) and the empty texture sampled
  black. ETC1 blocks are valid ETC2 RGB8 data, so these files are now uploaded as
  ETC2; without ETC2 an ETC1 mip chain is decoded in software. Windows and Linux,
  which already decoded ETC1 in software, are unchanged.
- The menu no longer requests the retired `/data/ui/background1.png` backdrop, which
  logged a 404 on every visit.
- Weapons without a `tag_ammo` anchor (the blade) no longer request an ammo-counter
  `.cfg` that does not exist, which logged a 404 on every weapon load.
- **Music remembers off and volume 0.** A saved music setting was only shown in
  Settings: the player itself started at half volume with music on, and a new map,
  the lobby or a menu return started the playlist again even with music off. The
  saved values now apply at startup, playlists stay silent while music is off, and
  turning music back on resumes the current one.
- **Colour-blindness correction.** Video → Advanced → **Color blindness** corrects
  the picture for red-weak, green-weak or blue-yellow vision, explaining each,
  with a strength slider (`r_colorcorrection` 0–3, `r_colorcorrection_strength`).
  `r_colorsimulation` 1–3 shows a map as a colour-blind player sees it, for map
  testing. Both apply live from the console; off, they cost nothing, and on they
  are one light full-screen pass. The correction follows the player's account.
- Opening the console puts the cursor in its input line, ready to type. In a match
  the pause menu that opens as the mouse is released took focus away, so the line
  had to be clicked first.
- `disconnect` in the console now returns to the lobby like **Leave match**, instead
  of leaving the last frame frozen on screen with its sounds still playing.
- **Lobby and room chat open on the newest message.** The history arrived before
  the log was laid out, so it showed from its oldest line and had to be scrolled
  down. Both logs now stay on the newest message, also when the Play page returns
  or the window resizes, until the reader scrolls up; scrolling back down follows
  again. The lobby log keeps its last 100 lines (the server sends the last 50).
- **Weapon colours on the HUD loadout slots.** Each slot is tinted with its
  weapon's colour (player suggestion): Blade teal, Rocket Launcher red, Grenade
  Launcher blue, Electrobolt a brighter teal, Voltaic yellow, Machinegun grey,
  Plasmagun green, Riotgun orange and Instagun magenta.
- **Count-up match clock.** Settings → Gameplay → **Match clock** (`cl_invertClock`)
  can show time played from 0:00 instead of time left (player suggestion). The
  server now sends `timeElapsed` in `match_state`; an older server keeps the
  countdown.
- **Auto-switch on pickup can be turned off.** Settings → Gameplay → **Switch to
  picked-up weapons** (`cl_autoswitch`, on by default). Off, walking over a gun
  no longer takes it out, so a spawn-blade fight is not interrupted (player
  suggestion). The client sends the preference in a new `ClientPrefs` message
  (0x8c) after every join and when it changes; an older server ignores it and
  keeps switching.
- **The Private leaderboard lists people only.** Bot preset accounts are still
  rated, and people are still rated against them, but they no longer appear on
  the boards; ranks and counts are among people (player suggestion).
- **Bots turn like people.** Bots snapped their view to every decision, about 30
  times a second, which read as spinning and aimbot flicks, and on some jump pads
  they spun round in flight. The view now eases toward where the bot wants to
  look, with a top speed and settle time from its difficulty, a pause before
  turns over 45°, no twitch at small changes unless it is shooting, and an aim
  error that wanders instead of shaking. Movement no longer waits for the view.
  On routes bots look ahead round corners; over a jump pad's landing they hold
  their view. In an offline tracking test, aim error against a strafing target
  rose by about 0.2–0.3° per preset (Insane 0.39° → 0.55°).
- **Bots hear instead of knowing.** A bot used to know where every enemy in its
  area was, walls or not, and which items were up anywhere on the map. Now it
  knows what it sees in front of it and what it hears: shots (rockets and rails
  further), explosions, footsteps, jumps, landings, pain and pickups. A heard
  armour, mega or powerup pickup is timed (by duel, DM and TDM item-timing
  skill), so the bot is back at the spot when it returns, watching the ways in;
  an item taken out of earshot is still believed there until the bot sees it gone.
- **Slide-blade lunge.** A bot running at slide speed with the blade on it and an
  enemy one slide ahead (200–450 units) may crouch-slide in and swing on arrival,
  jumping out sideways with its gun back out if it misses. Never on Easy, most of
  the time on Insane.
- **Bots move in fights.** The strafe used to flip every half second or so on a
  steady beat. Strafe runs now last 0.25–0.9 s with quick double-backs and stops
  on the higher presets; a hit sets off a jump or slide dodge, a rocket or grenade
  on course is sidestepped (and jumped) once the bot has had its reaction time to
  notice it, strafe-jumpers hop to keep speed at range, and with a splash weapon
  a bot takes a nearby ledge above its enemy. All of it scales with dodge skill.
- **Bots combo and switch early.** A rocket that throws the enemy up is followed by
  the electrobolt at range or the riotgun close, a rocket at arm's length by the
  blade, and long plasma pressure is broken by a rail shot. Out of a fight, a bot
  that hears an enemy close gets the gun for that distance out before they come
  into view. Each chance is taken at prediction-skill odds, from about one in
  five on Easy to nine in ten on Insane.
- **Bot moods and mistakes.** Two kills without dying make a bot confident (it
  backs off later), three deaths in a row tilt it (reckless, with looser aim and
  slower reactions), and low health or an enemy known to carry armour or a
  powerup makes it cautious; each fades after 20 quiet seconds. Each new fight
  may carry one human mistake, at the preset's mistake rate (one fight in two on
  Easy, about one in eighty on Insane): a wild first shot, a second on the wrong
  gun, a glance at an item, or forgetting the enemy once they are out of sight.
- **Bots chat.** Bots say the odd line to the humans they play: "gl hf" as the
  match goes live, something cheeky after killing a human (with blade show-offs
  and streak taunts), gracious or mad after being killed by one, a sulk on a bad
  run, and "gg" in the last 30 seconds. About fifteen lines per moment, in
  English with a few Finnish ones. Each bot's name sets how chatty and how sore
  a loser it is; a bot says at most one line per 20 s, the whole bot server at
  most one per 5 s, each after a moment's typing. Bot-only matches stay quiet.
  `BOT_CHAT=0` on the bot server turns it off; training never chats.
- The demo browser no longer shows recordings under two minutes anywhere:
  **Latest**, **Your demos** and featured picks. They were mostly one player
  alone on a map. The files are kept on disk.
- **Settings follow the account.** Key bindings, game preferences (the `cl_`, `cg_`,
  `s_` and `m_` cvars, such as FOV and sensitivity), the HUD layout, UI theme and
  remembered loadouts now sync to the logged-in account and arrive on any browser
  that logs in to it. Graphics stay per device. The lobby keeps them in a new
  `settings.db` beside `players.db`; nothing existing is migrated or changed, a
  browser uploads its settings at its first login, and a browser whose settings an
  account's replace keeps its own under `shag_settings_backup`.
- **Drop-downs in Settings** (player sounds, colour correction) are now our own
  menu instead of the browser's: it opens right under the field in the settings
  style, marks the current choice, and works with the mouse or the arrow keys,
  Enter and Escape.
- **Credits.** A **CREDITS** button beside **?** on the Play page opens the
  credits and copyrights, read from the game's `CREDITS.md` so GitHub and the
  game show the same text: the team and playtesters, libraries, fonts,
  the Arc Blade and Warsow weapon models, the Warfork sound packs, Mixamo, and
  the CC BY models used in our maps, each with its licence.
- The **welcome guide** and **credits** now use the lobby's yellow, ink and
  violet instead of red, so they match the rest of the menus.
- **Lobby offline** no longer covers the links at the bottom of the Play page.
- **Tooltips** are the game's own small ink-and-gold label instead of the
  browser's grey box, on hover and keyboard focus, and screen readers still read
  them.
- **Scrollbars** are thin and violet everywhere, dark on the yellow rail.
- The **version** is shown beside **CREDITS** at the bottom of the Play page,
  with a **DEVLOG** link to washoi.net/devlog that opens in a new tab.
- Turning on **Color blindness** switches default team colors to Cyan and Orange,
  with a notice and Undo. Colors a player picked are kept.
- The browser console is quieter: per-map and per-effect setup lines only print
  with `developer 1`.
- **Link previews** of the game (Discord, chat apps, social sites) now show the
  washoi.net card image, with the large-image card on X.
- The desktop app's **Help** menu opens washoi.net instead of a placeholder
  GitHub address.
- Release builds leave out the `public/ui-proto` design mockups; the dev server
  still serves them.
- **A quiet console when nothing is wrong.** Engine and game client lines now go
  through `devLog`, so a lobby visit prints about 20 lines instead of about 200;
  `developer 1` brings them back. A game server's per-match setup lines print
  with `SHAG_DEBUG=setup`.
- `noclip` toggles the free-fly camera's collision again; it had looked for
  instance members the camera keeps as statics, so it never changed anything.
  `wind direction <x> <y> <z>` sets the wind's heading instead of silently
  doing nothing.
- Type safety: `noImplicitOverride` is on, the engine's `window` debug globals
  and optional camera-controller capabilities are typed, and nearly every
  explicit `any` outside tests is gone (`as any` 237 → 4). The Biome warning
  baseline drops from 339 to 88. Biome is 2.5.15.
- Bugs those casts hid: the `lightgrid` debug spheres are tagged, so clearing
  them works; freefly collision no longer reaches into a private backend map;
  the physics debug readout shows Havok's real gravity; server WebTransport
  sends handle their errors.
- Removed dead code: the engine's old client-side pickup check (never called;
  the server decides pickups) and the `debug:collision` script, whose mock map
  could not exercise real collision.
- Babylon.js 9.17 → 9.31.2 (core, loaders, materials, KTX2 decoder) and Havok
  1.3.14. Both shader corrections in `BabylonShaderFixes` still apply to 9.31.
- **New version notice.** A tab left open across a deploy asks for its lazy
  pieces (kill feed, award banner, damage numbers, teleport effect) by file
  names the new build no longer has. Those effects used to stop appearing
  without a word; now the page offers a reload once, and each failure is logged
  with where it happened.
- Background async work (lazy chunks, model and playlist loads, transports,
  bot and lobby handlers) now always handles its errors: 87 unhandled promises
  are caught or marked, and Biome's `noFloatingPromises` keeps new ones out.
  TypeScript now also rejects unreachable code.
- **Highlight scenes.** The highlight reel films each frag as a scene: a
  third-person fly-by that slows into the frag, a flash back to the same moment
  through the player's eyes, then a slow orbit round it. Scenes end with a fade,
  flash or crossfade that stays the same each time a demo is played, and the
  reel opens and closes on black. The shot card and counter number highlights.
- Highlight camera fixes: a zoom's narrow field of view no longer carries into
  every later fly-by and the free camera; rocket-jump shots follow the jump's
  heading instead of the map's axes; the ending orbit watches the victim when
  the shot crossed the map instead of circling the shooter.
- **Trick jumps in the highlight reel.** Wall jumps, slides and hop chains
  faster than sprinting are now found in demos and cut in between frag scenes:
  about one for every two frags, never more than two in a row. A camera follows
  the run along its route, then the reel flashes into the player's eyes for its
  best moment.
- A frag made while jumping or wall jumping is an airborne frag again; any jump
  used to count as a rocket jump.
- Highlight reels are 1, 2 or 3 minutes (was 1, 2 or 5), and
  `demoplay cinematic` caps at 3. Every reel fades in from black and out to
  black over a full second, and stays black once it ends instead of showing the
  last frame.
- **Lightning beam in highlights.** In a reel's slow motion the Voltaic beam
  barely showed: its updates arrive slowed down with the demo, but it aged on
  the real clock and faded out between them. Beams, rails, tracers, flashes and
  sparks in demo playback now age on the demo's own clock, so they last as long
  at any speed and hold still while paused.
- When a highlight reel has faded to black, two gold keys fade in at the lower
  right: **Replay** plays it again from the start, **Exit** goes back to the
  demos as ✕ does.
- **Title and end cards on highlight reels.** A reel opens on who played,
  cut like the scoreboard: each team's plate over all its names, a duel's two
  players on gold plates, or up to eight free-for-all names and a count of the
  rest, with a gold VS between. It closes on cream chips for the match's top
  fragger and the reel's best moment, and how many highlights and trick jumps
  it held, above Replay and Exit.
- **Demo keys.** Space plays or pauses; ← and → move 5 seconds (in a reel, a
  shot); , and . step a frame; ↑ and ↓ change speed; N and P jump to the next or
  previous frag; Tab, Shift+Tab and 1–9 switch whose eyes you watch. Space and
  the arrows stay with the free camera while you fly it.
- **Clean view.** H now hides the mouse pointer too, so a screen recording of a
  demo or reel shows only the picture and the reel's cards.
- **Terms of service.** The welcome guide's first page now shows a short
  welcome and the terms (TERMS.md in the game's repository) in a scrolling box.
  Tick **I agree to the terms of service** to go on to your keys and tips; until
  then the guide stays open even if it was set not to show again. New terms ask
  again.
- **Fun words instead of asterisks.** A word the chat filter catches no longer
  becomes `***`: it turns into a Japanese noodle, a fruit or a silly animal
  ("What the duck is this?!"), in lobby, room and match chat alike.
- **Player names go through the chat filter.** A name it would catch shows as a
  silly name of its own, such as Soggy_Ramen, everywhere others see it: the
  lobby, rooms, matches, scoreboards, leaderboards, new demos and the demo
  list. The same name always gets the same silly one. Picking such a name is
  refused with "That name isn't allowed".
- **SHAGGED File panel.** The MAP menu is now one folder key that opens a gold
  File panel (Ctrl+O). It shows this map's name, ID and save state (a dot on the key
  turns amber when the server copy is behind), plus Save, Server save, New and
  Room template, and Import and Export. A list of drafts in this browser and maps on
  the server can be filtered and sorted. Every row has a download key that saves its
  `.map`, and local drafts other than the open one can be deleted.
- **Import .map in SHAGGED.** Drop a Quake 3 `.map` anywhere on the editor, or pick
  one in the File panel, and it opens as a new draft. The open draft is saved first.
  It accepts classic and `brushDef` brushes (boxes stay boxes, other convex brushes
  become hulls), patchDef2 patches, point and brush entities, worldspawn keys and
  func_groups as editor groups. Anything skipped, such as Valve 220 or Doom 3
  brushes, or patches inside brush entities, is listed in Map Health as "Not
  imported".
- **SHAGGED toolbar room.** Select, Vertices, Brush, Patch and Curves share one tray
  with their keys marked: **S**, **V**, **B**, **P** and **C** (C opens Curves). V
  was Select and is now Vertices; G still works for Vertices. Textures (**T**) and
  Models (**M**) moved off the toolbar to tabs on the right edge, which open and
  close their drawers and ride the open drawer's edge.
- **SHAGGED Entity key.** Entity is one key that names the class it places (spawn,
  light, model…), with a small ▾ key holding the class list. Picking a class still
  switches to the Entity tool. At 1600 px the whole toolbar now fits on one row.
- The texture new brushes get is shown on the SHAGGED Textures edge tab instead of
  the toolbar.
- SHAGGED's Compile, Playtest and build status share one **Build** menu. A dot on
  the key shows the state: grey offline, green ready, amber compiling, red failed.
- **SHAGGED floating bar.** A see-through bar floats at the bottom centre of the
  views. It shows the tool in hand with its key (and the curve shape or entity
  class), the texture new brushes get, and the grid size. It never takes clicks.
- SHAGGED layout papercuts: the toolbar fits on one row at 1280 px; the texture and
  model drawers start below the toolbar instead of covering its right end; toolbar
  menus open over an open drawer; and the edge tabs move to the screen edge when the
  inspector is hidden on narrow windows. The current texture shows only on the
  floating bar now.
- **SHAGGED Caulk key.** A square dev-grid checker key after Curves, as in Radiant.
  It puts `common/caulk` on the selected brushes and patches (or only the selected
  faces) as one undo step. With nothing selected it switches to the Brush tool with
  caulk as the texture.
- Map Health moved into SHAGGED's Build menu (H still opens it).
- **No more endless bot servers.** Pressing Esc → Spectate within three seconds of
  joining was silently ignored by the server while the game had already switched
  to watching, so the player stayed in the match. Spectate is now always honoured,
  and a join that comes too soon says "Wait a moment before joining again." A
  lobby match where humans only watch (for example after spectating out of a bot
  match, which freezes warmup for want of an opponent) now closes with a notice
  after two minutes instead of running forever.
- **Faster on Firefox.** The frosted blur behind HUD panels, menus and dialogs is
  off by default on Firefox, which redraws it every frame and loses a lot of frame
  rate to it. Panels get a slightly darker tint instead. `hud_blur 1` turns it back
  on (and `hud_blur 0` turns it off in any browser) for comparison.
- **Less work per frame for the HUD, in every browser.** The crosshair repaints
  only when it changes (moving, firing, aiming, a hit flash) instead of every
  frame, the speedometer writes its number only when it moves, and the ready bar
  no longer rewrites itself 20 times a second. A test now checks that a HUD tick
  with nothing new leaves the page untouched.
- **The game asks for the fast GPU.** On laptops with two graphics chips the
  browser is now told to prefer the dedicated one, which WebGPU already did.
- The screen-sized canvas behind the damage flash is hidden between hits instead of
  sitting transparent over the game for the rest of the session.
- **Gibs and damage numbers ran twice a frame online.** They were ticked once by
  the game and again by the camera, so gib physics (a collision trace per bouncing
  piece) ran twice and gibs and damage numbers fell and faded at double speed. They
  now run once, at their intended speed. A spectator who never deals damage no
  longer re-imports the damage-number module every frame.
- **Less garbage per network message.** Every message (each snapshot, and each
  command and ack, which a bot sends 125 times a second) used to allocate and
  zero a fresh 16 KB buffer. They now reuse one, and a snapshot is copied out
  once instead of three times. Bot-filled servers benefit most.
- **Server visibility checks walk the map once per entity.** Each snapshot looked
  up every entity's spot in the BSP again for every client. Now each entity and
  each viewer is looked up once per snapshot, so 16 players and 50 entities do 66
  lookups instead of 1,600.
- **Match state is encoded once per snapshot.** The scoreboard roster in
  match_state, and each weapon_state's weapon and ammo lists, were turned into
  JSON again for every client. They are now built once and shared, so the
  server's snapshot cost no longer grows with players × clients.
- **Bots trace each sight line once.** A bot's perception and its vision both
  checked line of sight to the same enemies, from the same spot, on every
  snapshot. The second check now reuses the first, halving bots' sight traces.
- **Rockets and grenades in flight cost less per frame.** Each one was looked up
  with a scan of every projectile (so 20 in the air meant 400 checks a frame) and
  allocated fresh vectors every frame. The lookup is now direct and the frame
  reuses its vectors.
- **Opponents' health and armor are no longer sent to you.** Every client
  received every player's health and armor in every snapshot, so a modified
  client could have shown enemy health over their heads. Now you get your own,
  your team's in team modes (the players you can watch once dead), and
  spectators get everyone's. Whether a player is dead stays public.
- **Ping on the results screen and in the spectator list.** Both always read
  0 ms because they used a latency value the server never filled in. They now
  show the measured round trip that the in-match scoreboard already used,
  refreshed once a second.
- **Collision traces allocate nothing on the way down the map tree.** Every
  sweep (more than ten per player per tick for movement alone, on the server and
  in client prediction) made two small arrays at each plane it crossed, plus more
  for each lift and breakable. They now reuse scratch arrays. Point checks for
  water, lava and ladders do the same.
- **Pickups find dropped weapons once per tick.** The server walked every entity
  in the world looking for dropped weapons, once for every player, every tick.
  It now gathers them once per tick.
- **Less camera work per frame.** The first-person camera computed a movement
  direction every frame that nothing used (two matrix transforms and seven
  vectors), and rebuilt the view-effects state with two cloned vectors every
  frame. The first is gone and the second is reused.
- **Five lighting settings could only be 0 or 1.** r_godrays_density,
  r_godrays_decay, r_daynight_time, r_daynight_lm_min and
  r_daynight_moon_intensity were registered as whole-number settings because
  their maximum is 1, so any value typed or saved was rounded to 0 or 1. The
  animated day/night cycle snapped between midnight and the next day. They now
  keep their fractions.
- **The day/night cycle no longer saves all settings every frame.** With
  r_daynight_animate 1 the clock wrote r_daynight_time every frame, and each write
  re-saved every setting to browser storage. The clock now runs on its own and
  saves once a game minute; a time typed in the console still takes over.
- **The view weapon's light sample allocates nothing.** It read the map's light
  grid at the camera every frame with about nine throwaway arrays; it now fills
  one reused result.
- **Pickups heal through the copy-on-write handle.** Health, armor, mega-health
  decay and powerups were written straight into the entity shared with the
  previous tick, changing the previous tick's state as well.
- **Each client's snapshot events are built in one pass.** The server copied the
  event list, filtered it, and rebuilt it again for every client on every
  snapshot. One loop now does all three, and agent directives are appended to
  that list instead of copying it a fourth time.
- **The announcer works out who is leading once per snapshot.** It filtered and
  searched the scoreboard every frame to tell whether you lead, tie or trail;
  the answer is now kept until a snapshot brings a new scoreboard.
- **Bots read each snapshot in one pass.** For every entity a bot searched the
  whole player list to see whether it was a player, and searched its own list
  again for each kill or shot event; both lookups are now a map built once per
  snapshot.
- **Collision traces no longer allocate for every lift on the map.** Each trace
  and point check made a fresh position object per lift before even checking
  whether the lift was nearby; the lift's height is now read in place.
- **The server skips decoding input it has already seen.** Clients send each
  command three times for packet-loss cover, and the server fully decoded all
  three before dropping two; it now reads just the sequence number first.
- **The game server stops cloning every player every tick.** Each tick it
  deep-copied every player (and their queued input) the first time anything
  touched them, to keep the previous tick's state intact, but nothing on the
  live server ever reads a previous tick's state: snapshots, delta baselines
  and lag compensation all copy the values they keep. The live server now
  edits entities in place. Copying stays on by default for the tools that do
  keep old states (re-sim checks and the headless tick tests).
- **Removed the `server:game` demo script.** It simulated a short scripted
  match in the terminal, wasn't part of the server build, and nothing
  referenced it. `server:tick` and `server:fuzz` stay: the regression checks
  and the manual use them.
- **Collision traces stop allocating their arguments.** Every trace went
  through three thin layers that each built new vectors, option objects and
  coordinate tuples before any collision math ran, several times per player
  per tick. They now reuse scratch objects for what is only read during the
  call; results are still fresh objects, since callers keep them.
- **Lifts check who is nearby without allocating.** Each tick, every lift
  built new bounding boxes for every actor, a new rider set and a filtered
  list, even with nobody near it. The step now reuses all of them, and
  dropped items without a body are skipped before being taken for writing.
- **Damage numbers are merged once per snapshot.** The server re-merged every
  hit gathered since the last snapshot on every tick in between (string keys,
  copies and a new map each time). It now merges once, when the snapshot
  reads them. The numbers players see are the same.
- **Lag-compensation history is a reused ring.** Every tick the server built
  a new map and one position object per player for rewound shots, copied the
  lift offsets into a new array, and scanned the whole history twice to prune
  it. History is now a fixed ring of slots indexed by tick, each reusing its
  map, objects and array; overwriting a slot is what expires the old tick.
- **The kill list is no longer copied twice a tick.** Both readers only look
  at it, and it is almost always empty.
- **No per-tick closures for movement input and gametype callbacks.** Each
  player's movement step built a new input object, two nested objects and a
  closure; the gametype tick context built three closures every tick. Both now
  reuse what they made once.
- **Weapon state keys are built once per player.** Deciding whether each
  client still needed another player's weapon state built a fresh key string
  for every weapon event for every client on every snapshot.
- **A held blade stops replacing its ammo every tick.** Melee ammo is kept
  full by writing a new ammo object each tick; it is now only written when it
  is not already full.
- **Modes without bot directives skip the work.** Every snapshot, for every
  player, the server built a context object, a fallback position and a
  closure to ask the gametype for bot orders, even in modes that never give
  any (deathmatch). Those modes now return straight away.
- **HUD flashes stop forcing a page layout.** The ammo, health, armor, frag
  and value-bar flashes restarted their animation by removing the class,
  reading the element's width and adding it back, which makes the browser lay
  out the whole page on the spot. The ammo counter did it on every shot. A
  running flash is now rewound in place and its class is dropped when it ends.
- **The open scoreboard idles between snapshots.** While held open (and the
  whole post-game screen), it rebuilt a JSON signature of every row and
  searched the page for ping cells twenty times a second. It now does nothing
  until a snapshot brings a new scoreboard.
- **The respawn countdown writes only the number.** Every 50 ms the death card
  re-set its layout attribute, label and visibility to the same values; those
  are now set once per death and the timer text only when it changes.
- **The demo player's controls write only what changed.** Every frame of a
  demo or reel, paused or not, the timeline, play button, speed button, clock
  and status were all rewritten, with four element lookups for the key
  labels. Each is now written only when its value changes; the clock moves
  once a second.
- **The kill feed fades with CSS instead of a frame loop.** Each fading entry
  had its opacity written every frame, and the loop kept running for seven
  seconds after every kill. Two timers and one CSS transition do it now.
- **The spectator bar stops rewriting the watched player's name.** It was set
  on every snapshot while spectating; it is now written only when it changes.
- **A hidden HUD stops ticking its widgets.** On the post-game screen (and a
  demo's fly-by shots) the HUD is hidden, but every widget still updated
  twenty times a second. They now wait until the HUD is shown, and catch up
  at once when it is. The scoreboard and chat stay live.
- **Shotgun tracers stop allocating every frame.** Each traveling pellet
  rebuilt its direction, both segment ends, the midpoint and its rotation
  every frame, about a dozen objects per pellet for every blast on screen. A
  pellet flies straight, so its rotation is now set once at spawn and each
  frame only slides and stretches it in place.
- **Pickups share one player position per frame.** Every pickup on the map
  looked up the camera, asked the controller for a new position vector, and
  checked freefly and pointer lock, every frame. That is now worked out once
  per frame and shared by all of them.
- **The quad glow stops re-walking the player rig.** While a player held quad,
  every frame listed every node of their model (bones included) and forced a
  world-matrix update on each weapon mesh just to read a scale that never
  changes. Both lists are now built once per model.
- **Player animations are switched, not rebuilt.** Every time a remote player
  went between idle, walk, run, strafe or jump (every bunnyhop toggles jump),
  the old animation group was disposed and a new one built, channel by bone
  channel. Each model now keeps one group per clip and switches between them;
  a reused group starts from its first frame at normal speed, as a new one
  did. Ragdolls and model disposal free all of them.
- **Demo playback stops re-reading the same snapshot.** The demo viewer pushed
  the lookahead snapshot into the player timeline every frame, even when
  nothing new had arrived, and rebuilt the set of player ids each time. It now
  skips a snapshot it has already pushed, and the id set is built once per
  recorded tick.
- **Water does its per-frame setup once, not per surface.** Every liquid
  surface re-read six settings and re-computed the camera direction each
  frame, and the debug state line was formatted as a string just to see it had
  not changed. The settings and the direction are now read once per frame,
  and the state line is only built when something in it changes.
- **Spectating reuses its view of who is on screen.** Following a teammate
  after death, and the S&D bomb on a carrier, asked for every rendered player
  each frame and got a fresh map with a new entry per player. They now get the
  same map back, kept current.
- **Projectile hit tests stop re-reading mesh names.** A rocket or grenade the
  client flies itself ray-tests the scene every frame, and for every mesh it
  lower-cased the name and texture and searched them for a dozen effect words
  (flare, halo, sprite…). Whether a mesh is an effect is now worked out once
  per mesh, and the test function is built once rather than per projectile.
- **Grenades turn along their arc without allocating.** Re-facing an arcing
  grenade built five new vectors and quaternions per grenade per frame; it now
  writes the same rotation into the grenade's own.
- **The bomb finds its carrier's spine once.** Carrying the S&D bomb searched
  the carrier's whole rig by name, lower-casing every bone, every frame. The
  bone is now looked up once per model.
- **A blade swing stops building a mesh every frame.** The slash trail grew by
  a point a frame, and each frame threw away its ribbon and built a new one,
  geometry and buffers included. It now keeps one mesh with room to spare and
  rewrites it in place, growing only past 64 points; it draws the same shape
  and feathering as before.
- **Bomb-site debris rests between explosions.** On S&D maps, every frame
  re-checked every site's debris models for preloading, built a new set from
  the destroyed-sites list and filtered the (usually empty) fragment list into
  a new array. Preloading now happens once per map, the set is rebuilt only
  when the list changes, and flying fragments move without temporary vectors.
- **The view weapon's resting offsets are shared.** Reload, switch, slash and
  holster each returned a fresh "all zero" object every frame while idle; they
  now return one shared, frozen answer.
- **Pickups behind walls rest.** Health, armor, ammo and powerup sculptures
  animated (bob, spin, pulse, ring scroll) and submitted their meshes every
  frame wherever they were on the map. A map pickup now looks up its PVS
  cluster once, and while the camera's cluster cannot see it, it neither draws
  nor animates. Its animation is a function of time, so it comes back exactly
  where it would have been. Collection and respawn effects still play out.
- **Gib bounces trace without temporary objects.** Each airborne hero gib's
  bounce test built five vectors and two option/result objects a frame; it now
  reuses one set.
- **Server projectiles are re-aimed in place.** Every rocket and grenade from
  the server got a new direction vector each frame; the projectile's own is
  now rewritten. The PVS position test also stopped building an array per call.
- **Weapon pickups behind walls are not drawn.** The PVS rest from health and
  armor now covers model pickups (weapons and the rest): out of the camera's
  view the model is hidden, and exactly the parts it drew come back. Its
  enabled state stays the server's.
- **Map sprites stop re-creating their UV buffer.** A sprite set its UVs every
  frame, which made a new GPU buffer each time. It now sends them only when
  its frame or facing changes, into the same buffer.
- **Moving platforms fill one object.** Each platform asked the lift system for
  its position every frame and got a new object; it now passes one to fill.
- **Biome warnings down from 87 to 47.** Wall-jump probes now use exact 22.5°
  and 45° turns instead of 0.924/0.383/0.707, which made the diagonal probes
  up to 0.3% short. Test harnesses that reached into private state through
  `any` now say what they reach for, and an unused `{}` type is gone. The 21
  CSS ordering warnings were checked one by one: none hides a rule that was
  meant to win, so they stay as written.
- **Terms of Service revised (October 22, 2026).** A one-line summary up
  front and plainer, friendlier wording. "Zero personal data" became an honest
  list of what is recorded, why, for how long, and how to ask for removal
  (usernames, keys, stats, demos with chat, and connecting IP addresses). AI
  training on demos and match events stays, and chat is no longer used for it.
  The chat licence covers demos rather than being unlimited. The disclaimer is
  scoped "to the extent the law allows", and the terms now name Higher Standard
  Games, a contact, a minimum age of 13, and that new terms are shown in game.
  "Hash" is now "key", as the game calls it. Because the date changed, every
  player sees the terms again and re-agrees. wash-fps gains the MIT LICENSE
  that section 6 refers to.
- **Account deletion.** Profile has a new "Delete account" screen. It takes a
  ticked "I understand this can't be undone" box and the whole key pasted
  again, and the lobby checks the key too. The account is then named
  `[deleted account]` on the leaderboards and in the demo list, its synced
  settings are erased, its key stops working and its name is free again. Every
  tab logged in to it is closed and the browser starts over as a new player.
  Demo files are not edited, so playback still shows the recorded name.
- **Terms: demos.** Section 3 now says demos are a permanent public record that
  we don't edit or remove and may archive, with no removal request; contact is
  for questions.
- **Terms: contact.** Questions now go to the wash-fps issues, the game's own
  repository, instead of the engine's.
- **Credits: licence.** Credits no longer say "All rights reserved" and now say
  the game is MIT licensed, like the engine, with links to both licences.

### Package loading and client rendering

- Package consumers share concurrent downloads and reuse mounted archives,
  avoiding repeated ZIP parsing and indexing. Explicit archive refreshes still
  work, and late responses after an unload cannot restore stale packages.
- Failed and cancelled map loads release visibility listeners and readiness
  timers. Map changes wait for the prior operation's cleanup and emit one
  completion each, preventing stale completion and duplicate fade timers.
- Firefox WebGL filters the first-person weapon camera's mesh candidates before
  world-mesh readiness and matrix checks. Chromium retains its default; WebGPU
  retains its ordinary evaluation path.

### Combat rendering and resource lifetimes

- Player color materials release their cloned texture wrappers when a body is
  removed. Repeated deaths retained these wrappers and their GPU references;
  source textures and other players' materials remain shared and intact.
- Quake material plugins have distinct shader-cache identities, including
  stage-color and cubemap variants. In Amphi, a distance-fading sprite could
  reuse a soft-particle shader with a larger uniform buffer, causing invalid
  WebGL draws and missing effects.

### Servers

- **Finished match servers now always exit.** When the last player left and
  then reconnected to resume a match that had already ended, the server
  refused the resume — but the reconnect had already cancelled its shutdown,
  and nothing restarted it. Two production servers ran empty for 16 hours this
  way. A connection that has not joined now only delays an empty server's
  shutdown by 15 seconds, and a server counts as having had players only once
  someone joins.
- **Saving the match recording no longer freezes the match.** At the end of a
  match, and mid-match when the last human left, the server compressed the
  whole recording in one blocking call: 300–500 ms of frozen game for everyone
  still in it (about a second for a 26-minute match). The recording is now
  compressed on a background thread in chunks; the longest pause is about
  16 ms, and a server shutting down waits for the save to finish.
- **Bundled servers.** `npm run build:server` now also bundles the bot server
  (`npm run bot:server`; the Vite launch is `bot:server:dev`), and swaps a new
  build in only once it is complete. A bundled match server starts in about
  0.26 s instead of 1.1 s and uses about half the memory (122 MB against
  268 MB). Bots rate under the same identity bundled or not: their behaviour
  fingerprint located the source tree relative to its own file, which in a
  bundle pointed outside the repository.

### Editor

- **New brushes default to caulk**, as in NetRadiant. The default was
  `blx/blx_grid`, a Warsow texture that no longer ships: new geometry had no
  texture in the editor, and a map using it was refused at publish (the
  compiler found no image). `common/caulk` seals and collides but is never
  drawn — texture the faces players see. The playtest starter room uses the
  shipped `cleansurface/pantonecoolgray10c` so it stays visible. The editor's
  compile tests, which failed on every run for the missing texture, pass again.

### Network

- **Each command is sent once over WebSocket.** The client sent every movement
  command three times, a loss cover that only matters for datagrams: over
  WebSocket every message already arrives once and in order, and the server
  threw two copies in three away after decoding them. Upload from the client
  drops from about 440 to about 190 messages a second (about 18.7 to 6.7 KB/s
  of WebSocket payload), which leaves less to queue on a busy or tunnelled
  connection. The datagram transport keeps the copies.
