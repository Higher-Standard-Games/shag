# v0.9.17

**Release Date:** unreleased — living changelog for the 0.9.17 dev cycle

## Summary

In progress. Focus areas this cycle:

1. **Fall damage tuning** — the whole damage band moved up 128u (damage was landing from too low): ramp starts at **256u**, full 100 at **384u**, fatal self-crush at **512u** (`sv_falldamage_min/_full/_fatal` defaults). A server-console `[FallDamage]` diagnostic logs raw vs effective drop + band on every landing for live tuning. *(merged to main)*

2. **Washoi manga UI rollout** — bringing every front-end surface into the dark-navy neon print-slab language of the combat HUD and ESC menu: lobby Social + Chat columns, the ready-room (`MatchLobbyView`), the "GAME STARTING" connecting overlay, and shared `.w-slab`/`.w-stamp`/`.w-btn`/`.w-panel-backdrop` primitives in `WashikiTheme.css`. Spec + remaining-surfaces checklist in `docs/research/THEMEUPDATES-0.9.17.md`. *(on `feature/manga-lobby-ui`)*

3. **Blade drop mesh leak fix** — the 3rd-person weapon mesh is bone-attached (not a scene-graph child) and was never disposed on death, leaking a floating blade at every kill (visible since the blade-scale fix; "blades piling up in duels"). Now tracked as `PlayerModelInstance.attachedWeapon` and disposed with the model on both death paths (gib + ragdoll), so the blade rides the corpse and vanishes with it. *(on `feature/v0.9.17-fixes`)*

4. **Teleporters & jumppads (in progress)** — investigation complete: `trigger_teleport`/`trigger_push` brush volumes + `misc_teleporter_dest`/`target_position` targets, present in our BSPs and fully parsed but never consumed. Implementation plan (shared `TriggerTable`, trigger evaluation inside the shared `MovementProfile` for snap-free prediction, Q3 `AimAtTarget` pad ballistics, server-side telefrag/events) in `docs/research/triggerbrushes-and-targets.md`. Test map: **wdm2** (4 teleporter pairs + 1 vertical mega-jumppad). **T1 done**: shared `TriggerTable.ts` extractor (`extractTriggerVolumes` + `q3AngleToGameYaw`) with 11 tests against the real wdm2 records.

## Changes

### Fall Damage Band Retune [CHANGED] — merged to main

- Default thresholds +128u across the band: `sv_falldamage_min` 128→**256**, `_full` 256→**384**, `_fatal` 384→**512** (map units; runtime-tunable per server). ~5 jump-heights (51u apex) are now damage-free.
- `[FallDamage]` server-console diagnostic on every landing: raw drop, crouch-softened effective drop, resulting band (SAFE/RAMP/CRUSH/FATAL) — units confirmed 1:1 BSP (the Q3→Babylon transform is axis-swap only; no world scale anywhere in the sim path).
- FallDamage regression tests shifted to the new bands (8 tests).

### Washoi Manga UI Rollout [CHANGED] — feature/manga-lobby-ui

Style source of truth: the ESC menu + combat HUD (dark navy + cyan scanlines + inset neon edge-bars + clip-path stamps + gold labels + hard black offset shadows). Full spec, recipes, and audit map: `docs/research/THEMEUPDATES-0.9.17.md`.

- **Lobby Social + Chat columns** (fps): gold stamp section titles, navy slab player rows with glowing status dots and neon badges, live matches as mini fight-tickets (magenta LIVE stamp), navy scan chat panel with magenta author names, gold-on-focus input.
- **Ready-room** (`MatchLobbyView.css`): poster header (magenta-shadow gametype + cyan player-count stamp), map-vote cards as fight-tickets (gold check when voted), team headers as cyan (alpha/udon) / magenta (bravo/soba) stamps matching in-game team tints, player slots with team-colour inset bars, LEAVE (magenta danger) / SHUFFLE (gold) / READY (gold outline → fills gold + pulses when active).
- **Connecting overlay**: "GAME STARTING" print poster — navy scan panel, gold→magenta top edge-bar, gold status stamp, cyan sweep bar, magenta error stamp.
- **Shared primitives** in `WashikiTheme.css`: `.w-panel-backdrop`, `.w-slab`, `.w-ticket`, `.w-stamp`, `.w-btn` — so new surfaces stop re-declaring the recipe.
- Remaining surfaces tracked in the THEMEUPDATES checklist (leaderboard/profile/settings/demos tabs, GamePanel shell, generic engine components, scoreboard).

### Blade Drop Mesh Leak [FIXED] — feature/v0.9.17-fixes

- `PlayerModelInstance.attachedWeapon`: the bone-attached 3rd-person weapon is now disposed with the player model (`disposeInstance`, `RagdollSystem.disposeModel`), covering both gib and ragdoll death paths; cleared on weapon swap. Dropped blades ride the ragdoll and vanish with the corpse (~5s) instead of accumulating over a match.
