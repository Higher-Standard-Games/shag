# v0.9.11

**Release Date:** 2026-03-23

## Summary

Framerate-independent server physics (Quake/Warsow model), 125Hz bot input, directional damage indicators with pain camera shake, **server-authoritative award system with HUD banner and event feed**, bot AI bug fixes, and engine-wide performance optimizations.

## Changes

### Award System & Event Feed [NEW]

- **Server-authoritative awards** — `AwardTracker` in `GametypeController` tracks kill streaks and emits award events (frag, first_blood, on_fire at 5 kills, raging at 10, unstoppable at 15). Awards work during both warmup and active match phases.
- **Award banner** — DOM-based `AwardBanner` widget displays personal awards center-screen (35% from top) with Orbitron font, gold color (`--w-gold`), glow effects, and fade-in/hold/fade-out animations. Queues multiple awards for sequential display.
- **Event feed** — `EventFeed` widget on the left side shows global game events (kills, streaks, first blood) visible to all players. Replaces the old `FPSKillFeed` widget.
- **Gametype API** — `GametypeController.getAwardTracker()` exposes the tracker for custom gametype scripts to emit their own awards.
- **BinaryProtocol support** — added `'award'` as event type code 12 with proper encode/decode (awardType, playerId, playerName, targetName, value).

### Remote Player Model Reliability [FIXED]

- **Late model assignment** — `RemotePlayerRenderer.render()` now retries model creation each frame if a hitbox exists without a model and the model manager is loaded, closing timing gaps during initial load.

### Damage Indicators & Pain Shake [NEW]

- **Directional damage overlay** — Canvas2D fullscreen overlay with red vignette gradient + scattered triangles on screen borders, weighted toward the damage source direction. Unique Washoi visual style with randomly rotated, semi-transparent triangles of varying sizes (12-70px "blood splash" shards).
- **Damage-proportional intensity** — triangle count (28-60), size, opacity, border depth, and flash duration (0.35-1.4s) all scale with damage amount. High hits (≥50 damage) trigger oversized blood splash triangles.
- **Pain camera shake** — `shakeCamera()` now triggers for ALL damage types (hitscan, beam, projectile, melee), not just explosions. Intensity scales with damage (5-60% of max shake).
- **Self-animating** — overlay runs its own `requestAnimationFrame` loop, starts on hit, stops automatically when all flashes expire.

### Framerate-Independent Physics [FIXED]

- **dt mismatch** — server was using `dt / queue.length` (fractional dt) per command while client predicted with full `dt`, causing the server to simulate less physics than the client expected → constant reconciliation snap-backs → "slow/jerky" movement. Now both sides use full `dt` per command.
- **60Hz physics bias** — removed `queue=0` stale-input simulation that ran extra physics for low-fps players. At 60Hz, ~62 empty-queue ticks per second each ran a full simulate, giving 60Hz players ~50% more server-side physics. Physics now only advances when commands arrive (Quake/Warsow model).
- **Bot 125Hz input** — bots now send input at 125Hz via timer-based loop (was 12-33Hz snapshot-gated). AI decisions still happen on snapshot receipt, but the last decision is re-sent at server tick rate. Ensures bots get identical physics to human players.

### Bot AI Bug Fixes [FIXED]

- **Retreat button flags** — `HybridBrain._applyTactical` retreat override now sets `BACK` button and clears `FORWARD`, ensuring server-side physics correctly moves the bot backward (was only setting `direction.z = -1` without button flags)
- **Dodge strafe buttons** — `HybridBrain._applyCombat` dodge now sets `LEFT`/`RIGHT` button flags for server-side air-strafe physics (was only setting `direction.x`)
- **Combat enemy LOS** — combat model now uses `visionResult.visibleEnemies[0]` (LOS-confirmed) instead of `state.players[0]` (nearest, possibly behind walls)
- **Training data buttons** — `DemoTrainingExtractor` now infers `FORWARD`, `BACK`, `LEFT`, `RIGHT`, `JUMP`, and `CROUCH` from velocity direction, vertical velocity, and movementState (was only `SPRINT` + `FIRE`)

### Engine Performance Optimizations [CHANGED]

- **ProjectileManager hot-loop** — pre-allocated `_tmpMoveDir`, `_tmpRay`, and `_defaultFwd` eliminate ~3 heap allocations per projectile per frame
- **Trail ribbon reuse** — trail ribbons created with `updatable: true`, updated in-place once at max capacity (60 points), eliminating GPU buffer churn at steady state
- **Trail trim** — single `splice(0, overshoot)` replaces while-loop of `shift()` calls (O(1) amortized vs O(n) per trim)
- **Impact/effect cleanup** — backwards swap-remove pattern replaces `findIndex` + `splice` loops in both `ProjectileManager` and `HitscanEffects` (O(n) vs O(n²))
- **Wall mark materials** — all wall marks now share a single `StandardMaterial`, fading via `mesh.visibility` instead of per-mark `material.alpha` (20 fewer materials per shotgun blast)
- **Remote beam cleanup** — `stopAllRemoteBeams()` collects IDs before iterating, fixing Map mutation during iteration

### Server Snapshot Optimizations [CHANGED]

- **O(1) client lookup** — `SnapshotBuilder` now builds a `clientByPlayerId` Map once per tick instead of linearly scanning `ctx.clients` per entity (~8x fewer iterations at 125 ticks/sec with 8 players)
- **Single entity pass** — weapon state emission merged into the first `allEntities()` loop, eliminating a second full entity iteration per tick

## Technical Notes

- `AwardTracker.ts`: server-side kill streak tracking with configurable thresholds; resets streak on death; emits `AwardEvent` objects with playerId, awardType, playerName, targetName, value
- `GametypeController.ts`: `onKill()`/`onDeath()` calls moved outside `MatchPhase.Active` guard so awards work during warmup; `drainAwards()` returns and clears pending events
- `BinaryProtocol.ts`: added event type code 12 (`award`) with encode/decode for awardType, playerId, playerName, targetName, value fields
- `AwardBanner.ts`: DOM-based widget using WashikiTheme CSS variables; Orbitron 28px gold text with glow; queues awards for sequential display with fade animations
- `EventFeed.ts`: left-side event list replacing old `FPSKillFeed`; shows kills and streak awards
- `RemotePlayerRenderer.ts`: added per-frame model retry in `render()` to close timing gaps during model loading
- `FPSMovementSubsystem.ts`: `queue=0` path no longer calls `simulate()`; queue>0 path uses full `dt` per command instead of `dt / queue.length`
- `BotClient.ts`: replaced `_minInputIntervalMs` (30-80ms) with 125Hz `setInterval` loop; `_lastBotInput` caches AI decision for re-sending; `_startInputLoop()`/`_stopInputLoop()` manage timer lifecycle
- `DamageOverlay.ts`: new Canvas2D singleton; self-animating via `requestAnimationFrame`; pre-computes all triangle positions at generation time (no per-frame randomization); directional edge weights from attacker→victim angle
- `GameEvents.ts`: incoming damage detection (victim === local player); computes screen-space damage direction from world-space attacker position using camera yaw; triggers both `DamageOverlay.show()` and `FPSController.shakeCamera()`; robust award ID matching with multiple format fallbacks
- `ProjectileManager.ts`: added `_tmpMoveDir`, `_tmpRay`, `_defaultFwd` class fields; `updateTrail()` uses `instance` parameter for in-place ribbon update; `updateImpacts()` uses backwards swap-remove
- `HitscanEffects.ts`: `wallMarks` type changed from `{mesh, material, spawnTime}` to `{mesh, spawnTime}`; added shared `wallMarkMaterial` field; `stopAllRemoteBeams()` collects keys before deletion
- `SnapshotBuilder.ts`: `clientByPlayerId` Map built at top of `buildSnapshot()`; weapon state emission moved from second loop into first entity loop; award events serialized with `player_${id}` format
- `HybridBrain.ts`: retreat/dodge button flags fixed; combat enemy lookup uses vision LOS
- `DemoTrainingExtractor.ts`: button inference expanded from 2 to 8 button types
- `WashikiTheme.css`: weapon rack vertically centered on left side (`top: 50%; transform: translateY(-50%)`)
