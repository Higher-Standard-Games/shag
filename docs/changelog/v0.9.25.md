# v0.9.25

**Release Date:** unreleased — living changelog

## Summary

The v0.9.25 cycle begins after the v0.9.24 console and QA release. Record
player and developer changes here as they land.

## Changes

### SHAGGED server build controls

The editor now connects to the loopback SHAGGED service when opened. **Server
Save** writes the current `.map` and editable sidecar as an immutable revision;
**Compile** saves first, starts a MakeBSP job, and shows its state and log in a
status panel. The local draft and Export controls remain independent. A saved
server revision is kept with each local draft, and a newer server revision
blocks overwriting it. When the service or compiler is unavailable, the
toolbar explains the state and the editor still supports local work. Browser
compile requests now pass the server's CORS preflight. Playtest remains gated
until a compiled BSP is visible to the game and lobby server.

### Duel testing maps

The lobby's duel pool now includes installed `wdm11` and `wdm12` packages for
testing. Map availability remains filtered against the local PK3 directory.

### SHAGGED editor implementation plan

The [SHAGGED research plan](../research/SHAGGED.md) sets out a console-launched
four-view brush editor, `.map` export, a separate MakeBSP compile service, and
playtest handoff. It records feature gates, file layout, input behavior and
open compiler-format checks.

The plan now fixes technical seams for later tools: stable object identity and
ownership, one undoable edit path, pure prefab/recipe expansion, read-only
overlays, and build IDs tied to exact source. It also identifies arbitrary
brush topology and face-ID preservation as a separate later risk.

### SHAGGED first editor slice

`developer 1; editor` opens a four-view editor from the lobby. Drag in an
orthographic pane to make grid-aligned box brushes; select and drag to move a
brush. The toolbar includes grid, undo/redo, local draft save, and `.map`
export. The editor owns rendering while open, and Exit saves the draft and
restores the lobby and game camera controls. `editor status` and `editor close`
provide console access to the handoff.

The brush inspector now edits exact XYZ min/max bounds and a brush shader in
one undoable Apply action. Duplicate offsets a copy by one grid step. Saved
drafts also recover the grid, zoom, tool, selection, and perspective camera.
Selected brush edges have handles in the orthographic panes and can be dragged
to resize without inverting the brush.
The Room Template button creates a sealed six-brush test room with a player
spawn; its exported source parses locally but awaits MakeBSP acceptance.
The perspective pane now selects visible brushes by click; right drag orbits,
middle drag pans, and the wheel zooms. A DOM/NullEngine smoke test covers 3D
picking, inspector Apply and Undo, room creation, and draft reopen.
Brush creation now uses an editable snapped work plane for its hidden axis and
a one-grid initial thickness. Draw, move, and resize previews appear in all
views without changing the saved document until release; the status bar shows
the proposed dimensions. Work planes and the active pane recover with drafts.
Drafts can now be named and reopened from a local draft chooser. Switching
saves the current draft and restores the chosen draft's geometry and view.
Orthographic panes now support middle-drag panning and wheel zoom toward the
cursor, with a shared center saved per draft. Frame (`F`) and Frame All
(`Shift+F`) center the four views on the selection or map. Navigation leaves
document history unchanged, and New/Room Template cancel an active drag.

Compile, compile status, and playtest controls remain disabled until the editor
service and MakeBSP executable are wired. Exported `.map` source is parsed by
the repository's map parser; acceptance by the target MakeBSP binary remains
unverified.

### SHAGGED: compiler acceptance proved, and the console-closing regression fixed

A local MakeBSP/MakeLight install (NetRadiant Custom, with the repository's own
`editor/makebspdata/washoi.json` profile already installed into it) compiled
the Room Template's exported `.map` end to end with the documented Washoi FAST
recipe (`makebsp -leaktest -fast -samplesize 8`, then `makelight -fast`): no
leak, a written `.bsp`, and the result loads cleanly through SHAG's own
`BspLoader` (`npm run cli:bsp` reports the expected FBSP v1 lumps, six faces,
and one model). This closes M1's compiler-acceptance unknown. One real but
non-blocking finding: the BSP's light grid lump has far fewer entries than
`BspLoader` predicts from the map bounds (3 vs. 49) on this fixture, which has
no light entities at all; likely MakeLight's grid compression collapsing
identical all-dark samples rather than an exporter defect, but unconfirmed —
flagged for a follow-up test room with real lights before fully closing the
P0 compiler gate.

Real-browser interaction QA (headless Edge over CDP) also ran for the first
time: console-launched four-view editor opens, a real pointer drag in the XY
pane creates a grid-snapped box brush that appears correctly in all three
orthographic panes and the 3D perspective view, the inspector reflects its
exact bounds and shader, and Exit/reopen round-trips the session. This QA
pass found that opening the editor silently closed the debug console
(`src/main.ts`'s suspend-game callback called `debugConsole.close()`), which
contradicted the documented contract that the console stays usable while
editing. Fixed by removing that call; the console's open/closed state is now
left alone when the editor opens, same as every other case.

### SHAGGED: three M1 toolbar shortcuts that silently didn't do what the table said

Checked the M1 toolbar/shortcuts table in `docs/research/SHAGGED.md` against
the actual key handling and found three gaps:

- `Ctrl/Cmd+Shift+S` (Export .map) was indistinguishable from `Ctrl/Cmd+S`
  (Save Draft) — both ran Save, so there was no keyboard way to export.
- `[` / `]` (grid size) did nothing at all; only the toolbar's grid dropdown
  worked.
- `Escape` did nothing at all; an in-progress brush drag could only be
  cancelled by releasing the pointer outside the browser window
  (`pointercancel`/`lostpointercapture`), and the drafts popover had no
  keyboard close.

All three now match the table: Shift distinguishes Export from Save; `[`/`]`
step the same grid-size list the dropdown offers, staying in sync with it;
and Escape cancels an active drag first, or closes the drafts popover if
nothing is being dragged. Verified in a real browser (headless Edge over
CDP) and with new DOM-shell tests in `EditorSession.test.ts`.

### SHAGGED: the status bar now shows the hovered cursor's Quake coordinate

The M1 status bar was supposed to show cursor Quake coordinates alongside
grid/work-plane/brush info, but it only ever updated from explicit events
(save, export, a drag's preview size) — a plain hover over an orthographic
pane left it untouched. Hovering any pane with no drag or pan in progress
now shows its snapped Quake coordinate (`cursor (x, y, z)`) in the status
bar, using the active work-plane value for the hidden axis; it clears when
the pointer leaves the pane or a drag starts, so it never shows a stale
position once the drag's own size readout takes over.

### SHAGGED: point entities

Mappers can now place point entities, the first M2 feature.

- **Placing:** the Entity tool (`E`) and the toolbar class picker place
  spawns, lights, weapons, ammo, items, flags and teleport targets with one
  click each.
- **Class list:** read from the Washoi NetRadiant definitions
  (`entities.def`), which are themselves derived from the engine's entity
  readers. Brush classes and compiler-only or raw-map-only classes are left
  out. Seen from above, a placed entity's box stands on the work plane.
- **Views and editing:** entities show as class-coloured boxes in all four
  views. They can be selected, dragged with a preview, duplicated, deleted,
  undone and framed.
- **Inspector:** edits the class, the origin, the class's documented keys
  (with their defaults shown), any other key the entity carries, and a new
  key. Keys the editor doesn't know are kept. A value that a `.map` can't hold
  (a double quote or a newline) is refused, with a message.
- **Export:** classname, origin, then keys in name order.
- **Room Template:** now includes a light, so its compiled room is lit.
- **Older drafts:** their test spawn becomes an ordinary spawn entity on
  load.
- **Compiled:** the Room Template with an editor-placed rocket launcher
  compiled with MakeBSP and MakeLight, and the game's BSP loader reads all
  three entities back.

The same pass fixed three editor bugs:

- A brush narrower than the grid couldn't be selected by clicking it.
- Status messages such as a rejected drag were wiped in the same frame they
  appeared.
- Scrolling or panning a view discarded a value half-typed into the
  inspector.

Export order no longer depends on the machine's locale.

### SHAGGED: first server Save/Open and compile jobs

`npm run shagged:server` now starts a separate loopback map service. It saves
numbered `.map` revisions under `server-data/shagged/maps`, accepts an optional
editor sidecar only when it generates the exact submitted source, and returns
a conflict for stale saves. The local API lists and loads saved maps and
reports compiler availability without exposing binary paths.

`npm run shagged:compile -- <mapname>` and the service's compile endpoint use
the same Washoi FAST/DEFAULT/RELEASE recipe and isolated job workspaces.
Jobs run MakeBSP then MakeLight with argument arrays and report `compiled`
only after checking for an FBSP v1 output. Compile status and a short log
tail are available through the API. The browser editor has not connected to
this API yet, and a compiled job does not claim the map is playable.
The two CLIs accept executable, media-root, toolchain-root, map-store and
quality overrides; `--check-config` reports missing setup. Saved maps survive
service restarts; job status is currently in memory.

The backend tests, full suite (3,502 tests), typecheck, production build,
Biome, simulation, physics, server tick, 1,000-tick fuzz, and headless `wdm2`
BSP load passed. The local `--check-config` correctly reports that MakeBSP is
absent from `PATH`, so a real compile through the new job service remains
unverified. The existing physics step-slide warning remains.

## Known Unverified Items

All items from the previous entry are now resolved: the Room Template's
export compiles with MakeBSP/MakeLight and loads through SHAG's BspLoader;
the editor's open/close/draw behavior has been checked in a real browser
(headless Edge over CDP), including three full open/Exit/reopen cycles with
no duplicate roots or leaked canvases; and the light-grid count mismatch on
an all-unlit fixture room is confirmed to be MakeLight's own grid
compression on a room with zero light entities, not a SHAGGED export
defect — adding one light entity by hand narrowed the predicted/actual gap
to the same small residual already seen on real shipped maps. Point entities
are now done (above). Remaining scope: brush entities, face/UV editing,
groups, browser connection to the new compile service, exact BSP delivery,
and the Playtest/Return loop. The backend compile path has passed tests with
an injected tool runner; it has not run the configured local binaries from
this service because they are absent from `PATH` here.
