# v1.0.6

**Release Date:** unreleased — living changelog

## Changes

- **The itch.io build goes out with the deploy.** EU's deploy pushes the public
  itch.io build (`higherstandardgames/washoi:html5`) for each release, once
  every region's lobby runs it: each region's activation now writes
  `release.json` (`{"pair":"<pair id>"}`) beside its game client, and EU builds
  `dist-itch` once and pushes when EU and US both name the pair. Before, the
  build was pushed by hand from a developer machine after a release. The
  staging page is still pushed by hand. The surface needs butler and an API
  key on EU (`/srv/washoi/bin/butler`, `/srv/washoi/env/itch-butler.key`), and
  is skipped without them.
- **Map loads skip a GPU readback per surface.** The texture-array merge
  compared materials by serializing them with their images, so Babylon read
  every PK3 image back from the GPU and encoded it as base64, only for the
  merge to replace it by its id. It now serializes without image buffers;
  surfaces merge as before.
- **Map materials no longer outlive their map.** Leaving a map disposed its
  meshes but not their materials, and texturing replaced each surface's
  stand-in material without disposing it. Both are now disposed once no mesh
  draws with them; images stay with the texture caches as before.
- **Q3 lightmaps encode through a table.** IBSP lightmap pages take their
  transfer curve from a 256-entry table instead of a `pow` per channel, with
  the same bytes.
- **Optional surface merging for games (off by default).** `MapLoader.setSurfaceMerge`
  lets a game replace the loaded map's merge; `mergeBspSurfaceArrays` takes
  `{ alphaTested }` to merge alpha-tested surfaces; and `atlasBspLightmaps`
  packs an IBSP map's lightmap pages into one atlas so surfaces on different
  pages can merge. Washoi uses none of them. See the BSP system guide.
