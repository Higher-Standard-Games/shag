# v0.9.4 - HUD Data Layer

**Release Date:** 2026-02-18

## Summary

Full data pipeline from server to client for HUD display. Health/armor is private to the owning player (sent via `combat_state` event, not in `PlayerState`). Scoreboard shows real names, frags, deaths, and ping. Debug overlay for visual verification.

## Changes

### Protocol

- **`deaths` in PlayerState** — New per-player death counter, delta-encoded in `BinaryProtocol` (flag `0x08`, uint32)
- **`ping` encoding** — Player ping now delta-encoded in `BinaryProtocol` (flag `0x10`, uint16)
- **`combat_state` event** — New event type carrying `health`, `armor`, `dead` status; sent per-tick, private to owning player only
- **Enriched `damage` events** — Now include `attackerId` and `weaponId` for kill feed attribution
- **Enriched `death` events** — Now include `weaponId` for kill feed weapon display
- **`scoreLimit` in match snapshot** — Clients can now display frag limit in HUD

### Server

- **Real player names** — `ClientInfo.playerName` captured from join message, used in `PlayerState.name` instead of "Player N"
- **Ping tracking** — Real connection latency written to `PlayerState.ping`
- **Deaths tracking** — `MatchState.addDeath()` called by `GametypeController` on each kill; wired to `PlayerState.deaths`
- **Combat state emission** — `GameServer.toGameState()` emits `combat_state` per player from `HealthComponent`
- **Damage event forwarding** — `CombatSystem.processedDamage` buffer captures final damage values (after multipliers) for network forwarding
- **Death event forwarding** — Kill events forwarded as `death` events with weaponId attribution

### Client

- **HUDState aggregator** — New singleton class (`HUDState.ts`) collects `combat_state`, `damage`, `death`, and scoreboard data from `GameState` events
- **Debug overlay** — Auto-enabled on connect; green-on-black box (top-right) showing HP, armor, scoreboard, kill feed, and damage numbers
- **`scoreLimit` in MatchStateManager** — Client now tracks and exposes frag limit
- **Event processing wiring** — `FPSGameManager` routes `combat_state`, `damage`, and `death` events to HUDState

### Bug Fixes

- **Missing `deaths` field** — Added to `BinaryTestCommand.ts` and `BinaryProtocol.ts` decoder PlayerState literals
