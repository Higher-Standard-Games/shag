# v1.0.0-beta.7

**Release Date:** unreleased — living changelog

## Changes

- Voltaic plays one attack cue and sustained hum per shooter instead of restarting its firing sample on every beam tick. Quad uses the dedicated hum variant. Remote sources follow their shooter; release, reload, weapon changes, death, disconnect, demo pause/seek and map teardown stop the loop. All four sound assets are preloaded.
- Loops started while SFX is disabled become audible when SFX is enabled. Muting controls the sound's gain without permanently zeroing its playback instance.
- Voltaic hums overlap their sample edges to smooth the repeated dip and discontinuity at the loop seam. The attack cue and playback gain are unchanged; prepared loops are cached separately from the original one-shot buffers.

- Standardized Machinegun, Riotgun, Plasma and Voltaic magazine reloads to 1.5 seconds (188 ticks at 125 Hz). Increased the dedicated reload cue's gain to match the shipped weapon-pickup cue's level; the existing local, spatial, spectator and demo handling is preserved.

- `BotClient` permits one connection attempt per instance. Failed attempts, disconnect and disposal require a fresh client; reuse is rejected before opening another socket. Existing fresh-client lobby retries and shared map/navigation caches are preserved. Lifecycle comments and the bot manual state the contract explicitly.

- Unexpected bot WebSocket closes and errors stop the 125 Hz input timer, preventing disconnected bots from retaining a running interval after the server removes them. Explicit disconnect behavior is preserved; corrected adjacent lifecycle comments.

- Bot BSP loading treats the pk3 index as authoritative. Missing maps and rejected published builds leave vision unavailable instead of falling through to loose BSPs or selecting the first BSP in a package. Successful indexed loading and error diagnostics are preserved.

- Team spawn classname membership excludes inherited object properties, preventing unknown BSP entities such as `constructor` from becoming player positions, team pools or spawn facings. The alpha/beta team mappings and valid spawn behavior are unchanged; shared spawn comments describe current technical behavior.

- Bot map knowledge uses the gameplay spawn extractor, retaining team-tagged spawns and correctly parsing whitespace-separated origins. Nonfinite and incomplete positions are skipped; the player-origin height offset and three-position fallback are preserved. Removed the duplicate classname list, coordinate parser and inaccurate loader header.

- Pickup origins accept surrounding and repeated whitespace, including tabs, without shifting coordinates or dropping valid items. Empty origins and vectors without exactly three finite components are skipped before pickup IDs are assigned.

- Pickup extraction rejects unregistered BSP classnames that match inherited object properties, preventing malformed pickups and unintended shifts in subsequent pickup IDs. Registered classname mappings and coordinate conversion are unchanged; pickup comments describe the implemented shared table without historical comparisons.

- Powerup respawn lookup validates supported kinds before reading the timer table, so unknown names such as `constructor` use the 120-second fallback instead of producing invalid server/bot deadlines. Shipped pickup timings are unchanged.

- `set`, `toggle` and `reset` report missing arguments and unknown cvars as checked failures, preserving their display messages and valid operations.
- Corrected the armor pickup manual and technical comments: green armor advances to the next 25-point boundary (58 → 75), and yellow advances by two boundaries. Removed external-game comparisons and design-document references from the pickup calculation comments; gameplay calculations are unchanged.

- The `loadout` console command reports invalid weapons and disconnected attempts as failures to checked command execution, while keeping its existing display messages.
- Corrected the console guide: `map` works without developer mode.
- Loadout comments describe the implemented tables, validation and timing without external-game history or design commentary.
- The player manual documents chosen kits in Amphi and FFA as well as Search & Destroy, including change timing, spawn armor and map-weapon exclusions.
- `giveweapon` rejects invalid ammunition amounts before changing inventory, preventing negative grants and partially parsed input.
- `giveweapon` help and the command reference stop advertising unsupported `all` grants. Unavailable controller/inventory and `all` attempts report checked failures.
- `giveweapon` requires developer mode, keeping local inventory grants unavailable in production browser builds.
- Corrected the inventory manual's API names to `dropWeapon`, `equipWeapon` and `getAmmoCount`, with their implemented return values and view-model responsibility.
- Physics-constant comments describe the implemented 44-unit crouched height, 64-unit default bounds-helper height and coordinate conventions, without historical comparisons.
- `giveweapon` resolves registered weapons and ammo types, rejects unknown targets, and grants usable ammunition with matching display totals. Grants respect weapon capacities, preserve loaded magazines and report the actual ammo added.
- Client inventory ammo keys no longer inherit object properties, so names such as `constructor` cannot return nonnumeric ammo counts.
- `InventoryManager.giveAmmo` ignores invalid amounts and never subtracts ammunition when an existing count already exceeds its grant cap.
- Inventory comments describe current ammo-key ownership, authoritative clip copying and selection handling without historical implementation notes.
- `spectator` validates its optional `0`/`1` argument before registering or switching cameras, and reports failed camera switches through checked command execution.
- `camera mode` rejects inherited object-property names as unknown modes. Unavailable cameras and failed controller selections return checked failures with accurate diagnostics.
- `camera fov` distinguishes a query from invalid input, accepts complete finite numeric values only, and reports range and update failures without changing the setting.
- The camera manual distinguishes the local `spectator` camera-toggle command from the watched-player controller used by live chase views and demos.
- `camera mode` requires developer mode; FOV, camera information and the FPS `spectator` freefly toggle remain available normally.
- Release console access now separates player settings from developer tooling. Scene/map/shader inspection, test harnesses, environmental controls and weapon-model tuning require `developer 1`; practice launching, spectator freefly, demos, support diagnostics and player preferences remain available.
- Developer cvar metadata is enforced through setters, toggles, resets, console aliases and config imports. Production browser builds ignore saved raw renderer/movement overrides; shipped video presets, input, audio and accessibility settings stay writable. Client map cleanup calls scene operations directly rather than executing a gated public console command.
- Renderer variable updates apply directly in headless tools when no browser frame scheduler exists; browser updates retain frame batching.
