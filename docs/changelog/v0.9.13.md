# v0.9.13

**Release Date:** 2026-05-19

## Summary

Three release workstreams:

1. **Curated FPS settings redesign** - shared settings surface used in both the lobby and in-game overlay, a new physical keyboard-and-mouse binding UI, curated player-facing graphics/audio/interface settings, and removal of non-user-facing authored-feel toggles from the public settings screen.
2. **BSP mesh builder maintenance** - split the monolithic `BspMeshBuilder.ts` into focused modules under `src/engine/loader/bsp/mesh/` while preserving public exports.
3. **Engine QA pass** - Pickup system refactored into engine-generic base + FPS subclass so future SHAG game submodules can ship pickups; lifecycle/leak fixes across `GameTimer`, `EngineScene`, `InputSystem`, `WeaponViewManager`, and `CameraSystem`; render-loop singleton caching; bulk type/lint cleanup; documentation accuracy fixes; investigation document with a 56-item improvement matrix that drives follow-up branches.

## Changes

### FPS Settings Experience [CHANGED]

- **Shared FPS-owned settings view** - introduced a single `FPSSettingsView` used by both the lobby `Settings` tab and the in-game `FPSSettingsOverlay`, replacing the earlier duplicated placeholder builders.
- **Curated top-level tabs** - settings are now organized into `Graphics`, `Audio`, `Controls`, and `Interface`, with only live, player-facing options exposed.
- **Controls redesign** - the old spreadsheet-style action rows were replaced with a physical keyboard-and-mouse settings view:
  - full virtual keyboard with clickable physical slots
  - CSS-built mouse diagram with left/right/middle/wheel hotspots
  - slot-first binding model where one physical slot shows one action
  - duplicate bindings remain valid and visible
  - hierarchical action assignment menu for `Movement`, `Weapons`, `Combat`, and `Actions`
  - visible but disabled `Controller` subtab placeholder
- **Curated graphics/audio/interface options** - graphics now expose fullscreen, bloom intensity, and anisotropy; audio uses the real music/effects cvars; interface keeps practical crosshair, HUD, and network readability options.
- **Crosshair controls cleanup** - crosshair color and hit color now use compact dropdown-style selectors with preview dots instead of tall swatch stacks.
- **NetGraph control cleanup** - `NetGraph` now uses a dropdown-style mode selector instead of a segmented three-button layout.
- **Reset protection** - `Reset Tab` and `Reset All` now show Washoi-style confirmation dialogs before restoring defaults.

### Lobby Integration [CHANGED]

- **Lobby settings tab reuse** - `LobbyPanel` now mounts the FPS shared settings view directly and refreshes it when the user switches to the `Settings` tab.
- **Placeholder removal** - the old lobby-only mock settings rows and keybinding placeholders were removed in favor of the shared implementation.

### Defaults And Exposure [CHANGED]

- **Weapon bind defaults aligned to current inventory** - only blade, primary weapon, and secondary weapon ship with `1`, `2`, and `3` bound by default. Higher weapon slots remain available in the assignment menu but are no longer pre-bound.
- **Weapon naming cleanup** - the controls UI now uses `Blade`, `Primary Weapon`, and `Secondary Weapon` instead of generic numbered labels for the currently supported inventory.
- **Removed non-exposed interface options** - `Weapon Hand` and `Weapon FOV` were removed from the public settings UI because those values are intentionally not player-adjustable in the current animation/ADS setup.
- **Authored-feel settings remain hidden** - bobbing, landing, idle, speed-FOV, and similar authored view-feel toggles are intentionally not exposed in the user settings surface.

## Technical Notes

- `src/games/fps/client/settings/FPSSettingsView.ts`: owns the shared settings content, cvar/input adapters, refresh/reset registry, physical slot projection for bindings, and reset confirmation flow.
- `src/games/fps/client/settings/FPSSettingsView.css`: contains the new controls-specific layout/styling for tabs, keyboard, mouse hotspots, menus, select controls, and confirmation copy.
- `src/games/fps/client/hud/widgets/SettingsOverlay.ts`: now acts as a thin host around `FPSSettingsView` rather than defining its own settings UI.
- `src/engine/ui/panels/LobbyPanel.ts`: now mounts the FPS settings view into the lobby `Settings` tab and destroys it with the panel lifecycle.
- `src/games/fps/client/Crosshair.ts`: crosshair settings exposed in the Interface tab are live because the renderer reads `cg_crosshair*` cvars during redraw.

### BSP Mesh Builder Maintenance [CHANGED]

- **BSP mesh builder split** - moved low-level BSP mesh helper code out of the monolithic `BspMeshBuilder.ts` into focused modules under `src/engine/loader/bsp/mesh/` while preserving the existing public exports.
- **Extracted geometry helpers** - coordinate conversion, vertex accessors, polygon/mesh face generation, Bezier patch tessellation, PVS face visibility, fallback texture creation, and brush model building now live in dedicated files.
- **Build cleanup pass** - resolved stale TypeScript errors in bot support code, renderer-adjacent tests, private-scene access sites, wind state, model/sprite initialization, and legacy diagnostic tools. `BinaryProtocol.ts` and `GameEvents.ts` remain intentionally deferred for a separate networking/client-event review.
- **Validation** - targeted BSP/rendering-adjacent tests pass after the split, and live startup was verified manually.

### Engine QA Pass — Pickup System [CHANGED]

- **Engine-generic Pickup base class** - new `src/engine/world/Pickup.ts` exposes in-world collectible primitives (model loading, optional Havok physics toss with settle detection, BSP-aware drop-to-ground with raycast + collision-manager fallback, glow-light pulse, respawn timer, server-driven deactivation entrypoint). Game submodules subclass it via overridable hooks: `onConstructed`, `onProximity`, `onAfterDeactivated`, `getPickupSoundKey`, `getPlayerPosition`.
- **FPS-specific `FPSPickup` subclass** - the former engine `Pickup` class is split: FPS-only concepts (weapon/ammo/health/armor taxonomy, weapon-barrel sub-model attachment, inventory-aware "PRESS [F] TO PICKUP/SWAP" prompt, static server-deactivation registry with weapon-id prefix matching) now live in `FPSPickup` inside the fps submodule.
- **InventoryManager and PickupPrompt moved into fps** - Q3-style ammo taxonomy and the pickup HUD prompt singleton were engine-positioned but FPS-specific; both moved to `src/games/fps/world/`. The empty `src/engine/game/` directory was removed.
- **Static-deactivation regression coverage** - new `src/engine/__tests__/Pickup.test.ts` (16 tests) locks the deactivation contract (`deactivateById` O(1) lookup + position fallback, `deactivateByPosition` with weapon-id prefix matching variants, XZ-only distance with Y ignored, closest-of-multiple selection, pendingDeactivations queue + 10s pruning, `triggerUseAction`). Documented one-directional asymmetry in weapon-id matching (server contract is "always send bare").

### Engine QA Pass — Lifecycle And Leak Fixes [FIXED]

- **GameTimer EventBus listener leak** - `EventBus.on("game:paused")` and `("game:resumed")` were registered in the `GameTimer` constructor without capturing the unsubscribe handles, so `resetInstance()` left listeners firing on stale instances. Captures the unsubscribers now and tears them down via a new `dispose()` invoked from `resetInstance()`.
- **EngineScene `map:loaded` listener leak** - the second `EventBus.on("map:loaded")` registered in `start()` (for the `onMapLoaded` game hook) was not stored, so `dispose()` only cleaned the one from `createScene()`. Stored in `unsubscribeStartMapLoaded` and torn down in `dispose()`.
- **InputSystem render-observer leak** - the two `onBeforeRenderObservable.add(...)` callbacks in `InputSystem.init` were not stored. Captured in `beforeRenderObserver` / `afterRenderObserver` and detached in `dispose()` so re-init on a fresh scene doesn't leave callbacks attached to the previous one.
- **WeaponViewManager render-observer leak** - re-`init` on a fresh scene used to leave the previous scene's update observer attached. Captured in `updateObserver` and detached on scene swap.
- **CameraSystem.registerController leak** - registering a fresh controller for an already-bound type (`"isometric"` etc.) used to silently orphan the previous one. Now disposes the previous controller (detaching it from the active slot first if needed) before overwriting.
- **EngineScene.dispose() expanded** - now disposes `PostProcessingManager`, `SkyLightSystem`, and `StreetLampSystem` (each in a try/catch so one failing teardown doesn't block the others). Clears the cached singleton refs added for the render loop, and deletes the `window.*` debug surface (`loadMap`, `setZoom`, `setCameraMode`, `setCameraHeight`, `getCameraMode`, `getCameraHeight`, `camera`, `fx`, `weather`) so stale closures don't keep disposed scene resources alive.
- **EngineScene.start() idempotency** - guarded by a `started` flag with explicit warn-on-reentry. The flag is cleared by `dispose()` so a clean cycle can re-start.

### Engine QA Pass — Performance [CHANGED]

- **Render-loop singleton caching** - `EngineScene` render tick used to call `getInstance()` on `SkyLightSystem`, `StreetLampSystem` (twice), `BuildableSystem`, and `CameraSystem` every frame. References are now cached lazily on the first tick and cleared in `dispose()`.

### Engine QA Pass — Type And Lint Cleanup [FIXED]

- **`TransformShape` IComponent contract** - the local shape interfaces in `BinaryProtocol.ts` declared `serialize/deserialize/clone` as optional, but `entity.addComponent` requires the `IComponent` contract where they're mandatory. Tightened the shapes plus the `_noopSerialize` / `_noopDeserialize` signatures (`BinaryEncoder`/`BinaryDecoder` args, `void` return) so constructed components satisfy `IComponent` at the call site. Pure type-level fix — the noops are attached but never invoked.
- **`GameEvents.ts` TS errors** - dropped the unused `localEntityId` parameter from `handleDeathEvent` and added the missing `wallJumping: false` field to the projectile `EntitySnapshot` literal.
- **Console-command lazy-import typing** - 20 lazy-import `let X;` sites across the console-command directory and `MapRenderer` were implicitly `any`. Added `import type { ... }` lines (erased at compile time, preserves the lazy-load semantics that support headless mode) and explicit type annotations. Resolves the bulk of the `noImplicitAnyLet` biome warnings on non-jewel files.
- **`forEach` callback returns** - rewrote three iterable callbacks that returned assignment expressions (in `WeaponViewManager` muzzle-flash setters and `UITheme` listener fan-out) as block statements / `for..of` loops, satisfying `useIterableCallbackReturn`.
- **`BuildableSystem.getInstance(id)` overload-signatures rule** - the instance lookup shares a name with the static singleton accessor by intent (different signatures, different `this`). Renaming would break downstream submodule consumers, so the false positive is suppressed with an explanatory `biome-ignore` instead.
