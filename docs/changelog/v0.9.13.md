# v0.9.13

**Release Date:** 2026-04-21

## Summary

Curated FPS settings redesign with a shared settings surface used in both the lobby and in-game overlay, a new physical keyboard-and-mouse binding UI, curated player-facing graphics/audio/interface settings, and removal of non-user-facing authored-feel toggles from the public settings screen.

## Changes

### FPS Settings Experience [CHANGED]

- **Shared FPS-owned settings view** - introduced a single `FPSSettingsView` used by both the lobby `Settings` tab and the in-game `FPSSettingsOverlay`, replacing the earlier duplicated placeholder builders.
- **Curated top-level tabs** - settings are now organized into `Graphics`, `Audio`, `Controls`, and `Interface`, with only live, player-facing options exposed.
- **Controls redesign** - the old spreadsheet-style action rows were replaced with a physical keyboard-and-mouse settings view:
  - full virtual keyboard with clickable physical slots
  - CSS-built mouse diagram with left/right/middle/wheel hotspots
  - slot-first binding model where one physical slot shows one action
  - duplicate bindings remain valid and visible
  - hierarchical action assignment menu for `Movement`, `Weapons`, `Combat`, and `Actions`
  - visible but disabled `Controller` subtab placeholder
- **Curated graphics/audio/interface options** - graphics now expose fullscreen, bloom intensity, and anisotropy; audio uses the real music/effects cvars; interface keeps practical crosshair, HUD, and network readability options.
- **Crosshair controls cleanup** - crosshair color and hit color now use compact dropdown-style selectors with preview dots instead of tall swatch stacks.
- **NetGraph control cleanup** - `NetGraph` now uses a dropdown-style mode selector instead of a segmented three-button layout.
- **Reset protection** - `Reset Tab` and `Reset All` now show Washoi-style confirmation dialogs before restoring defaults.

### Lobby Integration [CHANGED]

- **Lobby settings tab reuse** - `LobbyPanel` now mounts the FPS shared settings view directly and refreshes it when the user switches to the `Settings` tab.
- **Placeholder removal** - the old lobby-only mock settings rows and keybinding placeholders were removed in favor of the shared implementation.

### Defaults And Exposure [CHANGED]

- **Weapon bind defaults aligned to current inventory** - only blade, primary weapon, and secondary weapon ship with `1`, `2`, and `3` bound by default. Higher weapon slots remain available in the assignment menu but are no longer pre-bound.
- **Weapon naming cleanup** - the controls UI now uses `Blade`, `Primary Weapon`, and `Secondary Weapon` instead of generic numbered labels for the currently supported inventory.
- **Removed non-exposed interface options** - `Weapon Hand` and `Weapon FOV` were removed from the public settings UI because those values are intentionally not player-adjustable in the current animation/ADS setup.
- **Authored-feel settings remain hidden** - bobbing, landing, idle, speed-FOV, and similar authored view-feel toggles are intentionally not exposed in the user settings surface.

## Technical Notes

- `src/games/fps/client/settings/FPSSettingsView.ts`: owns the shared settings content, cvar/input adapters, refresh/reset registry, physical slot projection for bindings, and reset confirmation flow.
- `src/games/fps/client/settings/FPSSettingsView.css`: contains the new controls-specific layout/styling for tabs, keyboard, mouse hotspots, menus, select controls, and confirmation copy.
- `src/games/fps/client/hud/widgets/SettingsOverlay.ts`: now acts as a thin host around `FPSSettingsView` rather than defining its own settings UI.
- `src/engine/ui/panels/LobbyPanel.ts`: now mounts the FPS settings view into the lobby `Settings` tab and destroys it with the panel lifecycle.
- `src/games/fps/client/Crosshair.ts`: crosshair settings exposed in the Interface tab are live because the renderer reads `cg_crosshair*` cvars during redraw.

### BSP Mesh Builder Maintenance [CHANGED]

- **BSP mesh builder split** - moved low-level BSP mesh helper code out of the monolithic `BspMeshBuilder.ts` into focused modules under `src/engine/loader/bsp/mesh/` while preserving the existing public exports.
- **Extracted geometry helpers** - coordinate conversion, vertex accessors, polygon/mesh face generation, Bezier patch tessellation, PVS face visibility, fallback texture creation, and brush model building now live in dedicated files.
- **Build cleanup pass** - resolved stale TypeScript errors in bot support code, renderer-adjacent tests, private-scene access sites, wind state, model/sprite initialization, and legacy diagnostic tools. `BinaryProtocol.ts` and `GameEvents.ts` remain intentionally deferred for a separate networking/client-event review.
- **Validation** - targeted BSP/rendering-adjacent tests pass after the split, and live startup was verified manually.
