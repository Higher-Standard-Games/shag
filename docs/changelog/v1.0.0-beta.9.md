# v1.0.0-beta.9

**Release Date:** unreleased — living changelog

## Changes

- Player model tuning: select Police as the test default, reuse the shared animation clips with load-time retargeting, normalize held-weapon attachment frames, and use the player manager for `animtest`. The compressed body uses a locally served Draco decoder.
- Gameplay settings pair per-side Police/Male, Female/Female and Robot/Bobot model and voice choices, with lightweight rendered previews. Changes apply to existing players, including demo views and local water reflections. Death rendering preserves rig export units through a dedicated bone rotation frame.

- Robot uses the shared animation set, with a rendered settings preview. Thin outlines remain the default (enabled, size 25), with coverage for Gameplay reset.

- Smooth split normals for player outlines while retaining authored body lighting, shared geometry and snapshot replay. Normalize the new bodies to the standing player height with feet on the ground, preserve held-weapon size, and prevent ragdolls growing when physics takes over.

- Keep cached outline templates outside player source hierarchies, preventing subsequent spawns from inheriting an extra mesh that covers the textured body with the outline colour.

- Include outline shader readiness in snapshot draw tracking so cold compilations cannot leave new player outlines missing during replay.

- Add Cartel with male sounds and RiotKitty with female sounds; label the existing female model Female Police. Model menus show model names alone.
- Redesign Who's who as side-by-side team cards with live model previews and colour controls below. One lazy render surface supplies both previews and pauses when hidden.
- Package the shared animation clips separately in `washoi_player_animations.pk3`, preserving the owner-maintained body archive when rebuilding clips.

- Complete RiotKitty's fallback preview, refresh its package discovery, reuse preview bodies across model changes, and allow failed preview loads to retry.

- Use each model's natural full-body Running clip when running without aiming or recent fire. Weapon-ready poses bend the upper spine with view pitch, carrying the attached hand weapon and muzzle while keeping the lower body upright.
- Add untinted Off to Brighter players; retain Tint, Some and Lots. Off preserves authored body colours and the coloured outline. Player style uniforms refresh during WebGPU snapshot replay.
- Clear the local Voltaic beam during frozen round phases, disabled controls, weapon switches and non-beam/missing weapon states, including cached viewmodel retirement.

- Increase the five calibrated player bodies by 10% for readability around their fixed hull, keeping feet grounded and held-weapon size stable.

- Keep hips and legs on their movement animation during third-person blade swings, including jumps. Restore upper-body locomotion without restarting the stride; preserve full-body one-shot and demo clock behaviour.

- Fix water floating in mid-air under WebGPU snapshots: a liquid surface PVS hid before a recording now gets the current camera in replayed frames, instead of drawing where the recording frame saw it.

- Tune running separately for legs and upper body: `cl_player_run_legs` (0.75) and `cl_player_run_upper` (0.5) set each half as a share of the speed-matched rate.
- Walking or running backwards plays the new backwards run clip instead of the forward run reversed. Shared animation clips move to `models/players/animations/` in `washoi_player_animations.pk3`.
- Rename the player asset settings after what they hold: `config/player-animations.json` lists the shared clips and their archive, `config/player-model.json` the default body and its archive. The crowd benchmark measures the Police body (recipe `player-crowd-v2`); the retired vanguard body is no longer needed, and `tools:player-model`, which rebuilt the body archive from it, is removed. Headless `anim bones` reads the Draco-compressed body, and `anim inspect` names each clip's joints.

- Play a death animation once before the ragdoll on some deaths: a kill from behind plays `death_from_back`, a headshot from the front or side `death_headshot`, and a riotgun blast or an explosion that does not gib `death_flying_back`. The body turns to the shot and flies the same arc as before; the ragdoll takes over from the animated pose the moment it touches a surface or the clip ends. Death events from hitscan and melee kills now name the killing weapon and where the blow landed (event code 26), which a riotgun kill needs: it arrived as `bullet`, like the machinegun. Older demos keep code 11 and play their deaths from behind and their explosions with the new clips, and every other death as a plain ragdoll.
