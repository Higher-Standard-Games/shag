# v1.0.0-beta.5

**Release Date:** November 4, 2026

## Changes

### Native client lobby

The native client can show the game's lobby in its webview. Inside that
webview, and at `/client` in a browser, the page boots only the lobby rather
than the whole game, and talks to the native client through a small bridge:
match connections go to the native client, and the player's settings and
account key are mirrored to it. When a match fails to connect there, **Back to
lobby** returns to the lobby on the same page instead of reloading it. Every
other page boots the full game as before.

In the native client, the Demos page hands recordings to the native client's
own player and returns when playback ends; file saves go through the native
client, and its lobby shows the native client's update notice. Pasting a room link
anywhere outside a text field joins that room.

The native match menu can open the same settings screen as a browser match.
Back or Escape returns to the native match menu, and settings flow to the
native client's files and live cvars through the lobby's storage mirror.

### Touch input groundwork

The engine now tracks whether the player is using touch or keyboard and mouse
(`InputDevice`), starting from the primary pointer and following the last
input used, and announces each switch as `input:device_changed`; `in_touch`
forces either for testing. A laptop with a touchscreen no longer counts as a
touch device: it used to get the phone layout for menus and "Tap to start" on
the boot screen, and now gets the desktop ones. Phones and tablets are
unchanged.

Being in play no longer means pointer lock alone, which mobile browsers do not
offer. Play is its own state (`PlayCapture`): the pointer lock on desktop, or
touch play on a touch screen, which a touch on the game starts. The crosshair,
the match menu, firing, chat and pickup prompts follow it, and Resume and
joining a match enter whichever the device uses. Desktop play is unchanged.

Two more pieces for touch controls, with nothing on screen yet: a move stick
can drive movement at any angle (`FPSController.setMoveAxis`), running when
it points straight ahead, and on-screen buttons can hold any action through
`InputSystem.setVirtualAction`, independent of the player's key bindings.

### Touch controls

On a phone or tablet, tapping the game now brings up on-screen controls: a
floating move stick on the left, the right side to look (fast drags turn
further, and a thumb held at either edge keeps turning), and FIRE, AIM, a
fire-and-aim spot between them, JUMP, CROUCH, RELOAD, previous and next
weapon, the blade, the match menu, the scoreboard and chat. In warmup a READY
button replaces F4, and the ready bar says so. `in_touchsens` and
`in_touchaccel` set the look's speed and acceleration. While they are up, the
HUD's bottom row makes room for them and the key-based hints are hidden.

On a touch screen, the boot screen's start tap and the match menu's Resume
also take the game fullscreen and lock it to landscape where the browser
allows it. An iPhone allows neither for a web page, so in portrait the
controls ask the player to turn the device.

Touch players can pick up and swap weapons: a USE button pops up under the
pick-up message, which then reads "tap USE". Touch look has a slight aim
assist (`in_touchassist`): while the thumb turns, turning slows over a visible
opponent and bends toward one by at most a quarter of the turn. A still thumb
gets nothing, and mouse look never passes through it.

While a touch player holds FIRE, turning the phone turns the view too (gyro,
`in_gyro`, `in_gyrosens`), as big mobile shooters do. Aim assist now helps only
real touches, not script-made events or the gyro. The scoreboard shows a small
keyboard or a gold controller before each name, from a claim every command
carries (`InputButtons.ASSISTED_AIM`, a spare bit; no packet or demo layout
changes), and the server's telemetry counts that claim per player for
anti-cheat review.
