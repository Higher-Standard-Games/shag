# v1.0.0-alpha.6

**Release Date:** unreleased — living changelog

## Changes

- Rendering: experimental WebGPU non-compatibility mode skips water occlusion
  queries that could invalidate a frame by replaying into a pass without a query
  set. Water stays conservatively drawable; WebGL and ordinary WebGPU keep their
  existing query policy. Added a reproducible bundle-attribution driver with
  engine-counter reconciliation and source/dependency fingerprints.

- Rendering: PVS-hidden static world meshes skip Babylon's primary-camera
  readiness and transform evaluation. The filter shares ownership with weapon
  candidates, preserves source order and retains conservative camera/LOD/action
  fallbacks. Ten image comparisons per backend match on WebGL2 and WebGPU.

- Rendering: on WebGPU, soft halos and water read the main pass's depth instead
  of drawing the scene again into two depth passes of their own, as WebGL2
  already did. On washoi_dm5 playback the median frame drew 133–180 calls
  instead of 339 (p95 251–285 instead of 528). An earlier attempt was shelved
  after WebGPU rejected frames for a few frames after each map load; the
  convert draw now reads the main depth in a pass of its own, and three map
  loads produced no WebGPU errors.

- Development: added a reproducible matrix-free Voltaic draw experiment for
  WebGL2 and WebGPU, with matched depth, pool-lifecycle and buffer-layout checks.
  The experiment removes static matrix buffers but exposes inaccurate Babylon
  forced-draw statistics; gameplay keeps the validated matrix-backed renderer.

- Rendering: fixed-scale-only shader entries retain frozen materials and avoid
  repeating unchanged UV assignments. Shared textures still restore their
  authored transforms when another writer changes them; animated stages keep
  their existing path. Standard/PBR comparisons match on WebGL2 and WebGPU.

- Rendering: Voltaic batches upload changed slot intervals instead of full
  custom attribute arrays, and rebuild full-capacity retained buffers after
  context restoration. A one-active-slot GPU fixture submitted 96.875% fewer
  bytes with identical effect images on WebGL2 and WebGPU; this is a payload
  reduction, not a whole-game FPS claim. Animated frame textures also avoid
  redundant target assignments. Numeric stage evaluation is reusable without
  Babylon objects, with existing clocks and authored ordering retained.
  Isolated GPU fixtures validate a narrow scroll/sine material adapter without
  changing normal gameplay material selection.

- Development: feature work passes through `staging` in both repositories before
  promotion to the automatically deployed `main` branch. Engine CI also runs on
  pushes to `staging`.
- Research: documented a possible future Babylon Lite renderer, its feature and
  file boundaries, and small candidates for removing Babylon dependencies, with
  a reproducible source-import tracer. The existing renderers are unchanged.
  A second source review expands the groundwork catalog with 15 extraction
  plans, data and lifecycle contracts, and validation criteria before prototyping.
  Published Lite/compat package contents are also audited against SHAG imports
  and selected call sites, with integration pseudocode, file-change milestones
  and explicit unresolved material, actor and loading-lifecycle decisions.
  A native redesign study identifies measurable opportunities in pass lists,
  instance/effect uploads, selective baked animation and time-driven map shaders,
  including API pitfalls and parity/memory gates rather than assumed speedups.
  The follow-up compares those ideas with installed Babylon 9.31.2 and documents
  current WebGL2/WebGPU routes, including shader-driven map animation and partial
  effect uploads, so portable improvements need not wait for a Lite backend.
  A staged groundwork plan connects those current-renderer experiments to
  reusable shader/effect contracts and fixtures, with confirmed material entry
  points and separate correctness, behavior-change and performance decisions.
  Its feature progress matrix starts with baseline capture and bounded effect
  uploads, then shader evaluation and a narrow GPU-animation experiment.
