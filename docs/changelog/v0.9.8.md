# v0.9.8

**Release Date:** TBD

## Summary

HUD architecture refactoring and major BSP lighting overhaul. Split monolithic `FPSHud.ts` (2,582 lines) into 19 focused widgets. Re-enabled lightmaps with correct Babylon.js approach, restoring Q3-style baked lighting with dynamic light support.

## Changes

### HUD Widget Extraction [REFACTOR]

- **Widget module system** — Extracted 19 inline widget classes from `FPSHud.ts` into individual files under `client/hud/widgets/`, reducing `FPSHud.ts` from 2,582 to 396 lines (−85%)
- **Shared interface** — `HudWidget.ts` extracted as standalone interface file to break circular dependencies between `FPSHud` and widget implementations
- **Clean file naming** — Dropped redundant `FPS` prefix from widget filenames (e.g., `FPSValueBar.ts` → `ValueBar.ts`) since they're already scoped under `fps/client/hud/widgets/`
- **Cross-widget exports** — `WEAPON_SLOTS` constant exported from `WeaponRack.ts` for reuse in `PickupToast.ts`

### BSP Lighting Overhaul [RENDERING]

- **Re-enabled lightmaps** — Lightmaps were disabled due to a broken emissive-based approach. Rewrote `applyLightmaps()` to use Babylon.js `mat.lightmapTexture` with `useLightmapAsShadowmap=true`, implementing Q3's correct `texture × lightmap` multiplication formula
- **Overbright support** — Default lightmap intensity raised to 2.0 (Q3 overbright equivalent) for proper brightness levels
- **Fullbright surfaces fixed** — Light panels, lamp strips, and other `surfaceparm nolightmap` surfaces now render at true full brightness using `disableLighting=true` instead of clamped diffuse 0.3
- **Dynamic light support** — Lightmapped BSP materials are not frozen, allowing dynamic PointLights from projectiles, explosions, and muzzle flashes to illuminate BSP surfaces. Pre-allocated 8 simultaneous light slots per material

### Bug Fixes

- **UTF-8 encoding fix** — Repaired double/triple-encoded Unicode characters (♥, 🛡, —, →, ✓, ✕, ∞, ⬡) corrupted during automated file extraction

## Technical Notes

- **Architecture:** `FPSHud.ts` retains the HUD manager (container, layout, widget lifecycle, update loop). Individual widgets are self-contained classes implementing the `FPSHudWidget` interface with `getElement()`, `update()`, `show()`, `hide()`, `destroy()`.
- **Lighting:** BSP lightmap application uses `StandardMaterial.lightmapTexture` (UV2) with `useLightmapAsShadowmap=true` for multiplicative blending. Non-lightmapped materials (fullbright, skybox) remain frozen for performance; lightmapped materials stay unfrozen for dynamic light binding.
- **Feature branches:** `refactor/file-splits` (HUD), `feature/lighting-fixes` (lighting)
