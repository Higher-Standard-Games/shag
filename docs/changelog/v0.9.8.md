# v0.9.8

**Release Date:** 2026-03-03

## Summary

Remote player rendering fixed. Players are now visible as accurate hitbox wireframes at correct positions with rotation updates. Root cause of invisible players was `EngineStore.LastCreatedScene` returning the LogoCanvas UI scene instead of the gameplay scene. Crouch state now transmitted over the network via new binary protocol flag.

## Changes

### Remote Player Rendering [FIXED]

- **Scene reference fix** — `FPSGameManager` was using `EngineStore.LastCreatedScene` to create `RemotePlayerRenderer`, but `LogoCanvas` (3D lobby logo) creates its own `new Scene()` *after* the gameplay scene, causing all hitbox meshes to be created in the wrong rendering context. Fixed by using `CameraSystem.getInstance().getCamera()?.getScene()` which always returns the gameplay scene
- **Wireframe hitbox rendering** — Remote players rendered as green wireframe boxes sized to Q3 hitbox dimensions (32×56×32 standing, 32×36×32 crouching). Uses `MeshBuilder.CreateLines` for reliable line rendering
- **Position & rotation updates** — Remote player position and yaw rotation interpolated via `SnapshotBuffer` with per-frame sampling

### Crouch State Over the Wire [NEW]

- **BinaryProtocol flag 0x10** — New component flag transmits `isCrouching` and `isSliding` as packed booleans (1 byte). Previously documented as a known limitation
- **SnapshotBuffer integration** — Added `crouching` field to `EntitySnapshot` and `InterpolatedEntity` interfaces; carried through `lerpEntity()` (uses snapshot B's value at t>=0.5) and extrapolation
- **Hitbox height switching** — Hitbox mesh rebuilt on crouch/uncrouch transitions with correct height (56→36 units)

### Known Bugs Documented

- **Walljump collision desync** — Critical: performing walljumps causes player to drop further into the map. Collisions exist but no longer match rendering. Reproducible every time. Documented in `docs/known_bugs.md`

## Technical Notes

- **Root cause diagnosis:** `EngineStore.LastCreatedScene` is a Babylon.js global that returns the most recently created `Scene` instance. The `LogoCanvas` component creates a separate scene for its 3D model rendering, which becomes "last created" after the gameplay scene. Any code using this global to create gameplay meshes will silently render into the wrong scene
- **Affected systems:** This bug likely affects any lazy-initialized renderer in `FPSGameManager` that uses `EngineStore.LastCreatedScene` (e.g., `DroppedWeaponRenderer`, `GibSystem`, `DamageNumbers`, `ProjectileManager`). These should be audited
- **Feature branch:** `feature/remote-player-hitbox`
