# v0.9.8

**Release Date:** TBD

## Summary

HUD architecture refactoring, major BSP lighting overhaul, cel-shading outline system, and immersive full-screen UI. Split monolithic `FPSHud.ts` (2,582 lines) into 19 focused widgets. Re-enabled lightmaps with correct Babylon.js approach, restoring Q3-style baked lighting with dynamic light support. Added Warsow-inspired cel-shading outlines for weapons (enabled by default) and environment (opt-in). New `GamePanel` base class replaces dialog-box UI with full-viewport immersive overlays featuring blur zones, neon dividers, floating particles, and animated holographic frame edges.

## Changes

### Cel-Shading Outline System [RENDERING]

- **Post-process edge detection** — Custom GLSL fragment shader using depth-relative Sobel filter and dot-product normal comparison for BSP/environment outlines. Depth differences normalized by center depth to prevent close surfaces from overwhelming the detector
- **Weapon viewmodel outlines** — Babylon.js `renderOutline` (inverted hull) applied to first-person weapon meshes, enabled by default with Warsow-like thickness
- **HDR preservation** — PostProcess uses `TEXTURETYPE_HALF_FLOAT` to avoid quantizing the DefaultRenderingPipeline's HDR output
- **Explosion handling** — Brightness-based outline fade: outlines disappear under additive-blended effects (explosions, particles) by fading on bright HDR pixels
- **Projectile exclusion** — Projectile meshes tagged with `metadata.celOutlineExclude` and filtered via depth renderer `renderListPredicate`, preventing black blob outlines on rockets/plasma/grenades
- **Sky exclusion** — Skybox pixels (depth ≈ 1.0) excluded from edge detection

### Immersive Full-Screen UI System [UI]

- **GamePanel base class** — Reusable full-viewport overlay with blurred gameplay edges (top/bottom `backdrop-filter` strips), angled SVG neon divider lines (cyan→magenta→gold gradient glow), CSS-only floating particles (dots/shards/sparkles), faint kanji watermarks, and CRT scanline sweep

### BSP Lighting Overhaul [RENDERING]

- **Re-enabled lightmaps** — Lightmaps were disabled due to a broken emissive-based approach. Rewrote `applyLightmaps()` to use Babylon.js `mat.lightmapTexture` with `useLightmapAsShadowmap=true`, implementing Q3's correct `texture × lightmap` multiplication formula
- **Overbright support** — Default lightmap intensity raised to 2.0 (Q3 overbright equivalent) for proper brightness levels
- **Fullbright surfaces fixed** — Light panels, lamp strips, and other `surfaceparm nolightmap` surfaces now render at true full brightness using `disableLighting=true` instead of clamped diffuse 0.3
- **Dynamic light support** — Lightmapped BSP materials are not frozen, allowing dynamic PointLights from projectiles, explosions, and muzzle flashes to illuminate BSP surfaces. Pre-allocated 8 simultaneous light slots per material
- **Spawn jitter** — Collision-validated spawn position randomization. Server generates 9 candidate positions around each spawn point (8 compass directions + center at 24-unit offsets), validates each against BSP collision (`pointContents` + player-hull box trace), snaps to ground, and picks a random valid one. Prevents spawn-in-wall stuckage and adds anti-spawn-camp spread

### Bug Fixes

- **Dark textures race condition** — Fixed intermittent black surfaces on map load. Root cause: shader recompilation when `useLightmapAsShadowmap` changed state mid-render. Fix: set flag immediately during loading, pre-compile the lightmap shader variant via `EffectPreloader`, gate loading screen behind `scene.whenReadyAsync()`
- **First-shot wall flicker** — First projectile's dynamic `PointLight` triggered shader recompilation for all BSP materials. Fix: `EffectPreloader` creates a temporary `PointLight` during warm-up to pre-compile the "lightmap + dynamic light" shader variant
- **Explosion hit particles** — Removed directional sparks (Layer 6) and debris particles (Layer 7) from explosions — had a first-hit-only rendering bug and didn't look good
- **First-shot trail flicker** — First projectile trail caused shader compilation lag. Fix: `EffectPreloader` pre-compiles all effect material permutations (ribbons, icospheres, cones, discs) during map load
- **Physics stuckage on ledges** — Players getting stuck on small ledges and decorative geometry. Root causes: (1) BSP plane normals had floating-point noise causing wrong AABB corner selection in collision — added Q3-style `NORMAL_EPSILON` snapping in `BspLoader.parsePlanes()`. (2) `clipVelocity()` zeroed velocity components <0.001 (100× too aggressive), killing diagonal slide — removed. (3) Collision hull was shrunk by 0.125 units (non-standard) — removed to match Q3. (4) `LedgeGrab` target position pushed player into wall geometry — fixed with wall-normal offset and solid check
- **Crouchslide camera shaking** — Fixed by removing the aggressive 0.001 velocity component zeroing in `clipVelocity()` which was oscillating near-zero velocity components during slide
- **Ledge grab micro-shake** — Camera jitter during ledge grabs caused by reconciliation resetting grab state, forcing re-detection at a slightly different sub-unit position. Fix: preserve grab state across reconciliation (`resetPhysicsState`), skip reconciliation during active grab + 10-cycle post-grab cooldown, smoothedY snap grace period (15 frames) in `FPSController`
- **Ledge grab end-of-pull warp** — Camera appeared to "teleport" to the final position at the end of the pull animation. Root cause: `ledgeGrabPhase` dropped 1.0→0 in one tick on completion, snapping the camera pitch offset (8.6° upward tilt) to zero instantly. Fix: smooth lerp decay of `ledgePitchOffset` in `FPSController` (8×/s). Also improved grab feel: pull time 0.35→0.5s, removed upward bounce, reduced forward boost, increased Y clearance
- **FFA players stuck as spectator** — In non-team gametypes (Deathmatch), `MatchState.addPlayer()` defaulted team to `'spectator'` and no team was ever reassigned, blocking all FFA players from spawning. Fix: only apply spectator check for team-based gametypes
- **Team join button hover color** — Team join buttons (pink Udon, cyan Soba) lost their team colors after hovering, reverting to default orange. Root cause: `createButton()` hover/leave handlers used hardcoded orange colors. Fix: base colors stored in `data-*` attributes, team overrides update them, hover uses `brightness()` filter
- **UTF-8 encoding fix** — Repaired double/triple-encoded Unicode characters (♥, 🛡, —, →, ✓, ✕, ∞, ⬡) corrupted during automated file extraction
- **Skybox rendering fix** — Skyboxes were completely invisible, showing only the scene's clearColor through BSP sky holes. Root cause: material freeze loop called `freeze()` on the skybox material while its cube texture was still loading asynchronously (`isReady()=false`), permanently locking it in a non-rendering state. Fix: skip skybox material in freeze loop, add `celOutlineExclude` metadata to prevent depth pass conflicts with cel-shading, and disable depth writes on skybox material
- **GL ghost explosion** — Grenade projectile disappeared before explosion, then a delayed "ghost" explosion appeared at a different position. Root cause: client-side lifetime timer expired server-driven grenade visuals before the server's `projectile_impact` event arrived. Fix: server-driven projectiles (`isServerDriven`) skip client-side lifetime expiry — their lifecycle is controlled by server snapshots. Also added `hasRecentPrediction()` dedup in `FPSGameManager` to prevent duplicate explosions from both client prediction and server events
- **Patch/bevel rendering** — Bezier patch surfaces (arches, curved walls) rendered as angular, faceted geometry instead of smooth curves. Multiple root causes: (1) tessellation level was only 4 subdivisions per sub-patch — increased to 8 (matching Q3 "high" geometry quality). (2) Adjacent sub-patches in a quilt generated independent vertex grids causing visible seams and T-junction gaps — rewrote `buildPatchFace` to use a single shared vertex grid across the entire patch surface. (3) Black corners at arch edges where cross-product normals went degenerate — switched to interpolated control point normals (Q3/ioquake3 approach). (4) Patches now render two-sided (separate material groups with `backFaceCulling=false`). Collision: increased tessellation from 3→5, and made `traceTriangle` double-sided (tests both winding orders) so glass patches block from both directions
- **Glass shader transparency** — Additive blend materials (glass, halos, flares) rendered opaque despite correct shader resolution (`alphaMode=add`). Root cause: `transparencyMode` wasn't set to `MATERIAL_ALPHABLEND`, so Babylon.js never enabled the alpha rendering pipeline. Fixed in both `createMaterialFromShaderProps` and `applyTextures`
- **Shader info command** — `shader info` threw `ReferenceError: require is not defined` due to CommonJS `require()` calls in browser ESM context. Replaced with dynamic `import()` in `ShaderCommand.ts`

## Technical Notes

- **Architecture:** `FPSHud.ts` retains the HUD manager (container, layout, widget lifecycle, update loop). Individual widgets are self-contained classes implementing the `FPSHudWidget` interface with `getElement()`, `update()`, `show()`, `hide()`, `destroy()`.
- **Lighting:** BSP lightmap application uses `StandardMaterial.lightmapTexture` (UV2) with `useLightmapAsShadowmap=true` set immediately during loading. Shader variant pre-compiled by `EffectPreloader` (with dummy lightmap + temporary PointLight) to eliminate first-frame flicker. Non-lightmapped materials (fullbright, skybox) remain frozen for performance; lightmapped materials stay unfrozen for dynamic light binding.
- **Shader Warm-up:** `EffectPreloader.ts` creates off-screen meshes with all gameplay shader permutations (BSP lightmap ± PointLight, trail ribbons, fireballs, shockwaves, impacts), renders one frame to force WebGL compilation, then disposes. Runs during map load before `scene.whenReadyAsync()` gate.
- **Cel-Shading:** Environment outlines use a custom depth-only PostProcess (no geometry buffer dependency). Weapon outlines use Babylon's `mesh.renderOutline` inverted hull. Both systems are fully independent and cvar-configurable.
- **Feature branches:** `refactor/file-splits` (HUD), `feature/lighting-fixes` (lighting), `experimental/cel-shading` (cel outlines), `bugfix/graphical-effects` (shader warm-up), `experimental/spawn-jitter` (spawn validation + jitter), `experimental/ui-settings` (GamePanel immersive UI)
