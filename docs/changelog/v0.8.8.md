# v0.8.8 - Fog Research & Global Fog Commands

**Release Date:** January 4, 2026

## New Features

### Global Fog Console Commands

Added console commands for testing fog effects:

```
fog on [r] [g] [b] [density]  - Enable exponential fog
fog off                        - Disable fog
fog color <r> <g> <b>          - Set fog color (0-1 range)
fog density <value>            - Set fog density
fog linear <start> <end>       - Enable linear fog
fog status                     - Show current fog settings
```

**Note:** This is Babylon's global scene fog, not Q3's per-volume fog.

### Per-Face Fog Detection

The BSP mesh builder now detects faces that belong to fog volumes:
- Reads `effectIndex` from each BSP face
- Looks up fog shader params (`fogParms`) from Effects lump
- Stores fog params in mesh metadata for future use
- Logs fog-affected meshes during map load

### BSP Fog Volume Research

Extensive research into Q3's fog system:

**What We Learned:**
- Q3 fog does NOT render fog brush geometry as meshes
- Fog is applied per-face based on `face.effectIndex`
- Fog brushes have only ONE visible surface (other 5 sides have null normals)
- Fog rendering uses multi-pass with gradient texture
- Camera inside/outside volume transitions affect rendering

**Algorithm (confirmed by Carmack):**
1. Determine if camera is inside/outside fog volume
2. For faces inside volume: calculate fog depth at each vertex
3. Render fog as extra pass with gradient texture

## Technical Notes

### Why Global Fog Doesn't Work for Warsow

Warsow/Q3 maps use **localized fog volumes** - specific hallways, pits, or areas have their own fog. Global scene fog applies everywhere, which is incorrect.

True per-volume fog requires:
- Custom shader with volume bounds checking
- Per-fragment "am I inside this volume?" test
- Multi-pass rendering pipeline

This is documented as future work in `BSP_FOG_VOLUMES_PLAN.md`.
