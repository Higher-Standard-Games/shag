# v0.6.0 - Input System

**Release Date:** January 1, 2026

## Summary

Major addition of a centralized InputSystem for unified input handling across the engine. Camera controllers now use action-based input queries instead of raw input handling, significantly reducing code complexity.

## Major Features

### InputSystem

New centralized input management system providing:

- **Action-based input** - Query actions like `"move_forward"` instead of raw `"KeyW"`
- **Context stacking** - Switch between `"gameplay"`, `"menu"`, `"dialog"` contexts
- **Frame-based state** - `wasPressed()`, `wasReleased()`, `isActive()` queries
- **Configurable bindings** - Games can override default bindings via config
- **Multi-input support** - Keyboard, mouse, and touch (gestures planned)

### Default Actions

```typescript
// Movement
"move_forward", "move_back", "move_left", "move_right", "move_up", "move_down"
"rotate_left", "rotate_right"

// Camera
"camera_pan", "camera_zoom_in", "camera_zoom_out"

// Common
"interact", "cancel", "confirm"

// Menu
"menu_up", "menu_down", "menu_left", "menu_right"
```

### Default Contexts

| Context | Blocking | Actions |
|---------|----------|---------|
| `gameplay` | No | Movement, camera, interact, cancel |
| `menu` | Yes | Menu navigation, confirm, cancel |
| `dialog` | Yes | Confirm, cancel |

## Usage

```typescript
// Query actions in game code
const input = InputSystem.getInstance();

if (input.wasPressed("interact")) {
  // Handle interaction
}

if (input.isActive("move_forward")) {
  // Move character
}

// Context management
input.pushContext("menu");  // Pause gameplay input
input.popContext();         // Resume gameplay
```

## Technical

### New Files

```
src/engine/input/
├── InputSystem.ts    # Singleton manager

```

### Architecture

- InputSystem updates action states before render (high priority observer)
- Controllers query actions during their render observer
- Per-frame state cleared after render
- IsometricController retains BabylonJS pointer observable for ground raycasting

## Breaking Changes

None - existing code continues to work. InputSystem is additive.
