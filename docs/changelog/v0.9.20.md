## Changes

- **Voltaic/Lasergun beam graphics** *(merged to main)* — new `src/engine/weapon/voltaic/` procedural GPU beam renderer (analytic single-quad shader + thin-instanced remote/chain batch) replaces the old 18-cylinder re-jittered bolt. The server emits a `voltaic_beam` event (exact damage ray, contact point, surface normal, impact kind) so the electrical shape draws client-side over a spine that matches the real damage ray — no more through-wall / max-range remote beams or endpoints jumping at the 20 Hz fire cadence. Legacy `lasergun` is collapsed into `voltaic` everywhere (canonical IDs, classname + ammo aliases, pickups/registration/bot profiles). Beam wander retuned to a slow deterministic meander (was ~7 Hz spin between shots). Pixel-exact muzzle from the animated `tag_flash` socket. fps `ac64cf3`, engine `f74e198`.

- **Electrobolt rail** *(merged to main)* — the electrobolt/instagun bolt is now a procedural analytic-helix GPU rail (cold blue-white core, twin helix, muzzle crack + terminal nucleus), driven by an authoritative `electro_rail` wire event (exact endpoint) for both local and remote shooters, replacing the old re-jittered bolt. Anchored to the animated gun muzzle for the local shooter (was the eye origin → a near-camera smear). fps `516f04b`/`4a0860c`, engine `ae1f7b2`/`953c1c4`.

- **Procedural health & armor pickups** *(merged to main)* — health and armor map pickups are now runtime-generated "modern sci-fi" sculptures instead of MD3 models, with **no** change to gameplay, the server-authoritative active mask, respawn timing, pickup ids, or the map/network identity — only the client visual is replaced. New engine `PickupVisual` seam (`PickupOptions.visualFactory`; the model path becomes a fallback) plus an FPS `world/pickups/procedural/` module: a recipe-driven family covering all 9 tiers, a scene-scoped geometry/material cache (clone-per-pickup shared geometry), a fail-closed active-state machine (first mask applies silently; active→inactive plays a detached collection burst that survives the persistent visual being hidden; inactive→active assembles), and an `r_pickupProcedural` toggle (default on) that falls back to the MD3s. Health = a bright scrolling-gradient energy core + cross emblem (25 HP yellow, 50 HP orange→yellow) with a slow pulse; armor = a technical shield of dark hex plates with glowing energy rims, clustered by tier. fps `d7a7347`, engine `534eb48`.

- **Procedural muzzle flashes** *(merged to main)* — a shared procedural muzzle-flash renderer draws a flash for every weapon (GLB weapons shipped no `_flash` model, so only the light flickered before), with per-weapon styles (burst / fiery plume / electric arcs) that ride the animated barrel socket. Beam weapons keep their own corona. fps side is presentation-only. engine `83eb51e`/`57c3778`/`c32b6af`.

- **Bot map learning and authored movement** *(merged to main)* — headless bots now build and persist BSP-fingerprinted, schema-versioned navigation graphs instead of relying on map-specific coordinates. Typed A* steps retain stable pickup IDs and exact teleporter/jumppad metadata; bounded 125 Hz rollouts validate ordinary jumps with the authoritative movement model; and `npm run bot:analyze` produces reproducible map reports. A deterministic sequence director executes and verifies ordinary jumps, route crouchslides, conservative strafe jumps, teleporter/jumppad traversal, and final-edge slides into active items, then cools failed edges and replans. Team relations are isolated per bot and a final line-of-fire gate suppresses direct friendly fire across state-machine and hybrid decisions. This is the completed Phase 0–3 foundation checkpoint; richer surface discovery, advanced jumps, combat choreography, gametype directives, and lifelong learning remain planned. engine `bd025aa`/`8116dd9`/`12f6adb`, fps `fe9b0d3`/`c24d4eb`/`15fef36`.

- **Hitscan world occlusion** *(merged to main)* — `traceHitscanRay` now traces the BSP world and rejects targets occluded by geometry (bots were shooting through floors) and picks the nearest target, so a body shields whoever is behind it. Regression tests added; server determinism unaffected. fps `1e7cb62`.

- **Post-match & assorted-bug polish** *(merged to main)* — endgame music now plays at match end in **all** modes (was network-host-only) via a host-agnostic playlist trigger; player gameplay input (movement + blade/fire) is frozen on the end screen while chat + leave-lobby stay live; and the winner showcase gets a dedicated diorama camera framing a centered, straight-on hero shot relative to the model (not the death spot). Also: viewmodel no longer renders black under dynamic lights (#2), on-gun ammo counter restyle (#3), 'VIEW DEMO' plays in-engine instead of downloading (#6), and dropped weapons no longer despawn the tick they drop. fps `a952217`/`af97b1b`/`13fc28f`.

- **Babylon.js 9.17 renderer modernization** *(feature branch)* — migrated Babylon core/loaders to 9.17, replaced soft-deprecated `SceneLoader` class calls and remaining core barrel imports, clustered dynamic gameplay lights, and completed a default-on PK3-aware KTX2 pipeline with 3,020 generated/validated sidecars plus local decoder workers. Map pickups now spawn only after scene/material finalization and map reset owns their generations; composite weapon pickups preserve attachments. WebGPU is now also default-on: `WebGPUEngine` starts with bundled local GLSLang/TWGSL, selects WGSL for Q3 NodeMaterials, and automatically falls back to WebGL2. `r_webgpu 0` or `?renderer=webgl2` remains the explicit compatibility path. The KTX1 compatibility audit also fixed backend-independent upload of 56 alpha-only legacy textures.

## Technical Notes

- **Wire**: `voltaic_beam` (event id 16) added to `BinaryProtocol` + the `SnapshotEvent` union; encode/decode are byte-symmetric and the exhaustive client dispatch enforces the handler at compile time.
- **Determinism preserved**: the beam event is presentation-only output (no sim-state feedback); the wander retune is a pure function of tick+shooterId. `server:tick` checksum unchanged (`2768943778`).
- **Renderer split**: beam state moved out of the 1,200-line `HitscanEffects` into `voltaic/` (`VoltaicShaderMaterial`, `VoltaicBeamGeometry`, `VoltaicEffectRenderer`, profiles). Straight invariant damage core; all electrical motion is an analytic GPU field driven by the server/demo clock (frame-rate independent, prewarmed). Local truth reconciliation (`isVoltaicTruthAligned`) keeps the spine on the real damage ray.
- **Wire (rail)**: `electro_rail` added to `BinaryProtocol` + the `SnapshotEvent` union (byte-symmetric codec, exhaustive client dispatch), carrying the authoritative rail endpoint so both local and remote rails draw over the real damage ray.
- **Pickup visual seam**: `PickupVisual` / `PickupOptions.visualFactory` in the engine `Pickup` decouple the rendered representation from the authoritative lifecycle (position, ground placement, proximity, server active-mask, respawn, disposal). Procedural health/armor own their meshes + private materials + collection transients; shared prototype geometry and the structural material are scene-cached and disposed on scene teardown. No `PickupTable` / `PickupSystem` / snapshot changes.
- **Muzzle/rail motion**: procedural muzzle flashes and the rail are presentation-only (no sim feedback); the muzzle rides the projected `tag_flash`/barrel socket each frame.
- **Bot map cache**: immutable graph data is stored under `.cache/bots/maps` and invalidated by BSP hash, schema, trigger resolver, and movement-profile fingerprint. Mutable perception, enemy memory, failed-edge cooldowns, and item state remain scoped per bot or match.
- **Bot sequence safety**: sequence timing uses authoritative replicated ticks and verifies physical state transitions before declaring success. `HybridBrain` cannot overwrite an active authored sequence, and all decision paths pass through the same ally line-of-fire gate.
- **Renderer fallback contract**: WebGPU support detection and initialization are isolated behind a factory; unsupported adapters, compiler startup errors, and device-init failures return the established WebGL2 engine. Babylon engine observables now drive resource revalidation for both WebGL context restoration and WebGPU device restoration.
- **Headless asset parity**: the CLI now reads `public/engine.json` at its composition root and injects the same `GamePaths` configuration used by browser startup. Its default game-data path is the canonical `public/data`, while DOM-only world indicators stay dormant under `NullEngine`.
