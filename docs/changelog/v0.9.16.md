# v0.9.16

**Release Date:** 2026-05-31

## Summary

Server-authoritative pickups, a server timing fix, and a QA pass. Headline changes:

1. **Server-authoritative item pickups** — map pickups (weapons, armor, health) are now driven by an authoritative active-set replicated in every snapshot, replacing the old one-shot `item_pickup` events + client-local respawn timer. This fixes the long-standing **"ghost weapon"** desync (a pickup appearing collectible on the client but not granting until the server's next respawn).

2. **Armor & health systems** — a unified Call-of-Duty-style **plate armor** model (one 0–100 pool, masked behind Quake `item_armor_shard/ga/ya/ra` names) plus health pickups (`small`/`large`/`mega`/`ultra`), with per-type respawn and a 15s first-spawn delay on armor and mega/ultra health. Real Warsow item models from the PK3 data, with their cel-shade shaders now parsing correctly.

3. **Server tick-rate fix** — the dedicated server scheduler ran at **~62.5Hz instead of 125Hz** (half real-time), so in-game time, weapon timers, respawns, and projectile speeds were all ~2× slow. Fixed to track real time; weapon balance retuned for the corrected clock.

4. **Armor absorption fix** — armor never degraded or shielded (a parameter mix-up passed armor-piercing as armor-absorption). Armor now works for self- and enemy-damage.

5. **QA pass** — `SweepCollisionBackend` unit coverage (the second "golden jewel", previously untested), a `findGround` player-hull fix, and several leak/hygiene fixes carried over from the 0.9.13 QA matrix.

6. **Weapon system overhaul** — a QA/tuning pass over all weapons after the tick-rate fix (fixed hitscan vertical aim, deterministic fire cadence, straight projectiles, unified projectile identity) plus two new mechanics: **instagun insta-jump** and **voltaic chain lightning**, and a per-weapon **clip/pool/none reload model**.

Tests: **1041 → 1104**. `tsc --noEmit` clean.

## Changes

### Server-Authoritative Pickups [CHANGED]

- **Active-set replication.** `GameState.pickupActiveMask` carries the authoritative active state of every tracked map pickup (bit index = pickup id) in **every snapshot** (packed bitmask, full not delta). The client reconciles each pickup's visibility to the mask every frame (`FPSPickup.reconcileActiveSet`). State replication is convergent: a dropped datagram self-heals on the next snapshot — unlike the old one-shot events. (`docs/research/SERVER_AUTHORITATIVE_PICKUPS.md`.)
- **Shared pickup ids.** New `src/shared/bsp/PickupTable.ts` (`extractPickups`) is the single source of truth for the pickup list + ids, used by both server and client, so ids are provably identical without a handshake — removing the fragile parallel-counter invariant (`EntityManager.nextPickupId` vs `PickupSystem`).
- **Removed** the client-local respawn `setTimeout`, the `item_pickup`-driven client deactivation, and the dead `deactivateById`/`deactivateByPosition`/`pendingDeactivations`/`checkDeferredDeactivation` weapon-id/position fuzzy-matching machinery on `FPSPickup`.

### Armor & Health Pickups [ADDED]

- **Plate armor.** One 0–100 armor pool (4 plates × 25). Pickups: `item_armor_shard` +5 flat; `item_armor_ga/ya/ra` insert 1/2/4 plates, where a plate tops the current partial plate up to its 25-boundary (CoD-style: 58 + green → 75). Max 100. Damage absorption unchanged (~0.66). Pure, tested grant math in `src/shared/items/ItemGrants.ts`.
- **Health.** `item_health_small` +25, `item_health_large` +50 (cap 100); `item_health_mega`/`item_health_ultra` +100 overhealing to 200, decaying 1 HP/s back toward 100.
- **Per-type respawn + first-spawn delay.** Weapons 15s, armor 25s, health 20s, mega 60s. Armor and mega/ultra health are absent for the first 15s of a match (no instant grab off spawn).
- **Real Warsow models** (`models/items/armor/*`, `models/items/health/*`) wired into new `ARMOR`/`HEALTH` entity defs.
- **Server `PickupSystem`** generalized from weapons-only to all tracked types (grant logic, per-type respawn, mega-health decay). Coverage: `PickupSystem.test.ts`, `ItemGrants.test.ts`, `PickupTable.test.ts`.

### Server Tick Rate [FIXED]

- **`GameServer.scheduleNextTick`** measured `elapsed` as the tick's *work* duration (not the inter-tick interval) and scheduled ~2×`tickMs` apart, running a 125Hz server at ~62.5Hz — half real-time. Every fixed-`dt` timer (match clock, respawns, weapon fire/reload, projectile lifetime, pickup respawn) ran ~2× slow.
- Replaced with an **absolute wall-clock deadline** scheduler (bounded catch-up, cap 5, resync on stalls) so the simulation tracks real time regardless of `setTimeout` jitter, plus a ~5s tick-rate diagnostic log. Regression: `GameServerTickRate.test.ts` runs the real scheduler over wall-clock time and asserts ~125Hz. (`docs/research/TIMING_ISSUE.md`.)

### Combat — Armor Absorption [FIXED]

- **`CombatSystem.processDamage`** passed `event.armorPiercing` (always 0) as `applyDamage`'s 3rd argument, which is `armorAbsorption` — so armor absorbed 0%, never degraded, and gave no protection (self- and enemy-damage). Now converts piercing → absorption (`0.66 * (1 - armorPiercing)`). Regression: `CombatSystemArmor.test.ts`.

### Shader Parser — Warsow Items [FIXED]

- **Lowercase `_template`.** Template detection was case-sensitive (`endsWith("_Template")`), but Warsow uses both casings (`armor_template`, `debris_template`, `vsay_HUD_template`). Lowercase templates silently failed to expand (rendered with literal `$1`). Now case-insensitive (store + lookup lowercased).
- **`celshade`.** Added a handler for Warsow's cel-shade stage directive (66 shaders, incl. all armor): render the diffuse (arg0, or the diffuse overlay arg2 when the base is a `$builtin`). Items now show their textures. Coverage in `Q3ShaderParser.test.ts`.

### Weapon Balance [CHANGED]

Retuned for the corrected 125Hz clock (values were effectively tuned against the half-rate clock):

- Projectiles 30% slower — `projectileSpeed` ×0.7 (grenade launcher, gunblade, plasma gun, rocket launcher).
- Reload times 30% longer — `reloadTime` ×1.3 (all weapons).
- Fire rate 800ms (1.25/s) — rocket launcher, grenade launcher, riot gun.
- Blast radius +20% — rocket launcher & grenade launcher (`splashRadius` 125 → 150).

### Engine QA Pass [ADDED] [FIXED]

- **`SweepCollisionBackend` coverage** — 17 tests against a hand-built minimal BSP (trace/plane-crossing, startSolid, content-mask, `clipVelocity`, `slideMove` wall slide, `stepSlideMove` step-up/block, `findGround`/`isOnGround`, stats/dispose). The collision backend (shared client/server) had no direct tests.
- **`findGround` hull fix** — it hardcoded a height-56 probe hull while the real `PLAYER_HEIGHT` is 64, making the ground probe ~3u shorter than the player. Now uses `PLAYER_RADIUS`/`PLAYER_HEIGHT`; `Pickup.dropToGround` pins the historical probe so pickup placement is unchanged.
- **Leak/hygiene** (0.9.13 QA matrix): `Pickup` per-frame observer now detached in `dispose()` (#35); `AudioManager.dispose()` added (#40); `ViewportEffectsManager` caches the `MovementVars` singleton instead of per-frame `getInstance()` (#44).

### Weapon System Overhaul [ADDED] [FIXED] [CHANGED]

A QA pass over the whole weapon system after the tick-rate fix, plus two new
mechanics. Findings F1–F8; full write-up in `docs/research/v0.9.16-weapon-system-overhaul.md`.

- **Hitscan vertical aim fixed (F2).** Single-ray hitscan (machinegun / electrobolt / instagun) double-negated pitch, so the damage ray had the opposite vertical sign to the tracer and every other fire path — aiming up hit low. Now matches the fire-event direction; horizontal shots were unaffected, which hid it.
- **Deterministic fire cadence (F1).** Refire interval used `Math.floor(125 / fireRate)`, so weapons whose rate doesn't divide 125 fired slightly fast (machinegun +4%). Now nearest-tick, overridable per weapon via `WeaponDef.fireIntervalTicks`.
- **Projectiles fly straight (F6).** A blanket `velocity.y -= 50 * dt` sagged every non-grenade projectile below the crosshair. Gravity is now per-weapon (`WeaponDef.projectileGravity`, default 0); grenades keep their arc.
- **Instagun insta-jump (F4).** The instagun's splash was inert (hitscan never applied it), so instagib self-jumping didn't work. `CombatSystem` gained `DamageEvent.knockbackDamage` to decouple the push from dealt damage; the hitscan path now world-traces and applies radial splash-knockback — self-damage stays gated (instagib = 0) but the launch always applies.
- **Voltaic → chain lightning (F5).** Voltaic is now distinct from the lasergun: the beam arcs from its primary hit to nearby enemies at per-hop falloff (`chainCount`/`chainRadius`/`chainFalloff`), broadcast via a new `weapon_chain` snapshot event and drawn as arcs. It also has an **unstable hipfire beam** (`beamWanderDeg`) that bends/drifts from the hip and locks straight under ADS (Warsow-LG feel). Rendered as a procedural yellow lightning bolt. *(Beam/arc visuals are functional but rough — flagged for a later art pass.)*
- **Reload models (F3).** Per-weapon `reloadModel: clip | pool | none` with authoritative `{clip, reserve}` ammo. `clip` (MG, riotgun, plasma, laser, voltaic) uses a magazine + reserve with manual (R) and auto reload, fire blocked while reloading, and a `clip / reserve` HUD; `pool` (RL, GL, EB, IG, gunblade) is a single count with no reload; `none` is the blade. Reuses the existing generic procedural reload animation — no new models. First-pass magazine sizes are playtest-tunable.
- **Projectile identity unified (F8).** Projectiles register under their own `projectileId` (`rocket`/`grenade`/`plasma_bolt`/`gunblade_blast`) instead of the firing weapon's id, via `WEAPONS` aliases carrying identical stats — so server damage/splash and client impact/model selection share one identity. Determinism-safe.

## Technical Notes

- **Snapshot protocol**: the pickup active-set is appended to the snapshot after events, guarded by `decoder.hasMore()` so older payloads/demos (without the section) decode to an empty mask without error.
- **Test count**: 1041 → 1104. `tsc --noEmit` clean. `server:tick` + `server:fuzz --ticks 1000` determinism pass; `test:simulation` passes. `test:physics` and the `bsp load` render regression need map assets / a configured data path not present in the CI checkout.
- **Deferred** (tracked, not in this release): powerups (no timed-effect subsystem yet); `item_health_medium` mapping (used by maps, currently unmapped); plate-pip armor HUD (armor value already displays numerically); blade/gunblade bespoke re-timing.
- **Weapon overhaul — needs a browser pass** (functional, not visually verified headless): voltaic's lightning beam/arcs (rough, art pass pending) and F8 explosion/model selection. First-pass balance numbers (clip sizes, chain values, `beamWanderDeg`) are playtest-tunable.
