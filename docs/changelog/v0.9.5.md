# v0.9.5

**Release Date:** 2026-02-22

## Summary

Server-side PVS culling, weapon tuning & animation overhaul, pickup synchronization fixes, dropped weapon BSP floor detection, riotgun spread/fire rate tuning, projectile visual trails, and comprehensive documentation updates.

## Changes

### Weapon System Tuning

- **Dead player input blocking** — Client now strips all gameplay inputs (jump, fire, movement) while dead; previously only blocked WASD
- **Dropped weapon auto-pickup** — Players with room in inventory (<2 non-gunblade weapons) now auto-pickup dropped weapons on proximity; USE key (F) only required for weapon swap at capacity
- **Dropped weapon cleanup** — Picking up a weapon the player already owns (ammo-only pickup) now correctly removes the dropped entity from the world
- **Loadout weapon limit** — `initializeWeaponFromLoadout` now correctly excludes gunblade from 2-weapon limit; prevents weapon loss with 3+ weapon loadouts
- **Weapon model death guard** — Client skips weapon model sync while dead, preventing async race between weapon load and death hide/show logic
- **Dropped weapon despawn** — Reduced from 30s to 15s
- **Grenade owner pass-through** — Grenades no longer explode on contact with the player who fired them; splash damage from timer/world-hit explosions still applies
- **Static weapon ammo pickup** — Walking over a weapon the player already owns now auto-picks up ammo (no USE key prompt); pickup correctly deactivates and respawns
- **Dropped weapon ammo cap** — Weapons dropped via swap or death now contain at most one clip of ammo (`pickupAmmo`), not the player's full ammo pool
- **Dropped weapon ammo add** — Picking up a dropped weapon now adds ammo to existing reserves (capped at `maxAmmo`) instead of overwriting
- **Riotgun fire rate** — Increased by 20% from 1.5625 to 1.875 shots/sec (640ms → ~533ms between shots)
- **Riotgun spread** — Increased from 6° to 12° half-angle to match Warsow's actual spread cone and client FX `spreadAngle`
- **Riotgun explicit pickupAmmo** — Added `pickupAmmo: 10` to weapon definition for clarity
- **Pickup radius & vertical range** — Increased to 128 units radius, [-48, 96] vertical, improving reliability

### Pickup Synchronization

- **Initial pickup state sync** — Server now sends `item_pickup` events for all currently-inactive pickups on client join, so pickups consumed by bots before a player connects are correctly hidden
- **Deferred deactivation queue** — Client `Pickup.ts` queues `item_pickup` events that arrive before the corresponding visual is created; pending deactivations are applied when pickups register (handles race condition on spawn-near-pickup)
- **XZ-only position matching** — `deactivateByPosition` ignores Y axis for matching since client `dropToGround()` modifies pickup Y positions; 200-unit XZ tolerance
- **Flexible weapon ID matching** — Handles `weapon_` prefix variations between server and client weapon IDs

### Dropped Weapon Improvements

- **BSP floor detection** — `DroppedWeaponSystem` now receives the `CollisionWorld` and uses `trace()` to cast a ray downward from the drop position to find the real BSP floor; weapons settle at correct Y position instead of crude `dropY - 24` estimate
- **Collision world wiring** — `GameServer.setCollisionWorld()` now passes collision to `DroppedWeaponSystem` alongside physics/projectile systems

### Weapon Animation & Synchronization

- **Server-authoritative weapon sync** — `InventoryManager.syncFromServer` now always sets `currentWeaponId` from server unconditionally, preventing infinite animation loops when weapon definitions are missing from the client's local registry
- **Reliable weapon change detection** — `FPSGameManager.handleWeaponStateSync` uses `_lastServerWeapon` as single source of truth for detecting weapon changes, replacing the unreliable `syncFromServer` return value; initial spawn weapon loads without animation, subsequent changes play slide-down/up switch animation
- **Weapon slot sync from server** — `FPSController.currentWeaponSlot` is now synced from the server's weapon array every tick, fixing scroll cycling, key switching, and model/projectile mismatch after server-side auto-switch on pickup
- **Animation input blocking** — Mouse scroll and key weapon switching are blocked during `WeaponViewManager.isSwitching()` via callback pattern (`setWeaponSwitchBlockedCheck`), preventing scroll stutter and slot counter desync during switch animations
- **Removed client-side weapon state overrides** — `FPSPlayer.switchWeapon` no longer calls `equipWeapon()` locally; weapon state confirmed exclusively via server's `weapon_state` event. Removed redundant `EntityManager.checkPickups()` call from player update loop

### Projectile Visuals

- **Rocket trail** — Red-orange ribbon trail effect matching grenade trail style
- **Riotgun pellet spread** — Per-pellet seeded spread with traveling tracers for visual feedback

### Server PVS Culling

- **Per-client entity filtering** — `broadcastSnapshot()` now culls entities outside each client's PVS before encoding, reducing bandwidth on complex BSP maps
- **ServerPVS helper class** (`src/engine/server/ServerPVS.ts`) — Lightweight wrapper around BSP tree traversal and bit-vector visibility checks; zero Babylon.js dependency; handles Babylon Y-up ↔ Q3 Z-up coordinate conversion
- **BSP PVS data retained on server** — `headless-netserver-v2.ts` now passes nodes, leafs, planes, and visData arrays to `GameServer.setPVSData()` (previously discarded after collision extraction)
- **Always-visible entity bypass** — Own player, all player states (scoreboard), all events (kill feed, combat_state, weapon_fire, projectile_spawn, etc.), and non-spatial entities always pass through PVS filtering
- **Per-client delta baselines** — When PVS is active, delta compression uses the actual filtered state sent to each client (`lastSentState`) as baseline, preventing invisible entities at PVS boundaries
- **Maps without PVS** — Graceful fallback: maps with no visData skip filtering entirely (all entities sent to all clients, same as before)
- **Diagnostics** — Periodic perf log includes PVS culling stats (`pvs_culled: N entities across M clients`)

## Technical Notes

- **Estimated bandwidth savings:** 40–60% on complex BSP maps with multiple rooms/corridors. Single-room or open-area maps see minimal benefit.
- **Performance cost:** ~O(N) per client per snapshot tick, where N = entity count. Each entity requires one BSP tree traversal (O(log L) where L = BSP leafs) and one O(1) bit-vector check. Negligible compared to encoding cost.
