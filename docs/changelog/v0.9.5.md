# v0.9.5

**Release Date:** TBD

## Summary

Server-side PVS (Potentially Visible Set) culling for network bandwidth optimization, weapon inventory bug fixes, plus documentation overhaul aligning the manual with v0.9.2–v0.9.4 engine changes.

## Changes

### Weapon System Tuning

- **Dead player input blocking** — Client now strips all gameplay inputs (jump, fire, movement) while dead; previously only blocked WASD
- **Dropped weapon auto-pickup** — Players with room in inventory (<2 non-gunblade weapons) now auto-pickup dropped weapons on proximity; USE key (F) only required for weapon swap at capacity
- **Dropped weapon cleanup** — Picking up a weapon the player already owns (ammo-only pickup) now correctly removes the dropped entity from the world
- **Loadout weapon limit** — `initializeWeaponFromLoadout` now correctly excludes gunblade from 2-weapon limit; prevents weapon loss with 3+ weapon loadouts
- **Weapon model death guard** — Client skips weapon model sync while dead, preventing async race between weapon load and death hide/show logic
- **Dropped weapon despawn** — Reduced from 30s to 15s
- **Grenade owner pass-through** — Grenades no longer explode on contact with the player who fired them; splash damage from timer/world-hit explosions still applies

### Server PVS Culling

- **Per-client entity filtering** — `broadcastSnapshot()` now culls entities outside each client's PVS before encoding, reducing bandwidth on complex BSP maps
- **ServerPVS helper class** (`src/engine/server/ServerPVS.ts`) — Lightweight wrapper around BSP tree traversal and bit-vector visibility checks; zero Babylon.js dependency; handles Babylon Y-up ↔ Q3 Z-up coordinate conversion
- **BSP PVS data retained on server** — `headless-netserver-v2.ts` now passes nodes, leafs, planes, and visData arrays to `GameServer.setPVSData()` (previously discarded after collision extraction)
- **Always-visible entity bypass** — Own player, all player states (scoreboard), all events (kill feed, combat_state, weapon_fire, projectile_spawn, etc.), and non-spatial entities always pass through PVS filtering
- **Per-client delta baselines** — When PVS is active, delta compression uses the actual filtered state sent to each client (`lastSentState`) as baseline, preventing invisible entities at PVS boundaries
- **Maps without PVS** — Graceful fallback: maps with no visData skip filtering entirely (all entities sent to all clients, same as before)
- **Diagnostics** — Periodic perf log includes PVS culling stats (`pvs_culled: N entities across M clients`)

## Technical Notes

- **Estimated bandwidth savings:** 40–60% on complex BSP maps with multiple rooms/corridors. Single-room or open-area maps see minimal benefit.
- **Performance cost:** ~O(N) per client per snapshot tick, where N = entity count. Each entity requires one BSP tree traversal (O(log L) where L = BSP leafs) and one O(1) bit-vector check. Negligible compared to encoding cost.
- **Feature branch:** `feature/server-pvs` (both `shag` parent repo and `src/games/fps` submodule)
