# v0.9.7

**Release Date:** 2026-02-24

## Summary

Spectator mode, movement simulation refactor, centralized input system with rebindable keybindings, HUD polish, and player profile system. Full freefly camera spectating with `J` to join, Quake-style vertical flight controls, scroll-wheel weapon cycling (skipping gunblade), dynamic keybinding labels in weapon HUD and spectator overlay. Player profiles with UUID identity, themed bot names, and hold-to-show scoreboard.

## Changes

### Team-Based Gametypes [NEW]

- **Gametype Framework** — `GametypeController` extended to support team-based (`TeamDeathmatch`, `Duel`) vs standard (`Deathmatch`) gametypes
- **Team MatchState** — `MatchState` tracks team scores, assigns players via auto-balance (`assignTeamBalance`), and lists team players dynamically
- **Duel Mode** — Strict 1v1 enforcement; excess players automatically assigned to the `spectator` role upon join
- **Headless Parameter Parsing** — Robust CLI argument parsing in `headless-netserver-v2.ts` correctly handles `--map` and `--gametype` fallback inputs to circumvent NPM parameter stripping
- **Dynamic Scoreboard Layout** — Scoreboard UI (`FPSHud.ts`) switches from FFA to a multi-column, dynamic row format for Team Udon vs Team Soba with auto-populating player values
- **Team Select Spectator Menu** — `SpectatorOverlay.ts` supports "JOIN UDON" and "JOIN SOBA" button flows sending `TeamId` over the custom WebTransport payload

### Music System [NEW]

- **Playlist-driven audio** — JSON-based `.playlist.json` format with `name`, `loop`, `shuffle`, and `tracks` fields; three playlists shipped: menu, game (shuffle), endgame
- **PK3 streaming** — Music tracks streamed from `washoi_soundtrack.pk3` via `PK3Loader.getFileAsURL()` Blob URLs; on-demand PK3 loading via `PK3Index.findFile()` → `PK3Loader.loadPK3()` bridge
- **State-driven transitions** — Menu music on audio unlock, game playlist on `JoinAccept`, endgame on `MatchPhase.PostGame`, menu resume on disconnect
- **Crossfading** — Smooth fade-out/fade-in between playlists and tracks; `fadingOutMusic` tracking prevents overlapping audio
- **Robustness** — Blob URL lifecycle managed per `HTMLAudioElement`; `loadingRequestId` concurrency lock prevents race conditions during rapid playlist switches
- **Architecture doc** — `docs/research/MUSIC_SYSTEM.md` documents playlist format, integration points, and loading sequence

### Spectator System (SpectatorOverlay.ts) [NEW]

- **Freefly spectator mode** — WASD + mouse free camera with Shift for speed boost; activates on connect before joining
- **Spectator HUD panel** — Washiki-themed key binding panel with dynamic labels from InputSystem; corner brackets and orange neon accents; aligned with health/armor bars
- **Responsive scaling** — All spectator panel dimensions use `calc(... * var(--ui-scale, 1))` for resolution independence
- **Join/spectate dialog** — Washiki-styled dialog with dynamic key labels (e.g., "Press J to join")
- **Spectator-aware ready bar** — Shows "SPECTATING" text when in freefly mode; shows ready counter only for joined players
- **Quake-style vertical flight** — Jump (Space) flies up, Crouch (C/Ctrl) flies down — matches Q3/Warsow conventions
- **Sprint in freefly** — Shift gives 3× speed multiplier for fast navigation

### Centralized Input System (FPSActions.ts) [NEW]

- **FPSActions registry** — All FPS actions defined as typed constants (`FPS.MOVE_FORWARD`, `FPS.FIRE`, etc.) with configurable default bindings; registered into InputSystem as `fps_gameplay` context
- **scrollDirection binding type** — New `InputBinding.scrollDirection: 'up' | 'down'` field enables scroll wheel as a rebindable input source, processed as per-frame impulse in `updateActionStates()`
- **WEAPON_NEXT / WEAPON_PREV** — Scroll-based weapon cycling via InputSystem actions (skip gunblade at slot 0); fully rebindable like all other actions
- **Q for gunblade** — `KeyQ` added as secondary binding for Weapon 1 (gunblade) alongside `Digit1`
- **InputSystem.init() idempotent** — Safe to call from multiple controllers; `_initialized` guard prevents double event listener registration
- **Old DOM onMouseWheel removed** — Weapon scroll cycling no longer bypasses InputSystem; single source of truth for all input

### Dynamic Keybinding Labels

- **Weapon bar labels** — `FPSWeaponSlots` (3-slot bottom bar) and `FPSWeaponRack` (vertical rack) now pull key labels from InputSystem via `getActionKeyLabel()` instead of hardcoded `1/2/3`

- **getKeyLabel() / getActionKeyLabel()** — Utility functions in `FPSActions.ts` convert key codes to human-readable labels (e.g., `Digit1` → `1`, `KeyQ` → `Q`, `ShiftLeft` → `SHIFT`)

### Advanced Movement Fixes

#### Collision & Physics

- **traceBrush startSolid normal** — `traceBrush()` now computes the least-penetrated plane normal for startSolid cases (Q3 `CM_TraceThroughBrush` behavior). Previously returned no normal, making all startSolid depenetration in `slideMove` dead code. Root cause of the stuck-on-ledge bug.
- **Three-path ground detection** — Replaced two-path conditional ground detection with three paths: (1) downward movement blocked → grounded, (2) nearly level → trace down, (3) uphill + hit surface → ramp walking. Fixes ramp walking without breaking crouch slides.
- **MIN_WALK_NORMAL reverted to 0.7** — Restored from 0.75 to match Warsow; 45° ramps are walkable (`cos(45°) ≈ 0.707 > 0.7`).
- **Jump prevention on steep ramps** — Jumping blocked on surfaces steeper than ~32° (`normal.y < 0.85`), matching Warsow behavior.
- **Depenetration improvements** — allSolid handler tries multi-directional escape (10 directions, 2u) before giving up; 3-plane corner handler zeroes velocity (previously pushed downward, risking floor clips).

#### Crouch Slide & Camera

- **Reconciliation slide state preserved** — Removed `slide.reset()` from `resetPhysicsState()`. Slide state (camera tilt, speed decay) was being killed at every server reconciliation (~60Hz), preventing camera animation from ever completing.
- **Y reconciliation suppressed during slides** — Diagnostic revealed ±0.07u Y-correction oscillation from server/client desync during slides. Suppressing the Y component of `visualOffset` during slides eliminates camera bobbing.

#### Ledge Grab

- **Ledge grab input immunity** — Once grab triggers, only Crouch cancels; Sprint and directional input no longer interfere (fixes detection→cancel oscillation when approaching at angles)
- **Post-pull cooldown** — 300ms cooldown after pull-up completion prevents immediate re-detection loops
- **Upward boost on pull-up** — Small `vel.y = 50` boost ensures player clears the ledge surface on completion
- **Wall jump suppression** — Wall jump detection suppressed while ledge grab is active or on cooldown
- **Frame 0 velocity freeze** — Velocity zeroed on the detection tick itself (not just subsequent ticks)
- **Visual smoothing guards** — V2NetworkClient visual offset, NetworkGameHost reconciliation, and camera Y smoothing all snap instantly during ledge grab states

### Bug Fixes

- **Fixed movement-killing crash** — Removed `require()` calls in `FPSController.syncKeysFromInput()` that threw `ReferenceError: require is not defined` in browser ESM, breaking all input processing after first Tab/T press

## Technical Notes

- **Architecture:** `FPSActions.ts` defines all action IDs, default bindings, and the `fps_gameplay` context. `registerFPSActions()` is idempotent and called from controller `attach()`. `InputSystem.getBindingsForAction()` resolves overrides → context → defaults.
- **Scroll as action:** `scrollDirection` bindings fire as `pressed` for exactly one frame when the wheel moves in the matching direction, enabling `wasPressed()` checks in game code.
- **HUD zones:** Phase message and ready bar use `position: fixed` with explicit `top` values. They must be in `top-center` zone (not `center`) to avoid the center zone's `top: 50%` layout overriding their positioning.
- **Feature branches:** `experimental/keybindings` (keybindings), `experimental/player-profile` (player profile), both merged to `main`
