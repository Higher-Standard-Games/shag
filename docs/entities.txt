================================================================================
                         SUPPORTED ENTITIES
================================================================================

This document lists all entity types currently supported by the engine.

--------------------------------------------------------------------------------
WORLDSPAWN
--------------------------------------------------------------------------------
Classname: worldspawn

The root entity containing all world geometry (brushes and patches).

Properties:
  - message         (string)    Map title/description

Contains:
  - Brushes         Standard brush geometry
  - patchDef2       Bezier patch surfaces (3x3, 5x3, 3x5, etc.)


--------------------------------------------------------------------------------
INFO_PLAYER_START
--------------------------------------------------------------------------------
Classname: info_player_start

Defines the player's starting position. Camera will target this location.

Properties:
  - origin          (vector3)   "x y z" - Spawn position in Quake coordinates
                                (Z-up, converted to Babylon Y-up)

Example:
  {
  "classname" "info_player_start"
  "origin" "0 0 100"
  }


--------------------------------------------------------------------------------
LIGHT
--------------------------------------------------------------------------------
Classname: light

Point light source in the scene.

Properties:
  - origin          (vector3)   "x y z" - Light position in Quake coordinates
  - light           (float)     Intensity value (default: 300)
                                Scaled by /200 for Babylon.js
  - _color          (vector3)   "r g b" - Light color
                                Supports 0-1 range or 0-255 range (auto-detected)
                                Default: white (1 1 1)

Example:
  {
  "classname" "light"
  "origin" "0 0 200"
  "light" "500"
  "_color" "1 0.9 0.8"
  }


--------------------------------------------------------------------------------
TRIGGER_MULTIPLE (and other trigger_ entities)
--------------------------------------------------------------------------------
Classname: trigger_multiple, trigger_once, etc.

Interactive trigger volumes. Any entity with brushes using "trigger" texture
will be rendered as a clickable red wireframe.

Properties:
  - targetname      (string)    Unique identifier for this trigger
  - message         (string)    Debug message shown when triggered
  - windowTarget    (string)    Opens a UI dialog with this name
  - targetMap       (string)    Loads a different map file (e.g., "map2.map")

Behavior:
  - Rendered as transparent red wireframe (alpha 0.3)
  - Clickable via pointer/mouse
  - Executes actions based on properties when clicked

Example:
  {
  "classname" "trigger_multiple"
  "targetname" "dialog_trigger"
  "windowTarget" "intro_dialog"
  "message" "Opening dialog!"
  {
  ( ... ) common/trigger 0 0 0 1 1
  ( ... ) common/trigger 0 0 0 1 1
  ...
  }
  }


================================================================================
                         GEOMETRY TYPES
================================================================================

--------------------------------------------------------------------------------
BRUSHES
--------------------------------------------------------------------------------
Standard convex brush geometry defined by plane intersections.

Format:
  ( x1 y1 z1 ) ( x2 y2 z2 ) ( x3 y3 z3 ) texture u_off v_off rot u_scale v_scale

Texture naming:
  - color_R_G_B     Solid color (e.g., color_255_128_0 = orange)
  - common/caulk    Editor-only, skipped in render
  - common/trigger  Trigger volume texture
  - path/texture    Real texture file from /textures/ folder


--------------------------------------------------------------------------------
PATCHES (patchDef2)
--------------------------------------------------------------------------------
Biquadratic Bezier surfaces for curved geometry.

Format:
  patchDef2
  {
  texture_name
  ( width height 0 0 0 )
  (
  ( ( x y z u v ) ( x y z u v ) ... )  // row 1: 'width' control points
  ( ( x y z u v ) ( x y z u v ) ... )  // row 2
  ...                                   // 'height' rows total
  )
  }

Requirements:
  - width and height must be 2n+1 (3, 5, 7, 9, ...)
  - Control points stored as rows (height) x columns (width)
  - Supports multi-sub-patch tessellation (e.g., 5x3 = 2 sub-patches)

Examples:
  - 3x3: Simple curved surface (1 sub-patch)
  - 5x3: Extended curve (2 sub-patches in one direction)
  - 3x5: Extended curve (2 sub-patches in other direction)
  - 9x3: Long curved surface (4 sub-patches)
