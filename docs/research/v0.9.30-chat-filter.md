# Lightweight chat profanity filtering — investigation

**Reviewed:** 2026-10-14. The initial investigation below was followed by the
implementation described at the end of this document. The filter is now enabled
for lobby, room and match chat on branch `v0.9.30-chat-filter` in both repositories.

## Recommendation

Use **`@2toad/profanity`** for the first implementation: a local TypeScript-friendly
filter, no runtime dependencies, configurable word lists/allowlists and multiple
language dictionaries. Keep whole-word matching on, instantiate once and choose
languages deliberately. Start with public lobby chat, mask words rather than
issuing automatic penalties, then apply the same wrapper to room/match chat if
that is the desired policy. [Maintainer documentation](https://github.com/2Toad/Profanity).

Keep **`obscenity`** as the alternative if stronger spelling normalization becomes
a requirement. Its configurable transformers and match ranges are useful, and
it caught repeated-letter spelling in the probe. It still missed punctuation
and a zero-width variant in the tested English preset; do not promise bypass-proof
moderation. [Maintainer documentation](https://github.com/jo3-l/obscenity).

**`bad-words`** is the familiar simple option, but its default `.clean()` path was
much more expensive in this local probe. Its installed source recreates dictionary
regexes for each token; that is a poor fit for a busy lobby event loop when a
faster small library is available. [Maintainer documentation](https://github.com/nyvorin/badwords).

preset is English; custom datasets can be built separately.

whole-word 2Toad and Obscenity's English recommended preset. Results:

| --- | --- | --- | --- |
| Ordinary swear | Detected | Detected | Detected |
| `sh1t` | Detected | Detected | Detected |
| `f.u.c.k` | Missed | Missed | Missed |
| `fuuuuuck` | Missed | Missed | Detected |

| Ordinary armor/bomb-site callout | No match | No match | No match |

This is a small hand-selected set, **not** a measured real-world false-positive or
recall rate. The Finnish result is expected under English configuration. Neither
a clean result nor a detected word establishes whether a message is harassment.

Measured censor/clean calls on a repeated, nonprofane game-callout string, capped
to the actual 128-character match / 500-character lobby limits. Five warmups,
100 timing samples per length, one instance per candidate:

| Package | 128 chars median / p95 | 500 chars median / p95 |
| --- | --- | --- |
| bad-words | 13.491 / 20.856 ms | 77.141 / 83.105 ms |
| 2Toad | 0.0015 / 0.0037 ms | 0.0031 / 0.0033 ms |
| Obscenity | 0.0696 / 0.1219 ms | 0.0930 / 0.2149 ms |

The installed 2Toad code caches regexes, not complete input results. These timings
are synthetic local measurements: they do not benchmark cold-start compilation,
matched-message workloads, every language, hostile worst cases or production
throughput. No game FPS improvement is claimed. An initial 2,000-sample run was
stopped because the default bad-words path took too long; the completed table
uses the bounded 100-sample run for all candidates.

## Fit in SHAG

Three verified server entry points currently accept chat:

1. `src/lobby/LobbyServer.ts` — `handleChatSend`: type-check, trim, cap at 500,
   append to global history, broadcast and log.
2. Same file — `handleRoomChatSend`: verify room membership, trim/cap at 500,
   append to room history and broadcast to its members.
3. `src/games/fps/server/GameServer.ts` — `handleChat`: decode/strip team request,
   sanitize/cap at 128, apply the shared rate budget, validate team seat,
   enqueue the event with server-only addressing metadata.

A small engine-side pure utility can wrap the library and be used by both the
lobby and FPS server. Apply it **after existing normalization/length/rate checks**
and before history, logging, enqueueing or broadcasting. Re-cap filtered output
because a replacement marker may expand short words. Filter the message body,
not `/say_team` or the server's `[TEAM]` marker. Preserve recipient metadata;
moderation must not change team routing. Client-local mute/unmute never reaches
these paths.

For authoritative server masking, everyone—including the sender—receives the
same filtered body, lobby histories store it and server demos record it. A local
optional display filter is a different policy: recipients still receive raw text.
Choose that only if user-selectable display filtering is the actual goal.

Suggested first scope:

- English whole-word filtering for public lobby chat, with an explicit server
  enable/disable setting and a small application allowlist.
- A fixed masking marker and no automatic bans, kicks or rating effects.
- Review dictionary entries against game vocabulary and harmless substrings.
  Apply nickname validation separately if desired; do not silently rename users
  through the chat filter.
- Decide room/private/team-chat policy and supported languages before extending
  beyond the initial lobby path.

Implementation acceptance should cover plain profanity, common obfuscations,
benign substrings, custom words/allowlist, Unicode, empty/length-limited input,
history and sender echo, plus team-routing and demo regressions if match chat is
enabled. Server instances should reuse a compiled matcher; no per-message library
construction, browser downloads or remote calls are required.

## Implementation

User-approved scope: lobby chat, room chat and the in-game chat box. Installed
`@2toad/profanity` **3.3.0**, pinned as a runtime dependency. One server-only
instance uses English, whole-word matching, Unicode word boundaries and `***`
replacement. A second, fixed substring pass masks `fuck`, `shit`, `cunt`, `nigger`
and `faggot` case-insensitively, including when surrounded by other letters.
`Scunthorpe` is preserved case-insensitively without exempting adjacent text.
The substring pass excludes `ass`; tests cover benign substrings and common game
vocabulary. There is no remote
service, client setting, automatic penalty or nickname filtering.

All three server handlers mask normalized, length-bounded message bodies before
delivery and history storage; match chat filters after rate/team checks and before
logging and event enqueueing. Team markers and recipient metadata are preserved.
Private-room and spectator messages are filtered too. New demos record masked
events through the existing snapshot recorder; historical recordings are unchanged.
The browser continues to display authoritative server echoes, with existing local
mute/unmute behavior. Restart lobby and match servers to activate the new code.

### Selective substring follow-up

The user reported an added-letter bypass (`fuckj`) and approved substring matching
for the worst terms. The fixed list above supplements the library's whole-word
dictionary without enabling substring matching for every dictionary entry. Unit
coverage includes all five roots, uppercase, prefixes/suffixes, Unicode adjacency,
repeated calls, the place-name exception and profanity adjacent to that exception.
Lobby sender/history and live spectator delivery tests also exercise `fuckj`.
This literal pass does not normalize arbitrary punctuation or spelling tricks;
the library's existing whole-word substitutions remain available.

Files changed in this follow-up: `src/engine/server/ChatFilter.ts`, its unit test,
`src/lobby/__tests__/LobbyRoomChat.test.ts`, FPS `server/__tests__/TeamChatDelivery.test.ts`,
