# DM3 decals and animated shader replay

Date: 2026-11-08. Scope: DM3 world/inline-door materials and timed shader
animation, on native WebGL2 and WebGPU. No networking, collision, mover geometry,
map rules or protocol changes. Corrected author media and custom levelshots are
recorded in [the package report](v1.0.0-beta8-map-packages.md).

## Door decals

The reported number panel (`textures/decals/03`) belongs to inline `func_door`
model `*6`; the direction sign (`textures/decals/decal_telesign_right`) belongs
to model `*2`. The inline brush builder loaded image candidates but ignored
material-directive image paths, blending, vertex alpha, culling and polygon
offset. The earlier world-material bias correction could not reach these doors.

The brush path now uses the registry's resolved diffuse image and shared alpha
configuration, preserves authored vertex RGB/alpha, and applies authored culling
and polygon offset. Existing geometry, UV2 page grouping, lightmap sharing,
pivots and door movement remain in place. Ordinary unshaded panels retain their
existing path. The actual direction sign and number-panel views were inspected
on both GPU backends after the correction, without the reported stippling.

For world materials, polygon offset previously set slope bias but no constant
term. Both terms are now -2; multiplicative filter overlays use their existing
slope -4 and constant -4. Ordinary surfaces retain zero bias. No new meshes,
textures, passes or per-frame work are introduced by the decal changes.

The initial world-only symbol-atlas A/B restored 40,599 pixels on WebGL2 and
24,573 on WebGPU. That was a different surface from the reported door. Those
background-only probes did not install whole-frame snapshots; they do not prove
active replay. The final full-map probe covers the actual inline door materials.

## Teleporter animation

The packaged `textures/baxandall/teleglow_02` retains its authored rotation,
stretch and brightness-wave instructions. Its animation clock and CPU values
advance. Snapshot material learning compares loose per-draw uniform values over
a bounded number of normal frames. Texture transforms and brightness can live
in the material UBO instead, and replay can begin before learning identifies
the material. Later normal frames may identify it, explaining intermittent
animation without an asset change.

Timed shader registrations now declare their material dynamic before the first
recorded draw. This reuses the snapshot controller's existing material-bind path.
The declaration helper matches the existing staging implementation, avoiding a
second update mechanism. Fixed-scale and ordinary materials remain cached.
There is no extra draw, shader recompilation, whole-world traversal or periodic
re-recording added for animation; only registered changing materials are rebound.

A first-recording regression uses an animated StandardMaterial with no changing
loose values, plus fixed-scale and ordinary controls. Without the declaration it
fails (all three remain unrecognized); with it only the animated one is dynamic.
The focused rendering group passes 33 tests in four files.

The final full-map native GPU probe retains snapshots. WebGPU samples keep the
normal-frame count at 15 while replay advances 926 -> 1003 -> 1083. Animation
time advances 15.674 -> 16.152 -> 16.637 seconds, with changing stretch, rotation
and brightness. Consecutive sampled images change 66,650 pixels by more than
5 channel levels; the WebGL2 control changes 81,224 pixels. Neither backend has
failed asset requests or renderer errors. Existing model skin-root and unsupported
map-entity warnings remain. This is sampled map rendering, not a live match.
