# Remote player placement: measured model defects and fix

2026-09-13. Investigated from `1dc91dac`, following the
[placement brief](v0.9.23-remote-player-placement-brief.md).

**Confirmed and fixed:** player instances shared their animation target nodes.
A deterministic reproduction with the actual Vanguard model sinks a crouching
player through a floor when another player's idle animation is selected. No
network, snapshot timing, collision, or player position changes are involved.
**Still unverified:** whether this accounts for every intermittent wall/warp
observation in a live `wdm2` or `wdm7` match.

## Evidence

`PlayerModelManager.createInstance()` cloned the mesh and skeleton separately.
In the installed Babylon 9.17.0 implementation, `Skeleton.clone()` copies each
bone's link to the **original** TransformNode. SHAG built its animation targets
from those links without remapping them to the cloned mesh hierarchy.

The result was separate Skeleton and AnimationGroup objects driving the **same
nodes**. Each player's chosen animation could change all other players' poses.
The root-motion guard, meanwhile, reset nodes in the cloned hierarchy rather
than the nodes driving the visible skin. Instance creation also called
`stopAnimation` on the shared source nodes.

The real asset has 65 bones:

| Measurement | Original | Fixed |
| --- | ---: | ---: |
| Bones linked into their own instance's mesh tree | 0 / 65 | 65 / 65 |
| Bone-node links shared between two players | 65 / 65 | 0 / 65 |
| Crouching player's lowest vertex before another player idles | +0.9467 | +0.9467 |
| Same player's lowest vertex after another player idles | **-8.8236** | **+0.9467** |

Vertex Y is in world units relative to a floor at zero. The crouching player
uses the existing -10 anchor compensation. Both clips are sampled at their
midpoints. The model scale is the production value, 36. Only player B's pose
changes between measurements; player A's anchor remains fixed.

This explains how the renderer could select the correct crouch state for A,
then display a standing pose supplied by B on A's lowered anchor. It also gives
a concrete mechanism for poses that disagree with an individual player's
movement despite all animation clips being present.

A second defect had to be fixed together with relinking. Babylon prefixes cloned
node names with ancestor paths. The old `resetRootMotion()` matched `"root"`
anywhere in each name, so `player_a.RootNode.mixamorig:Hips.mixamorig:Spine`
matched too. It zeroed ordinary joint translations. This was masked for body
skinning by the first defect, because the skin still followed the source nodes.
Relinking alone exposed a collapsed skeleton; the new regression catches it.

## Changes

- `src/engine/animation/PlayerModelManager.ts`: clone the hierarchy with an
  explicit source-to-clone identity map; relink every skeleton bone before
  retargeting animations or stopping animatables; identify root/armature nodes
  from original names and cache their cloned nodes for the root-motion guard.
  Failed hierarchy cloning disposes the partial clone.
- `src/engine/__tests__/PlayerModelCloning.test.ts`: real Babylon tests for
  independent bone links, independent animation/pause/disposal, effective root
  resets, late-join source-pose isolation, and preservation of ordinary joint
  offsets beneath prefixed RootNode names. Asset loading alone is substituted
  with a small linked skeleton; cloning and animation use production code.
- This findings document and a follow-up link in the original placement brief.

The first three regressions failed against the original implementation. After
relinking, the prefixed-root regression also failed until root identification
was corrected. Existing root-motion tests constructed instances manually and
therefore missed both the real cloning behavior and prefixed joint names.

## What the brief's wireframe test can and cannot establish

Two source facts qualify its claim that the displayed box is the collision hull:

- `MovementProfile.PLAYER_BOUNDS` uses Y **-24 to +32** (56 high), with crouch
  **-24 to +8** (32 high). The renderer's standing box is 64 high and crouch
  box is 44 high, following different constants. The brief's 64-unit movement
  hull assumption is therefore inaccurate for the active simulation path.
- The renderer rotates the wireframe by yaw; movement sweeps are axis-aligned.
  At 45 degrees, a radius-16 debug square extends 22.63 units along a world
  axis. Its corner can appear 6.63 units into a wall without the movement hull
  penetrating it.

A model outside the displayed box can therefore indicate a pose/model problem,
but a displayed box intersecting geometry does **not**, alone, prove a bad
transported position. The shared-animation reproduction bypasses this ambiguity
by holding positions and hulls constant and changing only another player's pose.

There is also measured normal model overhang: with fixed isolated poses, the
idle body's maximum forward extent is 22.00 units and run's is 26.38 units,
versus the 16-unit movement radius. These are midpoint samples, not full-clip
extrema, and exclude the held weapon. Thus some near-wall limb clipping can
remain after this fix. No arbitrary scale/hull adjustment was made.

TypeScript passes. Final Vitest: **2,615 tests, 251 files passed**. Biome stays at
its existing baseline: **70 errors, 342 warnings**. Tick determinism checksum:
`2768943778`; 1,000-tick fuzz checksum: `691251920`, zero reported errors.
Simulation, physics, indexed `wdm2` loading, the three separate replay batches,
asset measurements and browser fixture all exit zero.

Qualification: exit zero is not a claim of warning-free headless logs.
`test:simulation` reports an uninitialized client CollisionManager and exercises
initialization without a collision world. `test:physics` on its default `wdm7`
prints a Y-change warning for a downward sweep starting at the spawn (Y=432).
Its own preceding simulation settles on the floor at about Y=416; the warning
assumes the unsolved spawn is already grounded. BSP loading also emits existing
lightmap/shader-template warnings. These scripts were not modified.

The exact AGENTS.md replay string exits **1**: the outer batch parser splits
at semicolons, interpreting `JUMP` and `W` as console commands. Repeating
`sim replay` for each segment succeeds, but each starts a fresh simulation and
is **not equivalent to the intended continuous crouch-jump sequence**. That
continuous sequence remains unverified through this CLI path.

Initial sandboxed Vite runs could not spawn esbuild (`EPERM`); the checks above
were rerun successfully with approved subprocess access. Logs and temporary
comparison scripts are in the artifact directory linked above.

## Scope and next live observation

Assumptions: this task concerns the active FPS game, the shared Vanguard player
model, and bots rendered through the remote-player path. No networking or
movement simulation changes were required for the demonstrated defect.

Reload the client to recreate model instances, then play the original bot setup
on `wdm2`/`wdm7`; `cl_remotehitbox 1` remains useful with the qualifications above.
Watch a crouching bot while other bots alternate between run, jump and idle.
Pose selection should now remain specific to each bot.

Still open: the exact intermittent live wall/warp reproduction, extrapolation
frequency, collision-blind interpolation/extrapolation, airborne crouch offset
versus selected pose, normal model/hull overhang, and full-match weapon/dance
presentation. This patch does not establish that transported positions are
always legal or that every original symptom has one cause.
