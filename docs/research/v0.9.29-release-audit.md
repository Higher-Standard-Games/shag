## Details

### RA-1 · The lobby never reconnects (High)

`LobbyClient` declares and clears a `reconnectTimer` (`src/lobby/LobbyClient.ts`)
but nothing ever sets it, and `LobbyPanel` connects once, in
`initLobbyConnection`. When the socket drops, the panel shows the disconnected
state for good: "LOBBY OFFLINE" on the Find key, "Offline" on the player card,
the chat disabled. In this audit the lobby was killed under an open page; 90
seconds later the page still said Offline (screenshot `41-lobby-back`; the lobby
did not come back in that run, so the code is the proof that it would not have
recovered).

Every deploy restarts the lobby, so every open page would need a reload.

**Fix:** reconnect with backoff (about 2 s, 5 s, 10 s, then every 30 s, with
jitter) and log in again. `LobbyPanel.logInToLobby` already re-runs cleanly; the
"Servers are full" card added in v0.9.29 shows the pattern of a countdown with
**Try now**. A player who was in a room should rejoin it, as "Return to lobby"
already does through `?lobby=`.

### RA-2 · Boot failures are invisible (High)

`src/main.ts` ends with `main().catch(console.error)`. With WebGL unavailable
(Edge with 3D APIs off), the start-up screen stays on "Initializing renderer…"
with the ring spinning, indefinitely (screenshot `50-no-webgl`). The same holds
for anything else that throws during boot: the pk3 index, `/data` unreachable,
a bad build.

**Fix:** on a boot error, stop the ring and say what happened and what to do:
for the renderer, "Washoi needs WebGL 2 or WebGPU — enable hardware
acceleration, or try another browser"; for anything else, a short message with
**Reload**. Keep the error itself in the console.

### RA-3 · First visit downloads every pk3 (High)

**Implemented 2026-10-12:** the prebuilt-index part of this finding is fixed.
`npm run build` now generates `pk3_manifest.json` and `pk3_index.json` before
copying public assets. `npm run tools:manifest` retains its existing name and
now publishes both; `npm run tools:pk3-index` is the explicit generator.
Runtime boot fetches the metadata from the game's origin with HTTP revalidation.
It validates version, ownership, package list and a content fingerprint before
adopting any of it, then rebuilds archive URLs from its own search paths. All
configured paths must validate; a stale pair, missing file, unsupported schema,
old manifest or failed request uses the prior archive scan/cache-validation
path. The fingerprint checks consistency, not cryptographic archive integrity.

The generator reuses `PK3Index.indexPK3ArrayBuffer` for exactly the existing
file/shader/map ownership rules. It indexes in alphabetical order, emits
portable paths, and prepares temporary files before publishing the matched pair.
Corrupt archives or files changing during generation fail the command and leave
the previous pair intact. A short index/manifest deployment mismatch falls back
safely. LocalStorage remains optional, including browsers that block it.

**Measured on this installed data set:** 107 PK3s, 535,755,013 bytes (510.94 MiB),
4,651 files, 1,687 shader entries and 49 maps. The generated index is 349,874
bytes and the manifest 2,629 bytes: **352,503 bytes (344.24 KiB)** instead of
downloading all archives for indexing, a **99.934% indexing-byte reduction**
before HTTP compression. Real isolated localhost HTTP acceptance:

| Phase | Requests / bytes | Result |
|---|---|---|
| Cold `ensureIndex()` | Two JSON GETs, 352,503 bytes, zero archive GETs/HEADs | 22.57 ms in Node on localhost. |
| Warm `ensureIndex()` | Two JSON GETs, zero archive GETs/HEADs | 11.78 ms; unchanged metadata accepted. |
| Select wdm2 | Only `map_wdm2.pk3`, 3,331,926 bytes (3.18 MiB) | `PK3Loader` extracted `maps/wdm2.bsp` with FBSP magic. |

These are indexing/lazy-load measurements, not browser startup, internet or FPS
benchmarks. Models/audio and map dependencies still download when needed;
mirror selection and archive loading are unchanged. The download reduction
does not establish that a complete first visit transfers only 344 KiB.

**Still open:** curate the shipped archive set, remove test/editor packages from
the release directory, and inventory/replace nonfree assets (RA-12). This patch
does not delete or silently filter local packages. Generate against a curated
directory with `npm run tools:pk3-index -- --data-dir <directory>` and deploy
its archives and both JSON files together. Direct `vite build` users must run
the generator themselves; the supported `npm run build` does it automatically.

Building the index (`PK3Index.buildIndex`) fetches every package in
`pk3_manifest.json` to list its files: 107 packages, about 512 MB here, before
the player can do anything. The boot log shows it ("Indexing
data0_000_nonfree_21.pk3…"). The manifest includes packages a player never
needs: `editortextures.pk3`, and test and editor maps (`map_mcp_probe_*`,
`map_shaggedapi_*`, `map_agent_arena1_*`, `map_shagged_*`). Later visits only
send HEAD requests, but the first impression is a long download, and on the
server it is the largest cost per new player (the pk3 mirror moves the bytes,
not the wait).

**Fix, in order of effect:**
1. Ship only the curated data set (deploy.md D2 plans this).
2. Generate the index at build time (file → package, shaders, maps) as a JSON
   next to the manifest, so the client downloads packages only when a map needs
   them. (The PK3 guide lists `scripts/generate-pk3-index.mjs`, but there is no
   such script; see RA-26.)
3. Leave test and editor packages out of the shipped manifest.

### RA-4 · Raw spawn errors reach the player (Med)

`LobbyServer` sends `Failed to start game server: ${err.message}` to the room
(`src/lobby/LobbyServer.ts`, in the spawn `catch`). During this audit the disk
filled and every start failed with "[Spawner] Server exited prematurely with code
4294963241". The room does reset everyone to not ready, which is right.

**Fix:** say "Couldn't start the match server. Try again in a moment." and keep
the details in the lobby log.

### RA-5 · No map ambient sounds (Med)

No code handles `target_speaker` (`grep -r target_speaker src` finds nothing).
Maps with speakers: wdm17 (2), wda1 (1), wbomb6 (1). Looping ambience (hums,
machinery, wind) is a large part of how these maps feel.

**Fix:** a client entity handler: `noise` → sound file, `spawnflags` 1 or 2 for
looping (Q3: 1 = looped on, 2 = looped off), played positionally at `origin`.
Leave triggered one-shot speakers for later.

### RA-6 · Missing `func_rotating` objects (Med)

`func_rotating` appears only in a comment in `brushModelBuilder.ts`; the map
loader logs "No handler for entity: func_rotating". Brush entities are built
only by their handlers (doors, plats, buttons), so these objects do not render
at all. Maps: acidwdm2 (1), wda1 (1), wdm17 (3).

**Check first:** look at those spots in game. **Fix:** build the brush model and
spin it client-side (`speed` degrees/s around Z, or X/Y by spawnflags); no
collision or networking is needed for decoration.

### RA-7 · Portal, sky-portal and particle entities (Med)

No handlers for `misc_portal_surface` / `misc_portal_camera` (wdm2 ×4, wdm12 ×2),
`misc_skyportal` (acidwdm2, wdm1) or `misc_particles` (wdm17 ×3, wbomb2 ×2,
wda2 ×7). Portal surfaces in Q3 maps are usually screens or mirrors; without the
camera they show their fallback texture. A sky portal draws a 3D sky scene;
without it the sky may look wrong or empty.

**Check first:** wdm2 is the main Duel map, so look at its portal surfaces. Then
decide per map: implement, or remove from the maps.

### RA-8 · wdm17 has no sky (Med)

Loading wdm17 logs "Skybox failed: No skybox textures found for 1 sky shader(s):
textures/sky/violetsky". `tex_sky.pk3` holds only `violetsky1.blend.ktx` and
`violetsky2.blend.ktx` (cloud layers, no box faces). **Check** how the sky looks
in game, then either support cloud-layer-only skies or give the shader a
skybox.

### RA-9 · Textures WebGL rejects (Med)

Loading wdm17: `GL_INVALID_OPERATION: glCompressedTexImage2D: The implied base
level dimensions for an S3TC … texture are not multiples of 4`, then about 30
"Texture level does not exist". Those textures most likely fail to upload, and
render black or missing. **Fix:** find them (log the name in the KTX path when
width or height % 4 ≠ 0), and re-encode or pad them to multiples of 4, or fall
back to uncompressed for those.

### RA-10 · Map cards without picture or name (Med)

vote cards are blank (screenshot `11-bot-added`). `config/maps.json` names

### RA-11 · Demo archive holds dev recordings (Med)
