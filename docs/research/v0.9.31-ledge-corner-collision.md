# Ledge grabbing on diagonal walls and corner pull-up collision

Date: 2026-10-16. The user reports holding forward + Space while falling against
a concrete corner in wfdm11: hanging, shaking and descending in small snaps.
They also report unsuccessful grabs at diagonal/curved faces in wdm2.

## Confirmed reproductions

With the actual sweep backend and shared collision world, the same reachable
ledge grabs at yaw 0 and 90 degrees but fails at +45/-45 degrees. A polygonal
curved ledge also fails. The old downward point probe advances 22.4 units from
the player center (`ledgeReach * 0.7`), but a square radius-16 hull touches a
45-degree wall about 22.63 units from its center. The probe can remain outside
the lip even when the hull is already beside the wall.

A second regression samples the full standing hull throughout a successful
straight-wall pull. The old straight-line interpolation enters the wall at tick
20: the horizontal part moves inward while the feet remain below the lip.
Endpoint and vertical-only clearance checks do not validate that diagonal path.
Four of six initial tests fail against the baseline; all corrected tests pass.

These establish geometry failures related to the report, not proof that the
exact prolonged shake/snap loop in the screenshot has been reproduced.

## Implementation

- Use each probe's actual contact point and horizontal wall normal. Offset the
  destination inward by the standing AABB's projected horizontal support radius
  plus clearance. Near-horizontal hits without a useful horizontal normal cannot
  define a side wall.
- Try valid destinations from each fan probe rather than committing to the
  nearest wall before checking whether its route is usable.
- Locate walkable support with the full radius-16, 64-high standing hull. Verify
  destination occupancy and separate lift/across sweeps.
- Interpolate along those two route legs and sweep the full hull during active
  movement. Check occupancy during the initial grab pause too.
- If an obstruction appears, release into falling motion and apply a 300 ms
  re-detection delay. Successful grabs retain the same delay. Crouch cancellation
  uses it as well.

The previous ledge checks used a 56-high hull, while standing step-slide movement
uses 64. The corrected checks use the actual standing dimensions. The destination
sits about one unit clear of support rather than eight units above a point
sample. Detection reach, height limits, pause/pull duration and wall-jump rules
are unchanged. This intentionally changes invalid grab trajectories/targets;
exact old movement parity is not expected.

No wire/demo format or collision backend changes are included. Both server and
client use this FPS movement code; a comment incorrectly calling ledge grab
client-only was corrected. Full hidden-state restoration during reconciliation
is a separate existing architectural limitation, not solved here.
