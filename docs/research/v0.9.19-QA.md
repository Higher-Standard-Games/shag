## Done

- ✅ **Hitscan world occlusion** — `traceHitscanRay` now traces the BSP world and
  rejects targets occluded by geometry (bots were shooting through floors); also
  picks the nearest target so a body shields whoever is behind it. Regression
  tests added. Determinism gate unaffected (server:tick is a single walking player).
  _fps `1e7cb62`, outer `ae1f7b2`-adjacent pin._
- ✅ **WO-EB3 — Electrobolt rail renderer** — new procedural analytic-helix rail
  (cold blue-white core, twin helix, muzzle crack + terminal nucleus), one-shot
  thin-instanced batch reusing the Voltaic grammar. Driven by the authoritative
  `electro_rail` event for local + remote; old `fireBolt` retired for bolt weapons.
  - ✅ Local double-draw fixed (the old bolt still drew from the local fire path).
  - ✅ Start anchored to the gun muzzle for the local shooter (was the eye origin →
    degenerate near-camera projection, the "inverse to the gun" smear).
  - ✅ Width bumped ~30%.
  - 💤 Further look tuning (helix visibility/turns/palette) parked — "kinda done for now".

- ✅ **Post-match song not playing** — root cause: the phase→music trigger lived
  only in `NetworkGameHost`, so local matches went silent at match end (while the
  showcase still ran, since it's triggered host-agnostically via
  `MatchStateManager.onPhaseChange`). Fix: fire `loadPlaylist("data/endgame.playlist.json")`
  from that same host-agnostic handler in `Game.ts` (dedupes by name, so a network
  host firing it too is harmless); restore `game.playlist.json` when leaving PostGame.
  Track `Endgame_Udon.mp3` already exists (referenced by `endgame.playlist.json`,
  resolved from a pk3 `music/` dir). Kept as JSON playlists (already were).
  _fps `a952217`._

## Planned (decided)

- ✅ **Post-game input freeze.** Movement + blade/fire still registered on the end
  screen: the FPS controller predicts movement (keys→physics) and
  `FPSPlayer.updateFiring` reads the controller directly, both bypassing the server
  input gate and the `sendInput` command strip. Added
  `FPSController.setGameplayFrozen()` (wired from the FPSHud phase handler beside
  `setLookFrozen`) + a PostGame bail in `updateFiring`. Chat + leave-lobby stay live.
  _fps `af97b1b`._
- 🔨 **Procedural muzzle flash — shared base, per-weapon skins.** Old muzzles only
  loaded if the pk3 shipped `<weapon>_flash.md3` (GLB weapons don't → only the light
  flickered). New `MuzzleFlashRenderer` (world-space pooled billboards, reusing the
  rail grammar) draws a flash for every weapon, no per-weapon assets. Style added to
  `MuzzleFlashDef` (+ `scale`): `burst` (default), `plume` (fiery — riotgun/rocket/
  grenade), `arcs` (electric teal — electrobolt/instagun). Triggered from
  `WeaponViewManager.fire()` at the muzzle; beam weapons skipped (Voltaic has its own
  corona). Renderer lifecycle tested. **Local first-person only in v1**; remote-player
  flashes + look tuning (per-style shaping) owed after playtest.
- 🔨 **Dedicated diorama camera for the post-match showcase.** Placement used to
  cast a picking ray through a fixed *screen* fraction from whatever the live camera
  faced at match end ("weird position"). Now a dedicated `postgame_diorama` FreeCamera
  frames the winner as a **centered, straight-on hero shot composed relative to the
  MODEL** (not the death spot), so the shot is identical every match. It sits in
  front of the model (clear space where the player stood), clamped to available
  distance so it can't clip a wall; swapping `scene.activeCameras` also drops the
  viewmodel overlay. Restored on warmup. Framing constants (`DIORAMA_DISTANCE/
  EYE_HEIGHT/LOOK_HEIGHT/FOV`) tunable — **playtest owed** to dial the framing.

## Procedural pickups (new workstream)

- 🔨 **Procedural health & armor visuals** (docs/research/PROCEDURAL_ITEMS.md).
  Runtime-generated "techno-relic" sculptures replace the MD3 model dependency
  for FPS health/armor — no new map entity or network identity; gameplay,
  active-mask, respawn timing all unchanged (server-authoritative).
  - ✅ Engine seam: `PickupVisual` contract + `PickupOptions.visualFactory` in
    `Pickup.ts` (model path is now the fallback; procedural drives update /
    active / dispose). `modelPath` optional when a factory is present.
  - ✅ Full family: all 9 tiers (health small/medium/large/mega/ultra, armor
    shard/ga/ya/ra) recipe-driven — 3D cross+core (health) / hex core+plates
    (armor), rings, motes, corona petals, satellites, floor pedestal, beacon.
  - ✅ Scene-scoped geometry/material cache (clone-per-pickup, shared geometry),
    private per-pickup energy materials for independent pulse.
  - ✅ Fail-closed active-state machine: first mask value applies silently;
    real active→inactive plays a detached collection transient that survives
    the persistent visual being hidden; inactive→active plays respawn assembly.
  - ✅ `r_pickupProcedural` cvar (default 1) toggles back to MD3 on next map load.
    `spawn_pickable_entity` now preserves health/armor type for direct preview.
  - ✅ Gates green: tsc (both), 1455 tests (+9 new), biome 925/586, determinism.
  - 🔨 **v2 art pass** (playtest #1 feedback): removed the oversized central
    cross (now a small emblem) and the floor pedestal (both families — the
    collection ring burst stays); compact "normal item" sizing; brighter HDR
    emissive; warm health palette (25 = bright yellow, 50 = orange→yellow) with
    a **scrolling gradient** core + slow gentle pulse; armor reworked to clean
    fanned **hexagonal shield plates** (no rings/floor). Target: modern sci-fi.
  - 📋 **Playtest owed** — another in-map look pass; then Phase 4 (distance
    quality tiers, MD3 retirement). Recipe values are all tunable data.
  - 💤 Deferred: nearby-proximity cosmetic boost, dedicated health/armor pickup
    SFX (needs asset verification), uneven-floor pedestal alignment.
