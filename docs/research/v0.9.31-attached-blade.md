# Held Arc Blade size and orientation

The remote-player and winner-showcase paths detached the raw geometry from the
GLB hierarchy. The Arc Blade export stores its normalization in a parent node;
discarding that parent restored the source model's large dimensions and axes.

Both paths now use `AttachedBlade.ts`. A hand attachment carries the complete
loader hierarchy, with the grip offset to the authored handle centre at export
X=-0.45. The attachment accounts for Babylon's glTF handedness conversion, which
reverses export X in a left-handed scene. Source +X runs from handle to tip.
The first-person model scale makes the complete sword about 60 world units long.
An initial half-scale correction was too small in gameplay; the extra shrink
factor was removed for both third-person and winner attachments.
The retained hierarchy and animation groups are disposed with the attachment.
First-person transforms and combat rules are unchanged.

## Size follow-up

In-game feedback showed the initial 30-unit sword was too small. The extra 0.5
factor was removed from both bone and fallback attachment scaling; the model is
now about 60 units long, retaining the handle pivot and handedness correction.
The bounds assertion now checks that full length. The browser probe was rerun
on both attachment paths: the actual idle rig measured about 60.13 units along
the main world axis, and the slash capture shows a full sword extending from the
hand. First-person scale and melee reach were not changed.

Typecheck, the six focused attachment/lifecycle/parity tests, Biome, build,
engine manual build, simulation, physics, server tick, 1,000-tick fuzz, and the
wdm2 BSP CLI check were rerun successfully with the commands listed above.
The full test suite was not repeated for this two-line scale adjustment.
