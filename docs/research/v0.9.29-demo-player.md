# v0.9.29: demo player tuning

**Reviewed:** 2026-10-13. **Source:** engine `4544f1e2`, FPS `9400513`.
**Status:** DP01 fixed on `v0.9.29-demo-player`; the rest proposed below.

The goal: a demo shows what the player saw while playing, one to one — the same
first-person camera, the same HUD, the same smoothness — before any new playback
features.

## How playback works now

| Part | Where | What it does |
| --- | --- | --- |
| Frames | `DemoViewer` | Steps recorded snapshots (the server's snapshot rate) by a playhead in recorded ticks; play, pause, speed, seek. |
| Entities | `DemoEntityTimeline` via `RemotePlayerRenderer.getDemoEntitySample` | Interpolates position, yaw and velocity between the two frames around the playhead. |
| Camera | `SpectatorController` on `fpsCamera`, fed by `DemoService`'s target provider | Interpolated position and yaw; pitch from the latest raw frame; walk bob and lean from `DemoPovState`. |
| Events | `DemoService` | Its own handling of chat, weapon fire, voltaic beams, deaths, damage and awards. The live game's `GameEvents` handles about thirty event types. |
| HUD | `DemoViewerHUD` | Transport bar, a player list, and one line of the followed player's name, health, armor and weapon. The game's `FPSHud` is not started. |
| Overlays | `DemoOverlayController` | Transport bar, cinematic HUD and chat; `H` shows or hides them all. |

## Findings

| ID | Problem | Evidence | Scope |
| --- | --- | --- | --- |
| DP01 | The first-person camera tilted sideways in the air, up to 29°. Babylon applies roll through the up vector and rebuilt it only on frames where the roll changed. The walk bob's roll drops to zero at a jump, so the up vector kept that frame's pitch, and turning in the air swung it to the side. The live game's camera has the same roll path (`FPSApplicator`). | Browser probe: wdm17, 1073 of 3703 frames tilted over 3°; wamphi1 334 of 3954; after the fix 0 of 3661 and 0 of 3961. | S, **fixed** |
| DP02 | No game HUD in demos. Health, armor, ammo, weapon slots, timer, frags, killfeed, crosshair, damage indicators, death screen — none of it shows; only a line of text. | `FPSHud` starts only in `Game`'s network path; `DemoService._updateDemoHud` feeds only `DemoViewerHUD`. | M–L |
| DP03 | Demos handle six of the game's event types in a parallel copy, so anything the HUD and effects learn from other events never reaches a demo. | `DemoService` event loop against `GameEvents`. | M |
| DP04 | Pitch is not interpolated: looking up and down steps at the snapshot rate while position and yaw are smooth. | The target provider reads `transform.rotation.x` from the latest frame; `DemoEntityTimeline` carries no pitch. | S |
| DP05 | The transport bar is unstyled: none of the game's look. | `DemoViewerHUD` against the HUD's Washiki theme. | S–M |

## Proposed order

1. **DP04:** interpolate pitch with the rest of the pose.
2. **DP02 + DP03:** run demo frames through the live game's event path with the
   followed player as the viewed entity — the path live spectating already
   uses — and start `FPSHud` for playback. The HUD shows by default; the
   transport bar gets a HUD switch.
3. **DP05:** the transport bar in the game's style.

## Done

  attach rebuild their up vector from their rotation every frame
