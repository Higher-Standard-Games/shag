# v0.9.29 media investigation

**Status:** investigation complete; no media moved or deleted.
**Snapshot:** 2026-10-12, local `v0.9.29-papercuts` working tree, engine HEAD
`9c94a4e3`, FPS HEAD `e257dc6`. Includes ignored files, not just Git contents.
Other release fixes were in progress during this inspection.

## Findings

The directory split is partly intentional. Site icons, shared engine fonts,
Havok WASM and Babylon lookup data belong outside `public/data/`. The largest
placement inconsistency is the live player model and animations under
`public/games/default/animations/`: FPS is selected, but these loaders still
hard-code the old `default` game directory.

The larger release problem is mixing runtime assets with local development
output. This machine has **3,432,795,316 bytes / 3.20 GiB** under `public/`.
Profiling results and demos alone occupy **2.17 GiB (68.0%)**. The standard Vite
build copies public files, including ignored files; being unreferenced does
not keep these files out of deployment. This is a packaging/storage finding,
not a claim that every browser downloads 3.20 GiB at startup.

Recommended order: exclude development output from the release package, retain
the runtime dependency set, then consolidate player assets. Moving everything
under `data/` would obscure engine dependencies and would not reduce the build.

Related work: [release audit](v0.9.29-release-audit.md), especially RA-3/26
(published PK3 index and remaining package curation), RA-10 (levelshots), RA-11
(development demos), RA-12 (base/nonfree packages) and RA-25 (disk exhaustion).
This document records findings; it does not close those tasks.

### Two different meanings of game data

`public/engine.json` selects `fps`, with engine assets at `/engine`.
`GamePaths.game()` consequently returns `/games/fps/...`, and
**`GamePaths.data()` returns `/games/fps/data/...`, not `/data/...`**.
Meanwhile `main.ts` explicitly sets PK3 search paths to `data/`, and weapon
definitions, playlists, UI assets and map previews use that directory.

The player model works because its URL bypasses GamePaths and explicitly uses
`/games/default/`. Changing `defaultGame` alone will not migrate it. The
developer `spawnmodel` resolver builds paths through GamePaths; it does not
provide a general proof that arbitrary `/data/...` paths work through that
command. See [model loading guide](../manual/guides/model-loading.md).

Recommendation: keep `/data/` as the current FPS distribution root and move
the live player outputs to `/data/models/players/vanguard/`, with animations
in a named subdirectory. Use one player asset definition for live players,
teleport ghosts, demo playback, animation inspection and benchmark tools.
Preserve GamePaths' existing contract for generic loose game assets until a
separate API migration is justified. Do not redirect the PK3 loader through
`GamePaths.data()`.

Both current game-data roots are ignored. Moving tracked shared assets into
either root would also change how they are obtained from a clean checkout;
an asset publication/source-of-truth plan is needed before such a move.

### Duplicates are not automatically redundant

Checked matching loose `/data/<path>` against the effective alphabetical PK3
owner, then compared SHA-256 of the actual bytes. **172 matching paths are
byte-identical**, totaling **145.73 MiB**:

| Loose family | Exact matches | MiB | Why removal needs care |
|---|---:|---:|---|
| `models/weapons/...` | 162 | 145.41 | Most winning copies are in `z_weapons.pk3`, but direct `.cfg`/texture URL consumers do not automatically read that archive. Converted runtime GLBs are a separate asset set. |
| Ammo icon TGAs | 9 | 0.15 | Deliberate loose fallback; matching archive is `data0_21.pk3`. Removing that archive during curation may make the loose fallback essential. |
| `levelshots/acidwdm2.jpg` | 1 | 0.17 | Archive copy is in `map_acidwdm2.pk3`; UI currently requests loose URL. |

Separately, 79 virtual file paths occur in multiple archives. This is an
override/overlap count, not 79 proven wasteful files. “Pure” and “non-pure” base
packages do not have identical contents; their names are not sufficient to
choose a winner for release. Texture packages and map-object archives can be
used by BSP/shader dependencies without any literal archive name in source.
Names containing `nonfree` also warrant the existing RA-12 provenance review;
this audit does not determine redistribution rights from filenames.

## Concrete discrepancies and missing media

1. **Player distribution root:** FPS uses `/games/default/` for players and
   `/data/` for weapons/effects/UI/music. Consolidate live player outputs with
   game media; archive source inputs rather than moving all 62 files wholesale.
2. **Runtime file inside benchmark directory:** optional outline proxy and its
   hash manifest should move together to `/data/models/players/vanguard/`, with
   generator recipe, safety path check and profiling provenance inputs updated.
   It must not be swept away with report cleanup.
3. **Missing previews:** current `config/maps.json` has 14 maps; loose levelshots
   cover 11. **wdm1, wdm11, wdm12** are missing. Same finding as RA-10.
4. **Optional missing animations:** manager lists `dance_1.glb`, `dance_2.glb`,
   `dance_3.glb`; none exists locally. Failed clip loads are tolerated and
   animation selection falls back to idle. This is incomplete victory-showcase
   media, not a missing core player model. Decide whether to ship clips or omit
   unavailable entries rather than creating new startup requests blindly.
5. **External data completeness:** brand, background, playlists, sprites and
   models live in ignored directories. A clean Git checkout does not reproduce
   the playable asset set. The PK3 manifest only covers archives, not these
   loose dependencies or players. A small release media manifest is useful even
   without introducing a new asset-loading framework.

## Investigation method and limits

Read the configuration, PK3 and model-loading guides, `package.json`, Vite
configuration, ignore rules and the relevant consumers before classifying files.
Walked all local public files with Python `os.walk`, recorded sizes/extensions
and Git tracking state, read GLB/glTF JSON headers for external image/buffer
URIs, inspected all 107 ZIP central directories and compared matching loose
files with effective archive entries by SHA-256. Runtime and tool references
were searched in `src/` (including FPS), `scripts/`, `config/`, root HTML/manifest
and prototypes. Comments, exported APIs and family names were distinguished
from application call sites. No network download or external source was needed.

```powershell
@'
import os, collections
groups = collections.defaultdict(lambda: [0, 0])
for root, dirs, files in os.walk('public'):
    for name in files:
        path = os.path.join(root, name)
        group = os.path.relpath(path, 'public').split(os.sep)[0]
        groups[group][0] += 1
        groups[group][1] += os.path.getsize(path)
for group, (count, size) in sorted(groups.items()):
    print(group, count, size, round(size / 1048576, 2))
'@ | python -
```

**Assumptions:** current FPS client and configured map pool are the release
baseline; source/artifacts should remain recoverable; optional developer
features are retained unless explicitly excluded. This is the local media set,
not necessarily the deployed production set.

**Unverified:** full BSP/shader/entity dependency closure for every map and
weapon fallback, every external mapper workflow, actual browser requests/audio
playback, visual quality, redistribution provenance, production retention/CDN
configuration. A missing basename match was never used to mark a whole PK3 or
dynamic asset family safe to delete. No source or renderer/network behavior
changed, so gameplay regression gates were not rerun for this document-only
task.
