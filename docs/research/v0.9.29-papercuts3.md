## 1. P2 — IME confirmation sends an unfinished chat message

Source: [FPSChat.handleKey](../../src/games/fps/client/hud/widgets/Chat.ts).

The Enter handler sends and closes chat without checking `isComposing`. When a
player uses an input method to compose text, Enter may confirm a candidate rather
than mean “send”. A composing Enter event currently invokes the send callback and
closes the input. Escape also closes chat during composition.

**Reproduction:** open FPSChat, enter text, dispatch a keydown with `key: "Enter"`
and `isComposing: true`. Observed: one send callback, input no longer active.

**Small fix:** keep gameplay propagation suppressed, but leave composing events
to the input method before handling send/cancel. Check browser compatibility for
composition-ending events. Test composing Enter/Escape plus ordinary send/cancel.

**Honest impact:** significant for affected input-method users; irrelevant to most
ordinary Latin-keyboard typing. Synthetic event behavior is reproduced; actual
Japanese/Chinese/Korean IME acceptance remains untested.

## 2. P2 — settings import reports success for rejected input

Sources: [SettingsCommand](../../src/engine/console/commands/SettingsCommand.ts)
and [Cvar.exportConfig / execConfig](../../src/engine/core/Cvar.ts).

The command counts non-comment lines, not successfully applied settings.
`execConfig` silently skips malformed lines and ignores `Cvar.set`'s false result.
A clipboard containing an unknown setting and a malformed line reports
`Imported 2 settings from clipboard`, although neither was applied.

The same path cannot round-trip a string containing quotes: setting a test string
to `say "hello"` exports `review_label "say "hello""`; the import regex rejects it,
leaving the reset value unchanged. This is one config-transfer quality issue with
two related failure modes.

**Small fix:** return accepted/rejected counts and useful line diagnostics; escape
and parse exported string values symmetrically while retaining simple legacy
config syntax. Distinguish clipboard access failure from invalid config.

**Acceptance:** unknown, readonly, invalid numeric and malformed entries are not
reported as imported; quoted strings round-trip; valid ordinary configs still
work. An empty or comment-only config should not claim meaningful success.

**Honest impact:** mostly console/power-user usability. Routine slider changes
and local-storage persistence do not use this text import format.

## 3. P3 — open chat history does not enforce its DOM limit

Source: [FPSChat.push](../../src/games/fps/client/hud/widgets/Chat.ts).

The message array is capped at 100, but while talk mode is open every incoming
message adds another DOM row. Trimming only happens in closed mode; the open
panel also scrolls to the bottom on every arrival, interrupting scrollback reading.

**Reproduction:** open FPSChat and add 150 messages. Observed: 100 stored messages,
150 rendered rows. Closing/reopening rebuilds the view, so this is growth during
an uninterrupted open session, not a permanent leak across the app's lifetime.

**Small fix:** enforce the same history limit on visible rows and follow incoming
messages only when the player was already near the bottom. Preserve sensible
scroll position when pruning old rows.

**Acceptance:** a long open session stays at 100 rows, a reader scrolled upward is
not dragged to the newest message, and someone following the bottom sees arrivals.

**Honest impact:** modest cleanup and scrollback usability. No frame-time or
memory-performance gain has been measured, and normal low-volume chat is unlikely
to be expensive.

## Implementation and validation — 2026-10-14

- Chat ignores composing Enter/Escape and legacy IME key code 229 after stopping
  propagation to gameplay. Ordinary Enter/Escape retain send/cancel behavior.
- Open chat trims rendered rows to the same 100-message bound as its data. It
  follows arrivals only within 40 pixels of the bottom; pruning compensates the
  reader's scroll position by the removed height. Opening chat still shows newest
  messages. No new timers or global listeners were introduced.
- Config export uses escaped quoted strings. Import returns accepted counts and
  rejected line numbers/reasons; readonly, unknown and invalid entries do not
  count as accepted. Simple unquoted values and legacy quoted paths with non-JSON
  escapes remain supported. Recognized JSON escapes in quoted values are decoded;
  use an export's doubled backslashes to preserve literal backslashes reliably.
  Clipboard failures and comment-only input receive distinct feedback.
