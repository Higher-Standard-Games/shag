# v0.9.24 — documentation QA and the bugs it finds

**Branch:** `0.9.24-qa-improvements` (both repositories)
**Cycle:** v0.9.24, a bugfix and documentation release
**Living changelog:** `docs/changelog/v0.9.24.md`

The manual was last written in bulk on 2026-08-12. Two releases have landed
since — water and liquid simulation (v0.9.22), then movers, lag-compensated hit
registration, the renderer and networking audits, and a lobby with accounts,
private rooms, Amphi and ranked results (v0.9.23). So the pages most worth
reading are also the ones most likely to be wrong.

This cycle reads the manual against the code, one engine part at a time. The
reading is the point: a page is only correct if someone has just looked at the
code that makes it true, and looking at that code is how the bugs turn up.

## The loop, per part

1. **Read the page.** Note every claim it makes: a command, a cvar, a default,
   a file path, an order of operations, a limit.
2. **Read the code that would make each claim true.** Not a search for the
   claim's words — the actual call path.
3. **Sort each claim** into: true, wrong, no longer exists, or true but
   incomplete.
4. **Fix what the reading found in the code.** Small, obvious defects are fixed
   in a batch as part of the same work order, each with a test that fails
   without the fix. Anything larger becomes a row in **Bigger tasks** rather
   than a detour.
5. **Rewrite the page** so it describes what the code does today. Delete claims
   that are no longer true rather than softening them.
6. **Update the matrix below and the changelog**, and commit the part as one
   commit.

## Rules

- **Evidence, not memory.** "Confirmed" means the code was read this cycle, on
  this branch. Name the file when it matters.
- **A page describes what is, not what was intended.** No aspirational
  documentation, no "should", no features that exist only in a research note.
- **`docs/known_bugs.md` is stale and is not evidence.** Entries there predate
  several releases; treat each as a rumour to verify against the code before
  acting, and correct or delete the entry as part of the part it belongs to.
- **Every code fix carries a test** that fails without it, unless it is
  unreachable from tests (a shader, a renderer draw call) — say so in the log.
- **Comments describe current code.** No before/after, no provenance, no
  references to the engine this project came from; that belongs in the commit
  message.
- **Keep this file current as you go.** Another agent, or another branch, picks
  up from the matrix alone.

## Progress log

### 2026-09-22 — WO-8: headless and the CLI tools — done

Read `guides/headless-mode.md`, `tools/headless-game.md`, `tools/index.md` and
`tutorials/advanced/headless-testing.md` against `src/cli/`, and ran the
commands they document rather than only reading them.

**Right:** `--exec` with `--command` as its alias and no `--map`; the headless
composition registering engine commands but no gameplay launcher, so `bsp load`
is the inspection path; `NullEngine` and the skipped browser Havok init; every
`npm run` script named across the pages; `cli:bsp info|liquids`; and the exit
status contract — a batch whose command is refused exits 1 while its remaining
commands still run, proven by running one.

**Wrong, each found by running it:**

- `npm run cli:game -- --exec 'pk3 stats; …'` — the page's own "useful batch" —
  fails at the first command, because `pk3` is developer-gated. It now starts
  with `developer 1`.
- `npm run cli:game -- --exec 'sim replay W+CROUCH 60; JUMP 1; W 30; quit'`
  appeared in three pages and cannot work: the batch runner split on the
  semicolons that belong to the replay sequence, so `JUMP 1` and `W 30` were
  read as console commands and the batch exited 1. Fixed on both sides — the
  splitter now honours double quotes, and the pages quote the sequence.
- `npm run net:client -- --host localhost --port 7777` names two flags the
  client does not have; it takes `--connect <url>` and `--name`, and silently
  ignored the rest while connecting to its default.
- The pages never mentioned that this runner alone registers `sim`, `anim`,
  `headless`, `leaktest` and `trace_test`, nor the server's `--gametype`,
  `--maxclients`, `--tickrate`, `--snapshotrate`, `--game` and TLS flags, nor
  `cli:bsp entities|textures|collision|clipbrushes|effects|build`.

### 2026-09-22 — WO-1: console, cvars and commands — done

Read all four guides and both tutorials against `src/engine/console/`,
`src/engine/core/Cvar.ts`, `src/engine/rendering/RenderVars.ts` and the FPS
command directory.

**What the pages got right:** the whole console and cvar API surface —
`getInstance`, the two `register` overloads, `unregister`, `execute`,
`executeChecked` with its `ok`, `fail()`, auto-discovery by default export,
every `Cvar` getter and setter, `engine_cvars` and `engine.renderVars` as the
two storage keys, `exportConfig`/`execConfig`, and the `RenderVars` instance
API. Developer-mode gating is real: 29 commands carry `developer: true`.
Camera modes, and the `pvs`, `pk3`, `physics`, `debug` and `render`
subcommand lists, matched the code exactly, as did the notes that there is no
`debug fps`, no `camera controller|height|target`, and no `r_list`.

**What was wrong:**

- The console guide told the reader to enable developer mode "before using
  renderer and inspection tools" and then demonstrated `help bsp` — but `bsp`,
  `camera`, `shader`, `pvs` and `freefly_collision` are *not* gated, while
  `map`, `pk3`, `render`, `debug` and `physics` are. The examples now name
  commands that are actually gated.
- The command reference omitted whole groups of real commands: `god`,
  `noclip`, `giveweapon`, `spectator`, `timescale`, `name`, `spawn`,
  `spawnmodel`, `entity`, `scene`, `texture`, `time`, `echo`, `exec`,
  `export`, `settings`, `screenshot`, `weather`, `wind`, `debris`, `light`,
  `shadow`, `godrays`, `skybox`, `fog`, `daynight`, `hud`, `ui`, `audio`,
  `game`, `animtest`, `console_debug`, `writeconsole`, `cl_wep_reset`. It also
  missed `bsp trace|door|lightgrid|unload|preload|loadtextures|clear`, the
  `shader anim|glow|blendmode|lightmap|toggle` family, and
  `freefly_collision test|draw|clear|clipviz|clipdump|cliptrace`. The page now
  carries them, with the developer-gated ones marked.
- The FPS section described "network simulation commands"; the command is
  `netsim`, and `water` and `camera_audit` were missing entirely.
- `render-variables.md` predated v0.9.22: none of the fourteen water and
  underwater variables were listed.
- The console tutorial quoted an argument with single quotes. The parser
  honours double quotes only, so the example printed the apostrophes.

**Fixed in the code while reading:** see the fix batch above. The cvar refusal
also reaches automation — a refused set is a failed command, which is how
headless and batch runners get a non-zero exit code.
