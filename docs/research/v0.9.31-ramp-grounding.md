# Uphill support and repeated jump sounds

Date: 2026-10-16. The authored-collision source change is checkpoint `d7d4f245`.

Removing draw-surface facets did not remove the repeated ground transitions.
`SharedCollisionWorld.stepSlideMove` classified uphill motion as grounded only
if the backend reported a hit that tick. Movement tangent to a smooth ramp can
have no impact, so this rule alternated between supported and airborne states.
The audio observer then classified some rising edges as jumps without an actual
jump activation. No audio code or snapshot formats were changed here.

The shared client/server collision world now probes two units below the resolved
position for uphill motion. Support requires a normal with y >= 0.7 and resolved
movement along/into the plane. Positive separation above 0.01 displacement units
is airborne. The small tolerance accommodates clipping error. A nearby floor
alone cannot ground an ascending jump or slide bump. Downward/level motion paths
and the actual trace/step solver are unchanged. Uphill frames without an impact
gain one short support trace; removing draw-surface collision makes those probes
cheap, but this change is primarily a movement correctness fix.

Before the fix, three new regressions failed: tangent uphill movement lost
support; a jumping player with an unrelated hit could be grounded; and real
brush-ramp traversal lost ground at tick 1. After the fix all six grounding
tests and 34 sweep tests pass. The real-ramp test runs the FPS movement profile
for 125 fixed ticks without ground loss, then verifies an actual jump leaves
the ramp. Tests also cover missing/steep support and upward slide bumps.

Synthetic straight runs from 32 grounded positions/headings in the wfdm11 stair
recording, 125 ticks each with jump input disabled, produce 116 eligible
grounded-to-rising audio edges with old grounding and 15 with new grounding.
Both use authored brush/patch collision. This is a controlled reproduction,
not a re-simulation of the recording's missing commands. Residual edges at map
geometry/route transitions have not been fully classified; these results do not
promise that every remaining sound is correct. Live stair/slide feel still
needs confirmation. The jump sound's snapshot heuristic is a separate issue
from the collision source and ground classification.

Local reproduction: `npx.cmd vite-node .cache/collision-grounding-movement.ts`.
Results: `.cache/collision-grounding-movement.json`. The scratch runner imports
the grounding implementation from `d7d4f245` for its control, with identical
authored BSP data and synthetic inputs. Durable regressions live in
`src/engine/__tests__/SharedCollisionGrounding.test.ts`.
