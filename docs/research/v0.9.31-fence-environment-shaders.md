# Fence lighting and teleporter environment passes

Scope: wfdm5, the sweepcollision FPS build, and the engine's BSP shader path.
No collision, network protocol, map, or packaged-media changes are included.

The fence mesh uses `textures/grates/fence01`, which already specifies
`cull none`. The material loader already disables culling and enables
two-sided normals. Its deluxe baked-light plugin nevertheless used a clamped
normal/light dot product, extinguishing the reversed side. Two-sided diffuse
lighting now uses the absolute dot product; one-sided materials are unchanged.

The frame uses `textures/metal_vertex/vertex_aluminium`: `rgbGen vertex`,
`surfaceparm nolightmap`, and an aluminium material/gloss texture. The paired
frame surfaces (237/269 in the current local BSP) contain 329/532 and 304/530
completely black vertex RGB values. Those values are actual map data, not
missing textures. They are preserved. Opaque vertex-lit material stages now
combine baked vertex colour with additive game lighting and specular instead
of disabling lighting altogether. Synthetic world fill is excluded. This
cannot restore lighting that is absent from the compiled vertex data.

Upstream Qfusion's [r_shader.c](https://github.com/Qfusion/qfusion/blob/master/source/ref_gl/r_shader.c) maps `lightingDiffuse` to vertex
lighting for world shaders. Its `r_backend_program.c` distinguishes baked world
vertex light from entity lightgrid lighting. The BSP resolver now makes that
interpretation explicitly through `worldSurface`; entity resolution is not
silently changed.

The teleporter centre shader is
`models/mapobjects/teleporter/teleporter_01_b` in `scripts/mapobjects.shader`.
It contains a `surroundmap env/televoid/void` branch, a negated cubemap branch
with a 2D environment fallback, a blended material and animated additive shine.
The previous parser did not recognise surroundmap, treated unknown conditions
as deluxe, and the resolver collapsed the stack to its material stage. The
corrected path selects the cubemap branch independently of deluxe, retains
source order, and creates three passes. The cubemap reuses the existing
six-face PK3 loader and axis conversion. The actual star asset is a single
`env/televoid/void.ktx` container with six ETC1 faces, 512 pixels per face and ten
mip levels. The environment loader now splits and validates that container,
software-decodes its base faces through the existing KTX decoder, and applies
the same sky-face axis conversion. GPU upload uses the decoded base level.
Material disposal releases the owned
cubemap through the map root's disposal observer.

The environment pass uses a StandardMaterial plugin with GLSL and WGSL paths;
normal engine fog remains in the StandardMaterial pipeline. Surround mapping
uses the world view ray, not the mesh UVs or a fixed skybox. Reflection cubemaps
use the reflected ray. Unsupported condition kinds are retained in the parser
but not selected as deluxe branches.

## Validation

All final commands passed:

```powershell
npm.cmd run typecheck
npm.cmd run test:run
npm.cmd run gate:biome
npm.cmd run build
npm.cmd run test:simulation
npm.cmd run test:physics
npm.cmd run server:tick
npm.cmd run server:fuzz -- --ticks 1000
npm.cmd run cli:game -- --exec 'bsp load wdm2; bsp info; quit'
npm.cmd run cli:game -- --exec 'sim replay \"W+CROUCH 60; JUMP 1; W 30\"; quit'
npm.cmd run cli:game -- --exec 'bsp load wfdm5; bsp info; quit'
npm.cmd run docs:build
```

Full tests: 4,964 passed, one skipped, 593 files. Targeted runs also cover parser
and resolver branch/pass order, retained black vertex shadows, game-light
eligibility, KTX1 cube byte orders and truncated input, and the real environment
loader with only NullEngine's unavailable GPU upload stubbed. The initial
NullEngine cube upload failed because it has no GL context; the corrected test
uses the same hardware-allocation stub as the existing environment QA tests.
The first gate run caught a new iterable-callback lint error; it was fixed
before the complete final gate run. Physics retains its known position warning.

Local browser commands:

```powershell
node .cache/fence-env-browser.mjs webgl2
node .cache/fence-env-browser.mjs webgpu
```

Headless Edge rendered the actual wfdm5 fence pair and teleporter. Both WebGL2
(RTX 4070 SUPER/D3D11) and WebGPU compiled the environment pass and loaded the
real cubemap. The three material passes were present. Both fences had culling
disabled, two-sided lighting enabled and the baked-light plugin; the aluminium
frame had the vertex-light plugin with lighting enabled. A separate real-GPU
front/back fixture on WebGL2 returned RGB `[96,96,96]` from both sides, confirming
equal baked diffuse response independent of the map's asymmetric lighting.
The browser logs still contain the existing ammo MD3 plugin failure, but no
new shader compilation errors in these runs. Artifacts:
`.cache/fence-env-webgl2.{png,json,log}` and
`.cache/fence-env-webgpu.{png,json,log}`.

The left fence remains darker than the right in the map capture. Compiled
lightmap samples differ: representative triangle-centre RGB is `[29,19,37]`
versus `[53,50,95]`. The many black frame vertex colours likewise remain black
without additive illumination. This is not proof that the model/media now
matches Qfusion exactly. Exact model orientation, all viewing angles, and a
matching-build Qfusion comparison remain unverified; repairing baked map data
is outside this renderer change.
