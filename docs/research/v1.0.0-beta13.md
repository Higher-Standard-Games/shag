## Server changes

Bots move out of `washoi-bots` into the lobby: the lobby seats bots and plays
each match's bots in a match runner, a child process of about 175 MB that
exits with its match. The full steps are in the fps
`scripts/deployment/README.md`, "v1.0.0-beta.13 operator steps":

1. **Before publishing**, on each host:
   `systemctl show washoi-lobby -p MemoryMax -p MemoryHigh -p TasksMax` must
   leave room for one runner per bot match on top of the match servers (about
   120 MB each). If the units are sandboxed, give `washoi-lobby` the write
   paths `washoi-bots` had, for the bots' navigation caches.
2. **Publish** as usual; the installed activation script still restarts both
   services, and the bot server starts and stays idle.
3. **Verify** in `journalctl -u washoi-lobby`:
   `Bots: seated by the lobby, matches in match runners`, and from a bot
   match's runner `[HeadlessBSPCollisionWorld] World trace: compiled (WebAssembly)`.
   `pgrep -af bot-runner` shows a runner while the match plays and none after.
   Play a campaign mission and a quick play with bots.
4. **Install** the new `scripts/deployment/activate-eu.sh` /
   `activate-us.sh` as `/usr/local/sbin/washoi-activate`.
5. **Retire** the bot server: `systemctl disable --now washoi-bots`.

Rollback to beta.12: `systemctl enable --now washoi-bots` first.

Behaviour changes worth knowing on the server side:

- Team Deathmatch plays a tie at the time limit on in 60 s of overtime;
  Survival does not.
- A new Survival gametype and body scale (`HitScale`, `BodyScale`) are used by
  campaign missions.
- `@tensorflow/tfjs-node` is no longer a dependency (bot training was
  removed); `npm ci` on the hosts drops it.
- No ratings or ranking schema re-rate is needed: `players.db` keeps its
  schema; the campaign's clears live in their own `campaign.db`.
- The lobby limits clients: 5 chat lines in 5 s ("You are sending messages
  too fast."), 200 messages in 10 s (then closed, 1008), 32 open connections
  per address (then 1013; loopback exempt), 30 s to log in, and 4 MiB queued
  per connection. A game server closes a connection that has not joined
  within 15 s.
- Chat is no longer written to the journals; `SHAG_DEBUG=chat` prints it on a
  game server.
- The lobby reads its demo archive in the background after a start: the demo
  list fills in over the first moments instead of the lobby stalling.

## Security headers (Caddy, on the hosts)

**Done on 2026-11-18.** Both hosts' Caddyfiles (the live
`/etc/caddy/Caddyfile` and the master copy `/srv/washoi/Caddyfile`) define a
`(security_headers)` snippet, imported by `us.washoi.net`, `washoi.net`,
`eu.washoi.net` and `manual.washoi.net`. The files they replaced are in
`/srv/washoi/backups/caddy-v1.0.0-beta.13/` on each host. Checked afterwards:
all five headers on the pages, `/data` and `/lobby`; content types unchanged
for `.js`, `.wasm`, `.css`, `.ktx2` and `.json`; the live game booting with
the lobby online in WebGPU and WebGL2 on both regions, with no failed request
or console error. `shag.dev`, the studio site and the sandbox are left as
they were.

Before, production sent no security headers. The Caddy configuration lives
on each host, not in git, and deployment never touches it.

**What was added.** In each site block of the Caddyfile (`systemctl cat caddy` shows
which file the service loads), add:

```caddy
header {
	Strict-Transport-Security "max-age=31536000"
	X-Content-Type-Options "nosniff"
	Referrer-Policy "strict-origin-when-cross-origin"
	Content-Security-Policy "frame-ancestors 'self'"
	Permissions-Policy "camera=(), microphone=(), geolocation=()"
}
```

| Header | What it stops |
| --- | --- |
| `Content-Security-Policy: frame-ancestors 'self'` | Other sites embedding the game in a frame. The profile page shows the account key, so a framing page could trick a player into exposing or using it. Keep `'self'`, not `'none'`: the highlight video export frames its own page from the same origin. |
| `Strict-Transport-Security` | Plain-HTTP requests: browsers that have seen it use HTTPS only, for a year. Every host is already HTTPS-only. |
| `X-Content-Type-Options: nosniff` | Browsers running a file as a type other than the one served. |
| `Referrer-Policy` | Full URLs (query strings included) sent to other sites; they get the origin only. |
| `Permissions-Policy` | Camera, microphone and location, which the game does not use. |

Steps, one host at a time, US first:

1. Back up the Caddyfile into `/srv/washoi/backups/caddy-v1.0.0-beta.13/`.
2. Edit it, then `caddy validate --config <file>` and `systemctl reload caddy`.
3. Check: `curl -sI https://us.washoi.net/ | grep -iE 'strict|nosniff|referrer|frame-ancestors|permissions'`
   lists all five, and the game loads, plays a map, and the lobby and profile
   page work, in both renderers.
4. Repeat on EU (`washoi.net`, `eu.washoi.net`).

Rollback: restore the backup and reload.

**Later, not for beta.13:** a full `Content-Security-Policy` that lists where
scripts, workers, WebAssembly and connections may come from (the lobby and
game servers' `wss:` hosts, the shader and decoder workers). It is the real
defence against injected script, but a wrong policy silently stops the game
from loading. Ship it first as `Content-Security-Policy-Report-Only`, test it
in WebGL2 and WebGPU, then enforce.

## Admin panel (`/admin`)

The lobby serves a fair-play admin panel at `/admin` (lobby guide, "Fair
play"). It stays off in production until both steps below are done. Reviewed
2026-11-18: scrypt password hashes, rate-limited sign-in (per address and
overall), HttpOnly/Secure/SameSite=Strict session cookie, CSRF tokens,
same-origin check, escaped output and a script-free page with its own strict
security headers. No problems found.

1. **After the deploy**, add a login on EU and on US (the command ships with
   this release, and the password is yours to choose, 12 characters at
   least):

   ```bash
   cd /srv/washoi/repos/shag
   sudo -u washoi npm run fair-play -- add-admin <name> --data-dir /srv/washoi/server-data
   ```

   Then `https://eu.washoi.net/admin` and `https://us.washoi.net/admin` show
   the sign-in page; the lobby logs `Admin panel:` at start when it is on.
2. **Done on 2026-11-18, ahead of the release:** both regions' Caddyfiles
   forward `/admin` and `/admin/*` to the lobby (beside `/lobby`), and the
   `(security_headers)` snippet sets `Content-Security-Policy` and
   `Referrer-Policy` only where the response has none (`?`), so the panel's
   stricter ones stand. Until the new lobby runs, `/admin` answers the old
   lobby's `426 Upgrade Required`. Backups:
   `backups/caddy-v1.0.0-beta.13/Caddyfile.etc.before-admin`.
3. No second gate in front of it (an IP allowlist or Caddy `basic_auth`):
   the owner's decision; the panel's own password and rate limits guard it.

Fifty failed sign-ins from anywhere within 15 minutes lock the panel for
everyone for the rest of those 15 minutes, admins included; the command line
(`npm run fair-play`) still works.
