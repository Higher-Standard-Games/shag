## Loader and rebuild contract

`ModelAsset.ts` resolves indexed GLBs to bytes and lazily loads their indexed
archive through the regular mirror-aware PK3 loader. Concurrent imports share
the download; failed downloads release their pending state; a newly indexed
replacement owner is loaded even if an old archive has the same virtual path.
Unindexed/custom URL models retain the existing loader path. Embedded resources
avoid browser object-URL lifetime management.

Consumers updated: generic `ModelLoader`, `AssetPreloader`, first-person main
sources, first-person barrel sources, FPS pickup barrels and ammo-counter config
reads. Generic model loading covers dropped/remote weapon cache consumers too.
Packaging alone would not have updated these direct HTTP imports.

`config/weapon-models.json` owns source paths and required main/barrel exports.
The existing Python converters remain; their old npm alias was absent and has
been restored as a two-stage wrapper targeting unserved exports:

```powershell
# Optional regeneration: Python 3 + Pillow are required.
npm.cmd run convert:weapons
# Publish existing GLB/config exports, preserving original bank entries.
npm.cmd run tools:weapon-models
npm.cmd run tools:pk3-index
```

`PYTHON` can select a Python executable. The wrapper checks Pillow before either
conversion stage can alter exports. This shell lacks Pillow; the complete
conversion pipeline was intentionally not run. Its prerequisite failure was
verified to report that no exports changed. Custom FBX-derived models such as
Blade still need their own authoring/export step; IQM conversion does not
replace them. Standard runtime builds need neither Python nor the source bank.

Packaging validates required GLBs and rejects external image/buffer references,
uses fixed ZIP timestamps and sorted entries, publishes via a temporary output,
and refuses to overwrite its source bank. Node unit coverage checks retained
source entries, cfg overrides, deterministic bytes, authoring-file exclusion,
missing required assets and external-resource rejection.

## Follow-up: preserve the PG attachment rule

The initial package omitted `plasmagun/tags.txt`, although the source GLBs were
unchanged. `TagsLoader` also still fetched loose URLs. This bypassed Plasma's
legacy `tag_barrel2` rule and used the authored `tag_barrel` socket instead,
causing floating barrels. The initial browser checks counted barrel instances
but did not verify their attachment position; that was insufficient coverage.

The builder now includes `tags.txt` and requires Plasma's rule. `TagsLoader`
reads the indexed sidecar first, preserving unindexed/custom URL fallback.
The rebuilt live package has 43 exports (33 GLBs, 9 configs, 1 tag rule), 197
non-directory entries, 82812041 bytes and SHA-256:
`d0078184023c71f906b0d6c29d46977fb96d6ce0b53b11ed8d83e2076773f0dc`.
Earlier size/hash/export counts above describe the initial package only.
Published manifest/index were regenerated; no GLB conversion ran.

Both headless Edge backends verified PG ? GL ? PG, Plasma's two parent-root
attachments at `(14.17,6,-1.9)` and `(14.17,6,2.1)`, GL's authored socket at
`(0,0,0)`, and zero loose weapon requests. Screenshots
`.cache/pg-tags-webgl2.png` and `.cache/pg-tags-webgpu.png` were visually inspected:
barrels align with the body. Probe/report: `.cache/pg-tags-browser.{mjs,json,log}`.
