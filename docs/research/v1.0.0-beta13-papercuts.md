# v1.0.0-beta.13 papercuts

An unattended pass on branch `review/beta13-papercuts` in both repositories
(from `staging`, 2026-11-17), after the release review
([v1.0.0-beta13-review.md](./v1.0.0-beta13-review.md)). The brief:
performance, data flow, overly large files, security, privacy, latency, and
any bug, big or small.

How it was looked for:

- **Measured, not guessed.** A CPU profile of a headless bot match (game
  server and four bots in one process), a CPU profile of the browser client
  playing an S&D demo in headless Edge (before and after the fix in row 15),
  a profile of the idle lobby page, and a timing of the lobby's demo scan over
  the 329 local demos.
- **Read for abuse.** Every lobby message handler and the game server's
  message router were read for what a hostile client can send: sizes, types,
  rates, values relayed to others, log lines it can trigger at will, sockets
  it can hold open. Client HTML sinks were read for text other players
  control.
- **Production checked read-only:** the response headers and caching of
  `washoi.net` and `eu.washoi.net`. Nothing was changed there.

Every fix has a test that fails without it (✗→✓) unless the Proof column
says otherwise. Nothing is merged or pushed.

| Finding | Why not changed |

## For the owner

Production sends **no security headers** on `washoi.net` or the regional
hosts: no `Content-Security-Policy`, no `X-Frame-Options`/`frame-ancestors`
(the profile page shows the account key, so framing matters), no
`X-Content-Type-Options`, no `Strict-Transport-Security`, no
`Referrer-Policy`. The Caddy configuration is on the servers, not in the
repositories, so nothing was changed. A starting point for each site block,
to try on one region first:

```caddy
header {
	Strict-Transport-Security "max-age=31536000"
	X-Content-Type-Options "nosniff"
	Referrer-Policy "strict-origin-when-cross-origin"
	Content-Security-Policy "frame-ancestors 'self'"
	Permissions-Policy "camera=(), microphone=(), geolocation=()"
}
```

A full `Content-Security-Policy` (scripts, workers, WebAssembly) needs testing
against the game in both renderers before it is turned on; the
`frame-ancestors` one above is safe on its own.

Caching is already right: hashed assets are `immutable` for a year, packages
and `pk3_index.json` revalidate hourly by ETag, and JavaScript is served
zstd-compressed.

Behaviour a player or operator can notice:

- Chat faster than five lines in five seconds is dropped with "You are
  sending messages too fast." (lobby and rooms, as in a match).
- The lobby's demo list fills in over the first moments after a restart.
- Chat no longer appears in the server journals; `SHAG_DEBUG=chat` brings it
  back on a game server.
